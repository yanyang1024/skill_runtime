# HBF × AI 推理调研 — 跨维度洞察（Phase 6）

以下洞察不重复单一维度结论，均来自 ≥2 个维度证据的交叉推理。

## Insight 1：HBF 的真正革命性不是"容量"，而是把 KV/权重卸载的判定逻辑从"预测命中"降级为"延迟掩盖"
- 来源：dim03（读-算带宽拐点 24–37GB/s）、dim04（MoE 预取失效是低带宽时代的病）、dim05（HBF 1.6TB/s 入 decode 回路）。
- 推理：现有卸载系统（LRU/S3FIFO/贝叶斯预测/门控预测）的全部复杂度都源于慢介质带宽太低、miss 代价太高。HBF 带宽比 NVMe SSD 高约 2 个数量级，越过"读不如重算"拐点后，按需读的代价可接受——预取从"必须命中"退化为"掩盖个位数 µs 延迟的优化"。
- 含义：评估 HBF 价值时不应沿用"命中率"这一 SSD 时代的第一指标，而应转向"有效延迟预算与聚合带宽利用率"。置信度：高。

## Insight 2：HBM+HBF 时代系统瓶颈的迁移路径可预测——从"容量墙"到"延迟墙"再到"调度墙"
- 来源：dim05（容量闸门抬高 1–2 个数量级）、dim09（瓶颈已从计算转向 KV 搬运）、dim10（HBF 敏感点在 SRAM/功耗而非算力）、dim03（GPU-centric I/O 是分水岭）。
- 推理：HBM 容量墙被 HBF 抬高后，下一瓶颈是 HBF 的有效访问延迟（需逐层流水/双缓冲掩盖），再下一层是调度——谁决定什么数据在什么时间放到哪一层（跨 HBM/HBF/DRAM/SSD 四级）。这解释了 NVIDIA 同时布局 KVBM/NIXL 软件栈与 ICMS 硬件层的战略。
- 含义：HBF 产品的竞争壁垒不仅在 die 堆叠，更在与推理框架（vLLM/Dynamo）联调的调度软件。置信度：高。

## Insight 3：MoE 与 KV cache 对 HBF 是"一体两面"——同一介质同时承接稀疏读权重与只读历史 KV，且二者访问模式互补
- 来源：dim04（MoE 稀疏读、推理只读）、dim03（KV 读:写≈186:1、80% 复用在 10 分钟内）、dim05（KV 流量反超权重流量）。
- 推理：MoE 专家是"随机稀疏读"，历史 KV 是"大块顺序读"；前者吃 IOPS/延迟，后者吃带宽。HBF 的多 plane/多 die 并行结构恰好可同时服务两种模式。共享专家/attention 权重驻 HBM，冷专家+历史 KV 驻 HBF，是当前证据下最自洽的分层。
- 含义：HBF 容量规划应把"全量专家 + 历史 KV"合并算账，而不是分别论证。置信度：中高。

## Insight 4：NAND CIM 的正确打开方式由"误差容忍的通路分裂"决定——权重 CIM 可行、激活/KV 必须留在数字域
- 来源：dim07（权重通路容忍度≥CNN，激活 outlier/KV 2-bit 即崩）、dim06（99.8% FLOPs 是 MAC、decode 权重 GEMV 占 73.8% 执行时间；softmax/LN 必须数字单元）、dim10（NAND 电流波动 2–3.5nA 掉点证据）。
- 推理：CIM 噪声主要注入权重通路（编程误差/retention），恰好落在容忍度最高的通路上；而真正脆弱的激活与 KV 本就不经过 CIM 阵列。主流架构（Cambricon-LLM/KVNAND/NASiC）的"flash 做 decode 权重 GEMV、NPU 做 prefill 与非线性"分工与此完全吻合。
- 含义：NAND CIM 的精度风险可控，设计重点是 outlier 冗余（FP16 稀疏）、噪声感知训练与 ECC/温补，而非整体回避。置信度：高。

## Insight 5："前几层数字、后几层模拟"这类固定启发式不可作为调度规则，层映射必须 per-model 剖析
- 来源：dim06（LionHeart 实测 first-last 映射行为不可预测；GPT-2 AIMC 逐投影画像最敏感在 block0 内部投影）、dim07（首末层 KV 敏感但权重耐噪——两条通路敏感度排序不一致）。
- 推理：层敏感度随模型架构、量化方案、噪声注入点而变化；权重与 KV 两条通路的敏感层排序甚至相反。因此软件调度层需要的是"离线 perturbation 剖析 → projection 级映射表 → 运行时按表调度"的工具链，而非静态规则。
- 含义：对 NAND CIM 落地，模型适配工具链（剖析器 + 映射编译器）是比阵列本身更长的短板。置信度：高。

## Insight 6：快照回放 + 存力指标体系是 HBF 仿真的入场券——最大争议（SSD 层入列与否）本质是 I/O 路径问题，可被回放实验直接裁决
- 来源：dim09（Chakra ET/Vidur 回放、MBU/SM 决策树）、冲突区 C2（Tutti vs LMCache/VAST 相反实测）、dim01（GPU-centric vs CPU-centric）。
- 推理：C2 冲突双方结论相反但各自为真——差别在 I/O 路径（是否 GPU 直访）与对象粒度。这意味着 HBF 仿真工具的微调关键不在 NAND 介质模型，而在 I/O 路径建模（GDS/CPU 拷贝路径、队列深度、对象粒度）。
- 含义：仿真工具适配 HBF 时，模型侧需重点参数化：注意力变体（MHA/GQA/MLA 决定 KV 流量 0.18–0.84TB/s 差 4.7×）、层数/隐藏维、上下文长度分布、并发与 SLO。置信度：中高。

## Insight 7：国内互联格局"多轨并行、RoCEv2 兜底"决定了 HBF 类产品的国产化接口策略
- 来源：dim02（灵衢 UB 私有转向开源、UALink/ETH-X/EthLink/OISA 多轨、2026 年内不收敛）、dim01（KV 搬运事实标准 GPUDirect RDMA）。
- 推理：标准不收敛期内，任何新存储介质若绑定单一私有总线将丧失跨厂商 KV 池化市场；支持 RDMA/RoCEv2 + PCIe/CXL 双接口是风险最低的切入点。
- 含义：HBF 主控接口规划应将 RoCEv2 兼容作为一等需求。置信度：中。
