## 5. 大模型打分评价体系与用户关心指标（对应模型问题 6）

2024–2026 年，大模型评价体系收敛为"质量＋服务性能"的双层结构：质量维度回答"模型能不能做对"，服务性能维度回答"服务得快不快、稳不稳、贵不贵"。本章依次梳理两层的指标构成与数值口径（5.1、5.2）、不同用户角色的指标分野与业界选型框架（5.3），以及污染、刷榜、Goodhart 效应三大方法论争议（5.4）。本章结论先行：评价维度已高度标准化、可明确枚举；"用户关心的指标"随角色系统性分野；且任何单一分数都不足以支撑选型，多源交叉是 2026 年的主流实践。

### 5.1 质量维度

#### 5.1.1 学术基准快速换代：MMLU→MMLU-Pro/HLE、HumanEval→SWE-bench、NIAH→RULER

质量层的第一特征是基准生命周期缩短至 18–24 个月，"饱和→被污染→换代"成为固定节奏。知识/推理主线上，大规模多任务语言理解基准（MMLU，57 学科约 1.6 万题）前沿分数已达 88–94%，标签噪声封住天花板，被判定饱和 [^748^][^715^]。继任者 MMLU-Pro 将题量精炼至 12,032 题、选项从 4 扩至 10，随机猜中率由 25% 压到 10%，24 种 prompt 风格下方差仅 2%（原版 MMLU 为 4–5%）；思维链（Chain-of-Thought, CoT）提示在 MMLU-Pro 上带来可测收益、在原版 MMLU 上近乎无效甚至为负，证明继任者确实在考推理而非记忆 [^718^]。再往上，GPQA Diamond 以 448 道研究生级理化生选择题维持区分度——PhD 专家准确率仅 65%、可自由上网的非专家仅 34% [^717^]，但前沿分数仍在 18 个月内从约 40% 爬升至约 80% [^749^]；HLE（Humanity's Last Exam，2,684 题专家级开放作答）带工具前沿约 53%，是当前远未饱和的天花板基准 [^716^]。数学与代码线上，GSM8K（98%+）与 MATH（80%+）相继饱和且 GSM8K 被证实污染，换代至 AIME 2025 与 FrontierMath；HumanEval/MBPP 因饱和叠加污染，让位于 SWE-bench Verified（500 个真实 GitHub issue）与按时间戳滚动采集竞赛题的 LiveCodeBench [^715^]。长上下文线上，单针大海捞针（Needle-in-a-Haystack, NIAH）已在 1M token 规模饱和；继任者 RULER 以 13 个任务、4 大类在 4K–128K 六档长度实测，发现受测模型在原始 NIAH 上接近满分、但随长度增加性能大跌，仅 4 个模型在 32K 长度保持满意表现 [^719^]；LongBench 则以 21 个数据集、6 大任务类提供中英双语多任务口径（英文平均 6,711 词）[^720^]。

基准换代之后，"多大差距才算数"成为读榜前提：业界校准规则为 Arena ELO 差 >20 分、MMLU >2 个百分点、GPQA Diamond >4 个百分点才有意义，置信区间重叠即不可区分 [^749^]。推理预算披露同理——每个分数应附采样数 k、答案选择机制与每题 token 成本，否则"90% on MATH"可含 20 个百分点歧义（pass@1 与 best-of-256 之差）[^751^]。偏好侧，Chatbot Arena 以盲测两两投票拟合 Bradley-Terry 模型，2026 年文本榜前沿约 1450–1560 分、累计 600 万+ 票 [^721^]。

#### 5.1.2 幻觉/安全/指令遵循/Agent/偏好：SimpleQA、HarmBench、IFEval、τ-bench、Arena

幻觉与事实性评测在 2024–2025 年完成一次自我纠偏：TruthfulQA 被实测证伪——约 25% 被 MC1 判错的回答其实事实正确，且含金标错误或过时答案 [^724^]；OpenAI 的 SimpleQA（4,326 道短事实题）以 correct-given-attempted 的倒数近似幻觉率，发布时 GPT-4o 与 Claude-3.5 得分不足 40%，且普遍过度自信、不肯弃答 [^724^]；Google DeepMind 的 SimpleQA Verified 经去重、主题平衡与多源核验清洗出 1,000 题，Gemini 2.5 Pro 以 F1 55.6 居首 [^725^]。HalluLens 进一步区分内在幻觉（与输入矛盾）与外在幻觉（无输入依据），并指出静态幻觉测试集极易被新训练数据吞没，须动态生成 [^724^]。指令遵循侧，IFEval 以可程序化验证的指令（如"输出编号列表""只写一句话"）做客观 0/1 判分，规避裁判主观性 [^727^]；Artificial Analysis 的 IFBench（294 题，单轮精确合规）已纳入其综合指数 [^742^]。安全侧，HarmBench（400 个有害行为、7 大类，头条指标为攻击成功率 ASR）、JailbreakBench（可复现越狱 artifact 仓库）与 MLCommons AILuminate（12 个危害类别、24,000 条评测 prompt、输出五级评级）构成互补三件套，其中 AILuminate 的五级标签明确面向采购与非技术干系人 [^726^]。

Agent 能力评测覆盖编码、客服、网页与桌面场景，不可合并为单一排名：SWE-bench Verified 上 Claude Opus 4.7 以 87.6% 领先 [^728^]；τ-bench 以 165 个客服任务考核 pass^k（k 次独立运行的一致性）与政策合规 [^729^]；WebArena（812 任务）与 OSWorld（369 个真实桌面任务）补足交互面 [^728^][^729^]。比分数更重要的是五个"真信号"指标——latency p50/p95、任务成功率、cost per task、N-run reliability（同任务 5–10 次重复成功率）与 tool-use success rate：单次运行 90% 的成功率，在重复运行下可能只有 60% 的可靠度 [^728^]。需警惕的是，2026-04 UC Berkeley/RDI 演示 8 大 Agent 基准全部可被 reward hack 至约 100%，第三方复现分加自有 holdout 成为必要防线 [^728^]。综合框架侧，Stanford HELM 同时输出 accuracy、calibration、robustness、fairness、bias、toxicity、efficiency 七维画像而非单一分 [^730^]；LiveBench 以月度更新题目加客观 ground truth 自动判分定位"抗污染"，头部模型仍低于 70% [^731^]。

### 5.2 服务性能维度

#### 5.2.1 八件套：TTFT/ITL/E2E/吞吐/goodput/SLO 达成率/每 token 成本/MFU（指标定义表）

2024 年以来，推理服务性能指标已标准化为八个一组的口径（表 5-1），覆盖延迟、产能、成本与效率四个侧面；本报告第 6 章的系统搭建将以本表指标作为服务等级目标（Service Level Objective, SLO）的输入。

表 5-1 大模型推理服务性能"八件套"指标定义

| 指标 | 全称/别名 | 定义与口径 | 决定什么 |
|---|---|---|---|
| TTFT | Time To First Token，首 token 时延 | 请求到达到首个输出 token 的时延，含排队调度与 prefill；不附 prompt 长度的 TTFT 数值近乎无意义 [^701^][^702^] | 响应感 |
| ITL / TBT / TPOT | Inter-Token Latency / Time Between Tokens / Time Per Output Token | decode 阶段相邻 token 间隔；TPOT 为均值口径，TBT 逐 token 考核、更为严格 [^701^][^708^] | 流畅感 |
| E2E / TTLT | End-to-End Latency / Time To Last Token | 调度＋prefill＋decode 的完整请求时延 [^752^] | 整请求体验；代码补全等"部分输出无价值"场景的唯一口径 |
| 吞吐 | Throughput | 全系统聚合 tokens/s，不计延迟或 SLO 达成 [^706^] | 原始产能 |
| Goodput | 有效吞吐 | 满足 SLO 达成目标（如 90%）前提下每 GPU 可服务的最大请求率 [^705^] | 直接换算每查询成本 |
| SLO 达成率 | SLO Attainment | 满足 TTFT/TBT 目标的请求比例，按 P90/P99 尾部评估 [^705^][^707^] | 服务等级合规 |
| 每 token 成本 | $/M tokens | 对负载极敏感：同一 H100＋Mixtral 8x7B，1 rps 与 25 rps 的成本相差 17.5–36.3× [^712^] | 成本曲线与容量规划 |
| MFU | Model FLOPs Utilization | 实际达成 FLOPs/s ÷ 硬件峰值 FLOPs/s；大规模训练典型 35–45%，推理 decode 仅 8–12% [^710^] | 效率诊断（非优化目标） |

八件套内部存在结构性张力，读数必须成组而非孤立。其一，吞吐与体验不可兼得——交互场景下"throughput matters only after TTFT is acceptable" [^704^]，goodput 因此成为统一产能与体验的度量：DistServe 实测 13B 模型在 A100、90% SLO 达成率下，prefill/decode 共置的 per-GPU goodput 仅 1.6 rps，分离部署后整体达 10 rps（2.1×）[^705^]。其二，成本指标必须画成负载曲线而非点估计：10% 负载会把 $13/MTok 放大为 $130/MTok [^712^]；行业层面 API 价目呈"LLMflation"——2021 年以来推理成本每年降约 10×，GPT-4 发布价 $30/$60（2023-03，输入/输出，$/M tokens）降至 GPT-5 的 $1.25/$10（2025-08），三年等效降约 95% [^711^]。其三，MFU 是诊断指标而非优化目标——"70% MFU 但收敛损坏"不如"35% MFU 但训练稳定"，且 decode 阶段 8–12% 是访存瓶颈决定的 roofline 上限，并非优化不力 [^710^]。

#### 5.2.2 典型 SLO：TTFT<0.5–2 s、TBT 50–100 ms；长上下文另看 KV/prefix 命中率

交互场景的业界惯例为：TTFT <500 ms 属优秀（用户感到即时）、500 ms–2 s 可接受、>3 s 用户开始流失 [^703^]；学术评测常以 TTFT<2 s、TPOT<0.08 s 为 SLO 约束 [^706^]，SGLang 生产部署指南将 TTFT p95>2 s 设为告警线 [^745^]。语音 Agent 的预算更苛刻：1 秒话轮中，语音识别端点检测约 150 ms、语音合成起播约 150 ms，留给 LLM 的 TTFT 约 600 ms，超过该值用户即感知"慢"，与模型质量无关 [^704^]。ITL 一侧对齐人类阅读速度：平均 250 词/分钟约合 6 tok/s 为下限 [^701^]，5–15 tok/s 覆盖正常阅读区间 [^702^]，60 ms ITL 约合 16 tok/s 的"流畅打字"体感 [^703^]；学术 SLO 常用 TBT 50 ms（8B 模型）与 100 ms（70B 模型）[^707^]，goodput 修正指标（smooth goodput）以 20 tok/s 为默认信息消费速度 [^709^]。

长上下文与多轮场景需在八件套之外追加 KV cache/prefix 缓存命中率指标，因为它直接换算为 TTFT 下降与 prefill 成本节约。生产命中率量级为：固定文档库检索增强生成（Retrieval-Augmented Generation, RAG）场景 40–70%、持久会话多轮聊天 20–40%、上下文高度独特的代码补全 <10% [^747^]；共享系统提示与工具定义的 Agentic 多轮负载可达 75–95% [^745^]；SGLang 论文报告各基准命中率 50–99%，cache-aware 调度达理论最优命中率的 96%，吞吐最高提升 6.4× [^746^]。换算关系上，并发 50 时前缀重叠 20%/40%/60%/80%/95% 分别对应命中率约 28%/54%/71%/84%/93%，TTFT 相对下降约 7%/15%/24%/37%/44%——前缀重叠超过 60% 时缓存收益明确，低于 40% 则收益边际 [^744^]。

### 5.3 用户角色分野与选型框架

#### 5.3.1 终端用户/运营/开发者指标差异；Artificial Analysis 指数 + 真实用量交叉选型

"用户关心什么指标"没有单一答案，四类角色的首要指标系统性不同（表 5-2）。

表 5-2 不同用户角色的首要指标与关注点

| 角色 | 首要指标 | 说明 |
|---|---|---|
| 终端用户 | TTFT、流式速度（ITL/输出 tok/s）、E2E | TTFT 即感知响应度，语音场景中是"死寂空气" [^702^]；>3 s 无输出即流失 [^703^]；流式速度须超过约 5–15 tok/s 的阅读速度 [^702^] |
| 应用/产品开发者 | 任务匹配的质量分、成本-质量-速度 Pareto、cost per task | 选型看 2–3 个匹配场景的基准而非 16 个；指标预先承诺 latency p50/p95、accuracy、cost/task、N-run reliability、tool-use success [^728^] |
| 平台运营/SRE | goodput、聚合吞吐、SLO 达成率（P90/P99）、GPU 利用率/MFU、每 token 成本曲线、KV 命中率 | goodput 直接换算 cost per query [^705^]；成本随负载 17.5–36× 摆动，容量规划必须画成本-负载曲线 [^712^] |
| 采购/管理层 | 综合质量-价格-速度指数、安全评级、TCO | Artificial Analysis 的 Intelligence Index＋Blended Price＋Output Speed 三角图 [^741^][^742^]；AILuminate 五级标签面向非技术干系人 [^726^] |

角色之间的指标可能直接冲突：2,000 tok/s 吞吐但 4 秒 TTFT 的服务在对话场景"感觉很慢"，200 ms TTFT 但 30 tok/s 的服务"开头轻快、长答案卡顿"，因此必须成组测量并映射到产品的会话预算，而非追逐单点最优 [^704^]。对运营侧，goodput 与成本-负载曲线才是容量规划的一等输入，终端用户侧的延迟分位数只是约束条件；对采购侧，成本-质量-速度三轴之外还需叠加安全评级等合规信号。

业界选型框架已收敛到"quality–speed–price 三轴＋真实用量"的交叉结构。Artificial Analysis 以 8 个基准等权合成 Intelligence Index（v3 口径：MMLU-Pro、HLE、GPQA Diamond、AIME 2025、SciCode、LiveCodeBench、IFBench、AA-LCR 长上下文推理）[^742^]；价格侧定义按 7:2:1（缓存命中:输入:输出）加权的 Blended Price，以及按实际 token 消耗核算的 Cost per Task——输出更长答案或更多推理 token 的模型，即使单 token 价格相同，单任务成本也更高 [^741^]；其性能口径明确"不代表某硬件平台上的最大可能性能，而代表客户跨供应商真实体验到的性能" [^741^]。OpenRouter 提供需求侧信号——按真实 token 消耗量排名，研究证实其覆盖 296 个模型自 2025-01 起的日级 prompt/completion token 数据 [^743^]。偏好侧另有 GDPval-AA：1,320 个覆盖 44 种职业、9 大 GDP 行业的真实经济价值任务，同样以 Bradley-Terry 拟合 [^750^]。多源交叉而非单一榜单，是 2026 年的主流选型实践 [^721^]。

### 5.4 评测方法论争议

#### 5.4.1 基准污染、Arena 刷榜（虚增可达 112%）、Goodhart 效应

争议一为基准污染。ConTAM 研究（13 个基准 × 7 个模型）的结论是污染影响"可能比近期模型发布报告声称的大得多" [^733^]；Phi-4 技术报告自陈 n-gram 去污染"对包括改写在内的场景并非全部有效"，并列举基准的另三宗罪——技能面窄、judge 偏风格、选择题可蒙 [^735^]。合成数据时代的污染分四级：token 级原样、改写级、语义近邻、推理模式级，后两级使传统 n-gram 检测完全失效 [^755^]。工程缓解手段为动态滚动基准（LiveBench 月度更新 [^731^]）、私有 holdout（ARC-AGI 2、HLE）与绝不公开的内部黄金集 [^715^][^739^]。

争议二为 Arena 偏差与可操纵性。风格层面，回答长度是主导混淆因子（Bradley-Terry 回归系数 0.249–0.267），加入风格控制后前排重排 1–3 位 [^722^]。操纵层面，《The Leaderboard Illusion》披露 Meta 在 Llama-4 发布前私下测试 27 个变体并选择性披露最高分，作者估算额外数据访问可带来最高 112% 的分数提升 [^736^]；针对投票的定向操纵（vote rigging）亦有学术复现 [^737^]。可用的读数口径是：头部分数在 50–100 Elo 分粒度上大体可信，在 10–30 分粒度上不可信 [^723^]。

争议三为 Goodhart 效应——指标一旦成为目标便失效。即使无人作弊，"每个团队都按基准选模型、调超参"的发表反馈环也会让基准泄漏进开发决策，形成系统性过拟合；外部检验法是观察 MMLU 上涨是否同步带动 BIG-bench 与自然偏好提升，不同步即疑似 gaming [^739^]。缓解共识是"任何单一评测指标都不应被孤立信任"：私有黄金集＋1–5% 生产流量持续采样评分＋多基准交叉＋公开全部私下测试结果 [^728^][^736^][^739^]。

综合判定：问题 6 的预设成立——评价维度可枚举且已标准化（质量双层结构＋服务八件套），用户关心指标随角色分野且均有定量口径；需要修正的常见预期是"找一个总分最高的模型"——2026 年的可信实践是质量分、服务性能、真实用量与私有 eval 的四路交叉验证，单一榜单只配当初筛、不配当终裁 [^721^][^739^]。
