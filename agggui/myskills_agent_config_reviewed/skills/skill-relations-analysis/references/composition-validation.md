# 多 Skill 组合的验证设计

检查分为材料/设计检查、真实加载与路由、真实业务执行。不能互相替代。本 Skill 只设计案例和审查已有证据；运行被分析对象需要另行获授权的执行任务及实际工具条件。

## 三个问题分别测

1. **选得对吗**：应选/不应选/可选/禁止的 Skill 集合；允许多个合理组合。包含无需任何 Skill 的通用任务、相邻场景反例、同名来源和明确单选约束。
2. **组合成立吗**：必需依赖闭合、输入映射有效、条件真实成立、共享写无冲突、失败只影响相关下游、汇总不掩盖分歧。多 Skill 组合可能比单个更差。
3. **结果值得吗**：质量、完成率与成本分别记录。读取 SKILL.md 不等于遵循关键步骤；记录 skill_load、reference_read、关键方法行为、工具与产物证据。无法采集时写 unknown。

## 对照与隔离

固定任务、输入快照、环境和预算；按任务选择无 Skill、旧配置、仅 A、仅 B、A+B、合并版对照，不要求每次运行全部条件。比较选择器时固定执行器，比较编排时尽量固定选择集合，避免混淆归因。

保留未用于改写的任务族、反例与相邻领域，特别是专业 Skill 对通用问答的干扰。一个任务可有多种有效拓扑，按约束与结果验收，不用唯一序列字符串作为金标。

同模型不同 session 或系统提示词可分离生成与评估角色，但不等于不同模型，也不自动消除偏差。若调用裁判，按目标环境 v1 端点配置、temperature=0、结构化结果和分维度模板；偏好比较交换 A/B 顺序，基础设施失败单列 error，不能记成正确拒选或任务失败来优化 description。

## 案例记录

本包 evals/scenarios.json 提供设计案例种子，均为人工构造，尚未运行。字段：id、prompt、setup、expected、forbidden、validation_level。替换为内部真实路径、Skill 及场景后再执行，不将示例当真实运行统计。

每次记录配置版本、工具条件、实际选集/顺序/主体、产物、错误、耗时/token 与验收证据。合并版按原任务族分别报告；不能只看总平均。小样本只用于发现问题，不宣称统计显著收益。
