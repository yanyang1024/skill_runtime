> 配套课件：《用 OpenCode 开始 Vibe Coding · 基础教程》第 7 章（第 18–25 页）
> 定位：基础教程之后的实战篇，面向已完成安装配置、跑通过基本会话的学员

## 本章概览

本章把前面学到的能力（配置、AGENTS.md、自定义 agent、skill）落到四类真实工作场景：

| 场景 | 典型问题 | 核心打法 | 对应课件页 |
|------|----------|----------|-----------|
| 生成内容 | 碎片信息堆给 AI，PPT 平庸、重点不突出 | 指令补齐四要素：受众、素材、结构、风格 | P19 |
| 编程排错 | EDA 脚本报错，日志长、层级深，人工定位慢 | 复现 → 插桩日志 → 分析定位，三步循环 | P20 |

## 1. 碎片信息 → 美观且重点突出的 PPT

### 问题分析

碎片化信息本身不是障碍——AI 很擅长整理素材。真正的障碍是**指令里缺少判断依据**：AI 无法替你决定"什么是重点、给谁看、什么场合用"。所以方法不是"把信息喂得更整齐"，而是"把判断依据补全"。

### 解法：指令四要素

1. **受众与场合**：给谁看、投影还是自行阅读——决定内容密度与字号大小。
2. **素材清单**：碎片信息全部贴入，并标注哪些是事实、哪些待补充（防止 AI 编造）。
3. **结构与页数**：先要大纲，确认后再成片；说清楚重点放在哪一页。
4. **风格与禁区**：给色板或参考模板，并明确"不要什么"（比"要什么"更有效）。

### 提示词模板（生成）

```text
做一份 8 页 PPT，部门月会投影用。
受众：硬件组同事；目的：同步项目进度。
素材如下（均为事实）：……（贴入碎片信息）
先给大纲我确认，再出片；重点放第 3 页。
风格：浅色底、不用圆角卡片。
```

### 优化迭代：指出具体问题

迭代效果取决于反馈的颗粒度：

- ✗ "再好看一点" —— AI 不知道改哪里，只能随机换样式
- ✓ "第 3 页结论不明，把良率数字放进标题"
- ✓ "第 5 页字太密，拆成两页"

### skill 参考

- Anthropic 官方 skills 库（github.com/anthropics/skills）中的 `pptx` skill 是目前最常用的文档类 skill 之一，同库还有 `xlsx` / `pdf` / `docx`。
- 团队若有固定模板与评审标准，值得沉淀为自己的 SKILL.md（写法见基础教程第 14 页"四种 Markdown 的分工"）。

## 2. EDA 脚本报错：AI 辅助快速定位

### 问题分析

EDA 场景的特殊性：工具日志动辄几千行、报错层级深（wrapper 套 wrapper）、人工翻日志定位慢。AI 擅长读长日志，但前提是**按固定流程喂**，而不是把整份日志直接丢过去问"哪错了"。

### 解法：三步循环

**第一步 · 复现**：让 AI 给出最小复现命令，确认错误可以稳定重现。日志太长时，先让它 grep Error / fatal 段落，缩小范围。

**第二步 · 插桩**：让 AI 在问题点前后插入日志——关键变量值、分支进入点、外部工具返回码——然后重新执行，拿到带上下文的新日志。

**第三步 · 分析**：把新日志喂回 AI 定位根因。**一次只改一处**，改完重跑验证；不行就回到第一步，不要一次接受多处修改。

### 常用提示词

```text
# 复现
"运行 run_flow.tcl 报错如下（贴日志），先给出最小复现步骤，不要改代码"

# 插桩
"在 problem_proc 入口和出口插入日志，输出关键变量值，然后重新运行"

# 分析
"根据新日志（贴入）分析根因，只改一处并说明理由"
```

### 使用建议

- **固化为 skill**：EDA 调试目前没有成熟的现成 skill，建议把这条三步 SOP 写成 `.opencode/skills/eda-debug/SKILL.md`，description 里写清触发条件（如 "use when a Tcl/EDA script fails"），每次报错 AI 自动按流程执行。写法可参照 anthropics/skills 中的 `skill-creator`。
- **撰写时就为排错做准备**（对"边写边 debug"场景同样适用）：让 AI 写新脚本时自带日志（关键变量、分支、返回码）和 `--dry-run` 模式；把团队的日志规范写进项目 AGENTS.md，每个会话自动生效。

## 3. A 脚本 + 变化点 → B 脚本

### 问题分析

"参考 A 写个 B"最容易翻车的地方：AI 自由发挥改动了不该动的部分，或者改了但没改全，而人靠肉眼读脚本很难发现。解法的关键是**把"改什么"和"怎么算改对了"都变成显式约定**。

### 解法：三条约束

1. **输入给全**：A 脚本全文 + 变化点清单 + 明确"不能动"的部分（工具调用命令、license 检查段等）。
2. **先说明，后改码**：要求 AI 先输出函数级的变更说明——改了哪些、为什么——你确认后再生成 B。
3. **验收可执行**：同一份测试输入分别跑 A 和 B，输出逐行比对；不一致即报警，人只做最终判断。

### 提示词模板

```text
附上 A 脚本 flow_a.tcl（全文贴入）。
变化点：① 工艺节点 N7 → N5；② 时钟约束 1GHz → 2GHz。
不要改：工具调用命令与 license 检查段。
先列出函数级变更说明，我确认后再生成 B。
B 生成后输出与 A 的 diff，并给出验收命令（同输入跑 A/B 比对输出）。
```

### 使用建议

- 验收脚本也让 AI 写：跑同输入 → 比对输出 → 不一致即报警。脚本功能是否等价，用运行结果说话，不靠肉眼读 diff。
- 变更说明和 diff 一起进 commit message，下次再改有据可查。
- 分工原则：AI 负责"改"和"自证"，人负责"定义变化点"和"拍板验收"。变化点越具体，返工越少；"顺便优化一下"这类模糊要求是返工的开始。

## 4. 数据处理总原则：让 AI 写脚本，人管 format 与校验

### 四步流程

```
① 小样试喂  →  ② AI 归纳规律  →  ③ 人确认 format  →  ④ 全量执行 + 双向校验
```

1. **小样试喂**：数据又大又乱时，先喂 10–20 条样本，不要整份丢给 AI。
2. **AI 归纳规律**：让 AI 分析样本——字段有哪些写法、分隔符是什么、异常行长什么样。
3. **人确认 format**：看懂规律后，由你写下目标格式：列名、顺序、日期格式、缺失值约定。
4. **全量执行**：AI 按 format 写转换脚本，全量跑，输出校验报告。

### 为什么写脚本，而不是让 AI 直接吐结果

- **可重复**：数据更新后重跑一次即可；
- **可校验**：转换逻辑是代码，错了能改能查；
- **可留档**：脚本进 Git，下次同类任务直接复用；
- 直接对话输出几千行，错了你也看不出来。

### 双向校验清单

- 行数一致：输入 N 条 → 输出 N 行；
- 字段齐全：每行列数 = format 约定列数；
- 抽样比对：随机 5 行与原始数据逐字核对；
- 关键值核对：总额、计数等整体指标对得上。

> 分工原则：规律由 AI 归纳，format 由你拍板——只有你知道下游要什么。校验脚本同样让 AI 写，但**校验标准由你定**。

## 5. 演示：乱格式名单 → 目标表（模拟数据）

> 练习材料 · 以下数据为模拟数据，可照着完整复现一遍流程。

### ① 输入样本（喂给 AI 的一小段）

```text
张三 工号A1023 入职2021.3
李四-A1057；入职：2020/11
王五 A1109 （入职 2019-07）
赵六，A1078，2022.1 入职
```

### ② AI 归纳的规律

- 姓名：中文 2–3 字，总在行首；
- 工号：均为 A + 4 位数字；
- 日期有 4 种写法：2021.3 / 2020/11 / 2019-07 / 2022.1，都指年月；
- 分隔符混乱：空格、-、；、，、（）。

### ③ 人确认的目标 format

```text
目标表三列：姓名 | 工号 | 入职日期
日期统一为 YYYY-MM；
解析不出来的行单独输出，不许丢弃
```

### ④ 转换结果与校验

```text
张三,A1023,2021-03 ｜ 李四,A1057,2020-11
王五,A1109,2019-07 ｜ 赵六,A1078,2022-01
校验：输入 4 条 = 输出 4 行，工号全匹配 ✓
```

> 照着自己练：换一份你手头的真实乱数据，先喂 20 条走一遍同样流程；format 没写清楚之前，不要让 AI 动全量数据。

## 6. 场景 1：工号 + 姓名 → 邮箱（企业内部工具）

### 流程

1. 输入名单：每行工号 + 姓名；
2. AI 逐条提取工号，调用**工号校验接口**；
3. 校验通过后，按企业规则拼接邮箱；
4. 再调用**邮箱 Agent 接口**二次校验；
5. 输出对照表：姓名 | 工号 | 邮箱 | 校验结果；失败行单独列出。

发邮件前不用再逐个添加校验——校验在生成阶段就完成了。

### 提示词模板

```text
"这份名单（贴入）逐条处理：先调工号校验接口，通过后生成邮箱并调邮箱接口校验，
输出对照表，校验失败的行单独列出并说明原因"
```

### 要点

AI 不"猜"邮箱，只负责编排：查证交给接口，format 交给你，结果对得上才放行。

## 7. 场景 3：PDF 数字信息 → Excel，且不漏数

### 问题分析

PDF 数字提取最大的风险是"漏"——直接让 AI 读 PDF 输出表格，漏了一行很难发现。解法是**把"不漏"变成可检查的**：先转中间格式，再用校验脚本逐页回查。

### 管线

1. 解析脚本把 PDF 转成 md / json 中间态；
2. 分类合成：数字信息 → csv（可导入 Excel）；图文内容 → html；
3. 校验脚本**逐页回查**：每页出现的数字，是否都在 csv 里；
4. 输出缺失报告；有缺失就回第 1 步修解析规则，再跑。

"不漏数"不靠肉眼，靠分页 loop 把漏数变成一张可报告的清单。

### 提示词模板

```text
"写脚本解析 report.pdf：先输出 md+json，数字提取到 out.csv；
再写校验脚本逐页检查每页数字是否都在 out.csv 中，输出缺失清单。
先处理前 3 页给我看结果"
```

### skill 参考

PDF 解析可参照 anthropics/skills 的 `pdf`、`xlsx` skill 思路：先中间格式、再合成、再校验。
