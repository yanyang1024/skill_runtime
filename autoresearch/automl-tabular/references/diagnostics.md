# 诊断表与搜索空间起点（阶段三）

## 1. 反馈诊断表

以下每一行是**待验证的假设**，不能仅凭一个分数断言原因。
"效果不好"先在这里定位，再决定动作——调参只是八种动作之一。

| 观察到的反馈 | 先查什么 | 下一轮可能的动作 |
|---|---|---|
| 训练、验证都差 | 标签/样本对齐、损失、特征可用性、训练是否收敛 | 修数据或训练；再考虑增大容量 |
| 训练好、验证差 | 分布变化、模型容量、样本量、划分合理性 | 正则化、简化模型、补数据；确认不是评估口径变化 |
| 平均分不错，某类/某设备/某时间段很差 | 子群样本量、标签质量、分布差异 | 错误切片、加权/采样或专门补数据 |
| 最好参数频繁落在搜索边界 | 搜索范围是否限制了模型 | 有依据地扩大边界；保留原默认参照 |
| 多次"提升"小于 seed 波动 | 候选差异是否稳定 | 对少数候选做配对多 seed 复核，不急着继续搜索 |
| 频繁 OOM/超时/配置错误 | 数据管线与资源可行域 | 缩小可行空间、修执行；不把系统异常伪装成模型低分 |
| 验证分数异常高 | 泄漏、重复、标签后验字段、指标实现 | 先审查数据和 evaluator，再庆祝 |
| 训练更好但推理很慢 | 集成数、模型规模、预处理、batch | 简化、refit/蒸馏或换模型；把部署成本纳入约束 |

停止条件不设单一固定阈值：按时间预算、噪声水平、有效 trial 数与提升幅度
联合判断。短预算筛选出的候选必须在**相同完整预算 + 多 seed** 下复核后才算数
——短跑胜者可能只是前期收敛快，未必在完整预算下更好。

## 2. 各模型族的第一轮搜索空间

原则：先小范围调试合法性，再按诊断结果扩大。连续正值尺度用 log 分布；
架构、优化器、离散 batch 用 categorical；条件参数只在对应分支出现。

| 模型族 | 第一轮优先搜索 | 不急于扩大 |
|---|---|---|
| 正则化线性模型 / SVM | 正则强度（log）、必要的类别权重 | 全部 solver × penalty × kernel 的无约束笛卡尔积 |
| LightGBM / XGBoost / CatBoost | 学习率（log）、树复杂度、叶节点最小样本、采样与正则；固定 n_estimators 上限配 early stopping | 把所有参数暴露给 agent；不合法 depth/leaves 组合 |
| 小型 MLP / CNN / Transformer 微调 | 学习率（log）、weight decay、可行 batch size、dropout；固定骨干先调训练 | 一开始同时搜架构、优化器、增强、损失和数据版本 |
| 大模型微调 | 固定训练方法下调学习率、有效 batch、训练长度；LoRA 时再考虑 rank | 同时跨模型规模、量化、训练方法和模板做巨型搜索 |

## 3. 计时公平性

不同模型只比较 epoch 数不公平：计时同时记录训练本体和含数据加载/编译/验证的
总耗时。结果 JSON 的 `cost.wall_seconds` 以总耗时为准。
