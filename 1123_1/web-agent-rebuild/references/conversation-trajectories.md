# 对话轨迹、任务过程与文件历史

## 先分清三个历史

- 对话历史表达用户意图、补充和答复；按轮次显示，引用可回到对应文件版本。
- 执行轨迹表达实际发生的动作、证据、状态和失败；按目标/阶段分组，默认摘要，需要核对时再展开。
- 产物历史表达文件发生了什么变化、由谁采纳和保存；链接回来源轮次与运行，但不把每个 token 保存为一个业务版本。

按实际需求关联会话/分支、运行、步骤、产物与版本，不强制引入全套事件平台。持久状态来自运行时和存储；模型生成的“正在查询”文本不作为执行证据。

## 用问题驱动渐进展开

默认回答：当前在做什么、完成了什么、哪里卡住、改了哪些文件、下一步可做什么。每轮以简短结果和产物链接结束；长工具输出默认折叠，失败、等待输入与取消未确认保持可见。展开层提供必要参数摘要、来源、耗时、重试关系和差异；详细日志放诊断入口并按权限脱敏。

轨迹呈现可核对的动作与依据，不暴露或伪造模型内部思维链。不凭动画制造进度百分比；未知耗时显示阶段或等待原因。平行工具按父任务分组，以事件顺序/时间和稳定标识更新，迟到事件不能倒退终态。长历史按轮次加载；虚拟化需验证查找、复制、锚点、屏幕阅读器和回看位置。

## 分支与恢复应有清楚语义

编辑旧提问或重新生成时保留原路径，并标明当前分支与分叉点。简单任务用局部分支选择器就够；只有需要比较多条调查路径时再提供树图。切换分支不自动回滚共享文件，旧分支的产物链接打开对应历史版本；若希望创建独立工作副本，显式选择复制/分叉产物。

“继续对话”“重试失败步骤”“重新生成答案”“恢复文件版本”是不同动作。重试绑定新运行/尝试记录；外部写入不能因回放聊天或刷新而重做。已取消/失败的旧结果可以查看，不能进入当前运行或直接覆盖当前产物。真实运行时不支持分支或恢复时，说明限制并提供独立新任务，不用 UI 标签伪装支持。

## 从 B 沉淀 A

标记可复用输入、成功步骤、关键证据、人工纠正与失败边界；跨多次任务确认稳定后才推荐保存流程。路由入口展示当前匹配的任务和参数，允许纠正。保留原探索记录用于解释，但不把整段聊天当流程规范或默认输入。

验收时从任意产物版本找到对应请求和来源；从失败步骤找到恢复入口；切换分支不丢未保存编辑；刷新不重复执行。优先这些能力，再考虑完整轨迹图和动画。
