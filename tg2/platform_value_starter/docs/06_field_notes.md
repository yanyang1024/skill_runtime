## 2. 批判性复核：你的推导需要加的护栏

### 2.1 「跨部门排名判断相反、应作为低成本第一步」——部分同意，但必须公平化

组织×技能×可靠性归因确实是便宜且信号强的第一步，org_skill_map.py 就是为此写的。但"跨部门排名"有一个你自己已经意识到的反例：**工具开发部门的失败率天然偏高**（打磨期试错是他们的工作方式）。因此落地规则是：

- 工具事件先分 `origin`（builtin/custom）和会话 `purpose`（tool_dev/tool_use）；tool_dev 会话的失败**不进**生产失败率；
- 任何一行调用量 < 阈值（默认 20）只列出不排名；
- 脚本**故意不输出跨部门失败率总榜**，只给各部门内部表 + 排除开发测试后的修复候选清单。

即：跨部门对比用于**定位问题落点**（哪个科的哪个工具），不用于**给部门排优劣**。前者低成本高价值，后者在任务结构不同的前提下天然不公平。

### 2.2 路由数字：两组实验不要混用，holdout 0.434 才是诚实数字

你报告里出现了两组数：1013 条 macro-F1 0.67 / 阈值 0.5 覆盖 23% 准确率 95.7%；以及跨科实验 dev 0.570 / holdout 0.434。这不是矛盾，是**两种评估协议**（随机切分 vs 跨科泛化），对外引用时必须说明用哪个。跨科 holdout 0.434 更接近真实上线的下界——新部门、新措辞。

另外两个具体警告：

- **coding 类 holdout F1=0.0 只有 n=3**，这是小样本噪声，不能作为"启发式短板"的证据，也不能作为"路由对 coding 无效"的证据；补样本之前两类结论都别下。
- **阈值选择只能看 dev**。如果"阈值 0.42 → holdout 74.2% 覆盖"是在 holdout 上调出来的，那这个 holdout 已经污染，下一轮要换新的独立 holdout。

### 2.3 「路由改写提示词，不换模型也能加速」——好假设，但现在只是假设

思路本身有先例（检索里的 query expansion / 路由后 prompt conditioning），route_hint.py 把它做成了可验证的形式：置信度够才加提示（abstain 不加），同一冻结题集、同一模型跑"无提示 vs 有提示"两版，`ab` 子命令成对比较。

判定顺序固定：**先看退步题**（路由错标会主动误导模型，这是这个方案最大的隐藏成本）→ 再看通过率差 → 最后才看 token/延迟节省。"不用换模型也能加速"只有在"通过率不降且成本降"同时成立时才能写进汇报。在那之前，报告里写"待验证假设"。

### 2.4 复用检测：upload 确实比 read 强，但要分两级

你提的"文件产物作为其他会话的上传"是对 blank 维度最好的补丁，reuse_signals.py 实现了它，同时保留两条批判线：

- **同用户复用 ≠ 平台资产**。自己把自己的文件带进新会话是粘性；产物被**其他用户/部门**采用才是可汇报的资产证据。两类分开报，不加总；
- 身份对齐只认 artifact_id+version/内容哈希，basename 相同仍不作数；
- 不算"全平台复用率"——分母（可被复用的产物全集）不可观测，算了就是下一个 0.18%。

另外补一个你没提但同源的机会：**skill/agent 本身就是可复用资产**。一个 skill 被几个科、多少人用（reuse_signals.py 的 skill_reuse 表），比文件复用覆盖更全，且天然有身份（skill 名），建议放进汇报。

### 2.5 「组织是信息量第一的切片」——同意，但它仍是切片

组织归因强（失败率、token、技能全按科分化），已升级进 01 号文档作为第一分析维度。但保留一条边界：部门是**切片维度**，不是**价值主体**——"IAD-D token 占大头"回答"资源用在哪"，不回答"IAD-D 产出了多少价值"。后者仍然只有案例卡 + 用户确认能给。

### 2.6 「每周人工复核不现实，改一次性+自动化」——同意，代价要写清楚

05 号文档已改为"一次性分层抽样 + 启发式标签 + `AUTO:heuristic-v1` 待复核标记"。保留的底线：启发式标签**永远不能去掉 AUTO 前缀进入汇报数字**；"确认覆盖率 0/1055"这个数字本身就是汇报内容（证明统计≠证据），不要用启发式标签把它填成 100%。
