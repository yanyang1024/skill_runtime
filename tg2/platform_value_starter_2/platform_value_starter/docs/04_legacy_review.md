# 原三份压缩包审查与迁移建议

历史说明：以下保留 v1 对原三包的源码审查，不是对你在公司修改后的代码审查。v2 实施优先级、无需持续人工运营的方式及新增能力见 `06_empirical_update.md`，以下迁移节奏不作为当前硬性依赖。

本次逐份解压并阅读了全部独立 Python 实现及说明，未访问任何内网数据。相同文件按内容 SHA-256 比较，结论如下。

| 压缩包 | 内容关系 |
|---|---|
| `session_value_analysis(2).zip` | 最完整：基础报告/图表、token 趋势、资产引用、留存、案例库、训练导出、benchmark，共 8 个 Python 脚本 |
| `session_value_analysis(3).zip` | 基础报告和图表，与第一包相同文件内容一致 |
| `session_value_analysis_2(1).zip` | 在基础版上含趋势/资产/留存，与第一包相同文件内容一致 |

因此不建议继续把三套脚本合并成更多并列模块。保留第一包作历史参考，先用新证据管道替换有误导风险的口径和导出逻辑。原 zip 未被修改。

## 1. 必须先修的具体问题

以下位置指原包中对应文件的函数或代码段，便于你用搜索定位。

| 文件/位置 | 观察到的问题 | 影响 | 新包处理 |
|---|---|---|---|
| `session_value_report.py` / `load_session` | 任意未识别文档回退为 unknown 消息，仍 `parse_ok=True`；目录递归抓 md/json/txt | 产出文档、报告可能变成会话；解析成功率失真 | 显式文件清单；不识别角色时拒绝；结构化汇总与真实消息分清 |
| 同文件 / `est_tokens` | 用全文字符数/2 估算 | 不能还原真实多轮上下文重复、缓存和 API usage | 实测 usage 独立字段；缺失不估成本 |
| 同文件 / `session_features` | `可以` 等完成词做子串匹配 | 第一条请求就可能命中“完成” | 词表只形成待看候选，不能改变 outcome |
| 同文件 / `count_hits` | 统计命中多少种词，不是发生多少次纠正 | 同词重复十次也可能只算一次；引用/否定混淆 | 候选保留 message_index；真正错误类型人工确认 |
| 同文件 / `n_code_blocks/n_files_mentioned` | 用户输入代码块和路径也计为产出 | 高产出排名混入用户提供的文件/代码 | 交付证据与文本特征分离，不合成价值总分 |
| 同文件 / “零纠正会话（一次做对）” | 没反馈也会零纠正 | 放弃/未使用被说成一次做对 | 未知单列 |
| `asset_reuse_backfill.py` / `written/mentioned` | 按 basename 聚合；有一次 write 痕迹时把全文所有路径当产出 | 同名文件串联；读入文件被当生成；生产前引用也可能被算复用 | 同租户资产 ID+版本、成功事件、严格时间顺序；仅报观察到的读取 |
| `retention_cohorts.py` / `_ts_of_file/owner` | 从正文第一个日期和一级目录推时间/用户；最早观测当首次使用 | 材料中的日期污染；历史不全时 cohort 错 | 初版不做该留存图；文档明确补真实身份、事件、观察窗口 |
| 同文件 / cohort 聚合 | 最新观测周未必完整；W4 各 cohort 简单均值 | 未完成观察窗口和小 cohort 权重影响结果 | 后续用固定观察截止和成熟 cohort 分母，不先拼图 |
| `token_trend_attribution.py` / `_model_of` | 多模型会话只用第一个 runs 模型 | token 错分到一个模型 | 请求层模型信息优先；混合会话模型无法分摊则保持未知 |
| 同文件 / 增长解读 | 会话量与均值恒等分解被表述为归因，量增自动称健康 | 不能排除重试、质量下降、长上下文 | 分层描述 + 固定任务对比 + 原因抽查 |
| `case_miner.py` / `_case_id` | 案例 ID 由路径和 mtime 生成 | 移动/触碰文件就变成新案例，人工标签难继承 | 稳定 tenant/session ID + 内容 revision |
| 同文件 / 版本写出 | `latest/cases.jsonl` 仅包含本轮变化，后续读 latest 当整个库 | 老案例在新导出的训练/benchmark 候选中消失 | SQLite upsert，导出全量当前快照，增量与语料概念分开 |
| `training_data_builder.py` / `to_sft` | 把 good 完整对话直接写入，包括先前错误；dialog 丢工具消息 | 错误答案也可能被学习；正确答案失去必要观察 | 只导出人工重建的 prompt + 单一认可 target |
| 同文件 / `to_dpo_pairs` | 遍历任意后续用户消息，未检测是否纠正/接受 | 普通追问产生偏好；chosen/rejected 条件不一致 | 不实现自动 DPO；仅在同条件生成和独立比较后考虑 |
| 同文件 / `to_intent_samples` | 首问配 outcome/depth，名称称意图数据 | 标签是后验结果，不是任务类型 | 首轮可判断的 task intent；不使用后续轮次、good/bad |
| `bench_manager.py` / `cmd_build` | 首问和最后回答各截 4000 字；失败案例最后回答也当参考 | 条件/附件丢失、目标错、答案被截断 | 人工任务包，完整条件和已核对 target |
| 同文件 / `random.shuffle(pool)` | bad/review 拼在前面后又全池 shuffle | 实际没有保持“失败优先”采样策略 | 显式 representative/regression 标签，由你选首批题 |
| 同文件 / `latest_bench` | 字典序找最新 `vN` | v10 可能排在 v9 前 | 明确目录路径，冻结内容与代码 hash |
| 同文件 / `cmd_compare` | 空人工分用 `or 0`，双空会变成平局 | 未评题显示已评；缺失被抹掉 | 计划试次、已收结果、缺失与双方失败分列 |
| 同文件 / 准入建议 | 无依据固定“胜率 >55%” | 小题量、关键退步、缺失/平局都可能被忽略 | 输出证据，不自动决定；先核对关键退步和样本范围 |

## 2. 两个已实际复现的最小例子

```text
原始用户文本：可以帮我解释一下吗？
旧 session_features 的 completed_proxy：True
实际：只是一个问题，没有助手答复或用户验收。

原始对话：输出摘要 → 摘要A → 再加一个英文版本 → English summary B
旧 to_dpo_pairs：生成 1 对。
实际：普通追加需求；后答有新条件，不能直接证明原条件下偏好。
```

增量只写变化、vN 字典序、basename 聚合和空评分转零等问题由源码逻辑确认；没有拿用户真实语料模拟运行或宣称实测影响比例。

## 3. 哪些仍然值得保留

- 现有内网导出、lookup_emp 与平台 CSV 获取：这是最难替代的数据入口。
- `stats/runs/stages` 的结构化采集经验：保留事件，不把活动序列直接升级为业务意义。
- 小批次人工抽查、版本目录与错误线索：方向有用，补稳定身份和全量快照即可。
- 图表绘制代码：等指标口径确认后可复用呈现部分。旧象限图、完成率标题不沿用。

旧 `ref.md` 中无可核对引用的固定节省比例、经验阈值、平台能力宣传，以及员工数据处理的概括性法律结论，不作为本方案依据。训练数据用途依你们实际授权和制度明确；本包不提供通用法律结论。

## 4. 最短迁移路线

1. 用现有导出脚本构造统一 JSONL，不重新开发平台埋点系统。
2. 挑 10 条典型真实会话人工对照原文件：角色、时间、usage、真实文件/工具证据。
3. 并行保留旧报表一次，只对比同一窗口的字段与分母，解释为何数字变化；不把旧完成率与新复核可用率画在同一趋势线上。
4. 上线新的案例确认与报告批处理；先不启动自动训练。
5. 从同一案例卡整理少量固定题，做第一次当前模型基线/候选模型比较。
