# 任务与回传契约

任务输入：goal、sources（绝对路径与类型）、允许访问范围、max_claims（本示例默认 5）、验收要求。核对模式还需 candidate_claims；任务要求必须能从包内信息理解，不依赖上游完整会话。

图像分支要求运行时能把图像交给有视觉能力的模型；验证图像结论同样需要该能力。源文件和证据引用都必须可访问。

所有角色返回一个 JSON 对象，字段如下：

| 字段 | 类型与语义 |
| --- | --- |
| status | PASS：本次委托完成且适用检查通过；FAIL：执行后发现不合格；BLOCKED：输入／能力／证据缺失，无法完成 |
| summary | 简短结论 |
| claims | 提取者返回对象数组，每项含 id、text、source、locator；验证者返回空数组，不修改候选 |
| checked_ids | 验证者实际核对的候选 id 数组；提取者为空 |
| issues | 对象数组，每项含 claim_id（全局问题可为空字符串）、reason |
| missing_inputs | 需要补充的输入或能力字符串数组 |

文本 locator 使用行号或章节与记录编号；图片使用区域位置与可见标记。所有陈述限于来源实际支持的程度。提取者 PASS 只表示提取任务完成，不能替代验证者 PASS。

大材料不回传全文，只回传限定数量的结论与源引用。当前示例没有文件写入需求；真实任务要保存产物时，另行设计授权输出位置和 artifacts 字段。
