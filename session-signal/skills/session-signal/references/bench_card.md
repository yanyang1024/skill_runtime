# 评测题卡（bench card）与信号→评测循环

## 题卡字段（模板见 assets/bench_card.template.json）

| 字段 | 说明 |
|---|---|
| task_id / state | 缺目标、输入或可核对答案就保持 `draft` |
| origin | `real_replay` / `reconstructed` / `synthetic`，分列统计 |
| source_refs | 原始会话与事件引用，可回溯 |
| source_group | 人工核对的同源任务家族；同家族不分散到调参集和未见考试 |
| input_cutoff_ref | 真实任务开始点；后续修正/答案只进验收资料，不进题面 |
| initial_user_request | 原请求，保留用户约束，不改写美化 |
| acceptance_checks | 程序断言或人工参考；**不让 Judge 根据末尾感谢生成 pass** |
| benchmark_role | representative（按真实分布抽）/ challenge / regression，分别汇报 |
| intended_change | 本轮只改一个 Skill/Prompt/工具配置 |
| reviewer_verified | 人工核实后才 true |

## 走通第一次"信号→评测→小改动"循环

1. **补观测**：先补 edit 提取、保留 hash 来源、纠正 skill 加载口径——立即增加诊断覆盖。
2. **复核案例**：各取少量共同/差异切片的真实对话，复核 question 和错误前后变化；另取普通随机样本对照，不只挑极端案例。
3. **整理 3–5 道可复跑真实题**（填题卡），做**一个** Prompt/Skill 改动，旧/新同题对照。3–5 道只够走通流程，不支持全平台泛化收益。

### 三个候选小实验

| 小实验 | 固定什么 | 主要验收 | 辅助成本信号 |
|---|---|---|---|
| 路由后补充任务提示 | 同模型、原始用户约束、工具与输入 | 正确性不下降、没有篡改意图、必要澄清保留 | 总 token、耗时、重复追问 |
| 给特定工具补错误恢复规则 | 原始失败、原成功与新来源三组题 | 真正解决该错误；没有误重试或改变业务参数 | 所有尝试消耗、重复失败数 |
| 文件摘要/范围缓存 | 同文件版本/访问条件、允许回源 | 跨段细节、更新后内容与引用仍正确 | 实际减少的输入 token/读取字节 |

## 评测集维护

- 两个视角分列：按真实任务分布抽的代表集 + 按失败/边界问题选的挑战与回归集；困难题集通过率不当生产成功率。
- 真实回放、由真实案例重建、纯合成题分列比例；20/20 合成只能说明那批合成题的结果。
- 反复用来调提示的题变成已见题，不再算新能力证明；训练样本不吸收评测保留家族。
- 不同时改模型、路由、Skill、缓存再宣称单点收益。
- 历史日志没 loaded_harness 就保持观察性；手工记录实际运行副本与配置即可，不虚构版本哈希。
