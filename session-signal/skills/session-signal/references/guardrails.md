# 解读护栏：实测纠偏清单与汇报口径

写任何结论前对照这张表。左列是容易脱口而出但证据不足的说法，右列是证据支持的表述。

| 容易说错 | 更贴近证据的解释 | 正确做法 |
|---|---|---|
| I/O hash 交集为 0，字节哈希方法被证伪 | 写入参数与包装/截断后的读取输出不是同一种指纹；源文件集合也可能少有交集 | 不用 I/O hash 冒充 file_bytes；保留路径候选补召回 |
| 相同绝对路径就是同一资产 | 还必须同租户、同实际存储命名空间/挂载实例；同路径容器可能互不共享 | 路径角色可用规则猜；是否共享依赖实际部署约定 |
| 私有 workspace 候选 identical=0，证明都无关 | 只说明当前指纹未建立内容一致证据 | 不确认复用，也不声称已证明全部无关 |
| 去空白+casefold 能确认语义近等 | 缩进、标识符大小写、字符串和单位可能有语义 | 仅可做文本候选，不提升为金标准 |
| edit/bash 都能作为漏掉的文件操作补入 | edit 有明确目标与修改参数；bash 语法只提示可能副作用 | 先补 edit；bash 放复盘队列，不做完整 shell 解析器 |
| Skill 加载后无 invoke = 沉默供给 | 很多 Skill 通过加载指令即参与任务，本无独立 invoke | 按事件语义统计接触；供给分析需真实可见清单 + usage_event_semantics=invoke_required |
| event_id 绑定 N 次 Skill 失败 | 绑定证明那一次加载/调用报错，不证明后续工作流根因 | 加载错误、下游错误共现、验收失败分列 |
| 两部门指标相近，已排除人的使用影响 | 还没控制任务、工具、模型、阶段、时期及用户构成；相近也可能来自抵消 | 先看共同切片；结论保持观察性 |
| "自愈"约 30%，所以 70% 需人工介入 | 其余可能是窗口不完整、任务终止、转到子会话、错误非必需 | 输出后续成功/未见成功/观察不足；人工介入另找证据 |
| 33% 重读说明迭代，超 40% 表示复杂度增加 | 重读可来自修改后检查、截断、重复注入、正常检索 | 固定分母和版本/范围口径；不设没有基线的警戒线 |
| reasoning parts 可算 reasoning token 占比 | 片段数、字符数、计费 token 是不同单位 | 有实际 usage 字段再算 token，确认是否已含在 output 中 |
| assertion_failed=0 说明测试没有失败 | 全部断言元数据缺失时是没有观测到测试结论 | 同时展示 assertions_observed；0/0 显示 N/A |

## 契约审计与探针的纠偏（真实样例实测）

| 容易说错 | 更贴近证据的解释 | 正确做法 |
|---|---|---|
| 校验通过 = 产物没问题 | 校验器可能没有检查到目标（目标未登记/不存在时静默 pass） | 校验报告必须含 checked_count；0 个被检查对象不算成功 |
| 探针 5 中 3 = 工具误判率 60% | 探针是刻意挑选的故障模式，分母不是生产请求 | 探针只证明"该故障模式的检出能力"，报告逐案列期望与结果 |
| 回执不是裸 JSON = 业务失败 | 围栏/多余文字是格式适配问题，最小字段检查可能全部通过 | 格式偏离、业务效果、缺少执行证据分列；可恢复记 normalized=true |
| verifier 报 pass 就是独立验证过 | 没有子轨迹时不证明裁判实际执行/只读/覆盖正确 | verdict_claim 与执行证据分开；completed 不证明执行过程 |
| 三个共享材料的会话 = 三个独立成功样本 | 共享材料/任务的会话不是独立证据 | 同 source_group 标记，不重复计数泛化结论 |
| 删掉 SKILL.md 就能测 Skill 增量 | 同一方法可能重复写在 Agent/PROTOCOL/job prompt 里 | 先查方法是否多处重复；分开报"加载机制增量"和"方法指令增量" |
| 大纲与派生物字段不同 = 线上已损坏 | 派生物可能本就用于保留历史输入 | 暴露差异即可；是否重建取决于版本约定，拦截的是"把旧版当当前输入" |
| 会话里的命令有输出 = 命令成功 | Markdown 导出通常无真实退出码；管道尾部命令的退出码不属于校验器 | 历史保持 unknown；未来运行器直接保存实际退出码 |
| 静态文本写 edit:deny = 权限已生效 | 不同版本权限语义不同，字面严格不代表实际收口 | 用实际运行的分支做微型写入探针；不以模板字面下结论 |

## 范围纪律

- 每份报告带一行：dataset_id、时间窗、取样用户、组织层级、统计单位。不同导出范围的数字不拼成同一总体。
- "纯会话来源"说明采集成本低、可追溯，不自动说明推论可靠；磁盘快照有时间局限；LLM 判断有语义误差。按信号需要选择来源，不按来源预先排可信等级。
- 观测清单可按 first_seen_at/last_seen_at 维护，不能把 first_seen 冒充 published_at。

## 向上汇报的安全句式

> 在明确的采样范围内，我们观察到若干共性摩擦点，并完成了对应案例复核。某项改动在固定题集上的改善、退步及资源变化分别为……。业务采用与实际节省还需用户确认，当前不外推全平台收益。

- 部门比较三状态：部分部门切片集中 / 共同切片中均出现或相近 / 覆盖不足或混杂未解。不硬分"部门特定/部门无关"两类。
- 对业务用户问"结果后来是否用上、还需要改哪里、哪一步最费劲"，比请用户认可平台价值分数更有用。
- 失败尝试消耗记录为"失败相关消耗"，不直接改名浪费；不把输入 token 当真实货币成本。
- "高 I/O""长上下文占比高"可指导选长输入评测题，但不能直接证明反复重读、模型过度推理或有缓存收益。
