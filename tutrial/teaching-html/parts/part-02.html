第二部分

Agent、Harness 与 Skill 的核心定义

Agent 不是一个 Prompt，也不只是一个模型。本讲给出工程化定义，并拆解运行时的决策循环与 Skill 的本质。

2.1 Agent 的工程公式

Agent = Model
      + Harness（循环、上下文、工具中介）
      + State（会话、任务、文件、检查点）
      + Resources（规则、Skill、Tool、API、数据）
      + Policy（权限、沙箱、密钥和审计）
      + Feedback & Verification（观察、测试、验收）
🛠️ Harness：模型外部的运行脚手架，负责七件事
  1. 组织消息和上下文；
  2. 把工具以结构化 Schema 暴露给模型；
  3. 执行工具调用并把结果送回模型；
  4. 保存 Session、Message、Artifact 和事件；
  5. 管理重试、超时、压缩、取消与恢复；
  6. 在行动前执行权限检查；
  7. 判断继续循环、请求用户输入还是停止。

模型越能自主行动，Harness 对安全、状态、观察和验证的责任反而越重。

2.2 Agent 的运行时：带状态的决策循环

ReAct 把推理与行动交错：行动从环境得到观察，观察再影响后续决策。生产 Agent 通常采用 ReAct-like 循环，但不一定逐字暴露内部思维过程。

用户目标或待办任务
↓
装载会话状态与相关资源
↓
选择：回答 / 调用工具 / 委派子任务
↓
权限与安全检查
拒绝 → 请求确认或停止
↓ 允许
执行并获得真实观察
↓
有完成证据吗？
没有 → 回到装载状态
↓ 有
交付结果、产物与证据

循环各环节的工程含义

环节工程含义应保留的可观测信息
观察读取用户输入、文件、工具结果、环境状态输入来源、版本、时间、权限范围
决策选择下一步行动、更新计划简明计划、选择理由、风险提示（不要求完整思维链）
行动调用 Tool、API、脚本、Subagent工具名、参数摘要、调用身份、幂等键
反馈接收 stdout、API 响应、测试结果、用户回复结构化结果、错误类型、证据与 Artifact
状态更新写入 Session、Task、文件或检查点状态迁移、差异、可恢复位置
停止完成、阻塞、失败或超预算停止原因、未完成项、下一步建议

2.3 Agent 必须知道何时停止：七类停止条件

停止条件含义
完成停止验收断言通过，并产生了约定的 Artifact
需要输入缺少会显著改变结果的用户选择
权限阻塞动作被拒绝，且没有同等安全的替代路径
失败停止同一错误重复出现，继续尝试没有新增信息
风险停止即将执行不可逆、越权或高影响操作
预算停止达到时间、Token、调用次数或费用上限
外部停止用户取消、服务超时或依赖系统不可用
⚠️ 注意

"还可以继续想"不是继续循环的充分理由。每次循环都应回答：这一步能否获得新信息、产生新证据或推进状态？

2.4 Skill 的定义：可按需加载的操作知识包

Agent Skills 规范把 Skill 定义为以 SKILL.md 为核心、可附带脚本、参考资料和资产的可复用知识包：

my-skill/
├── SKILL.md              # 触发边界、流程、判断与资源路由
├── scripts/              # 可重复、确定性的执行逻辑
├── references/           # 需要时读取的领域或接口资料
├── assets/               # 模板、样例、静态资源
└── evals/                # 触发与输出质量测试
✅ 一个合格的 Skill 回答的七个问题
  1. 什么用户意图应该触发它？
  2. 哪些相邻场景不应该触发它？
  3. 开始前需要检查什么？
  4. 以什么顺序使用哪些资源？
  5. 哪些判断由模型做，哪些必须交给程序？
  6. 失败时如何分类、重试、降级或停止？
  7. 最终交付什么，如何验证？

Skill 不是什么

容易混淆的对象与 Skill 的区别
PromptPrompt 是一次性指令；Skill 是带触发边界、流程和配套资源的可复用包
Tool / APITool 提供"能做什么"；Skill 说明"何时做、按什么方法做、怎样验收"
WorkflowWorkflow 固化控制流；Skill 给模型一套可适应上下文的操作方法
AgentAgent 是运行主体；Skill 是 Agent 可加载的程序性知识
SubagentSubagent 有独立上下文与任务生命周期；Skill 默认注入当前 Agent 上下文
RAG 知识库RAG 提供事实材料；Skill 偏程序性知识、边界和资源导航

按需加载：渐进式披露三级

① 发现
只暴露 name + description
→
② 激活
命中后读取完整 SKILL.md
→
③ 执行
需要时才读 reference / 脚本 / 资产

这使 Agent 可以"知道有哪些能力"，又不必为每个 Skill 预先支付完整上下文成本。
