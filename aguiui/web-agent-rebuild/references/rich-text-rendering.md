# 流式文本与富文本渲染

## 按已有栈和任务选择

| 场景 | 优先考虑 | 选择依据 |
| --- | --- | --- |
| Flask/Jinja 或原生 HTML/JS；简单解释 | 转义纯文本；需要时用受控 Markdown 渲染器 | 复用资产与最少依赖，不为视觉替换框架 |
| 已有 Astryx React UI | 核对所装 Markdown 组件与主题能力 | 主题/组件一致性；不能仅凭教程宣称零额外依赖 |
| 已有 React，长 Markdown、代码/数学等需求较强 | 评估 Streamdown 与所需插件 | 未闭合语法、性能、样式链和安全配置的实测 |
| 复杂跨组件应用 | 业务 Response/Message 适配层包住选定渲染器 | 在原始消息、来源和业务对象不变时可替换显示方案 |

候选字段、工具状态、澄清卡和产物版本走 Schema 与业务控件；Markdown 承担解释正文。A 的字段只能在完整、校验通过的候选产生后供采纳；B 的正文可渐进阅读，证据与动作仍有独立对象。不要从尚未结束的 Markdown 或工具参数里提取并提交业务操作。

## 把原文、展示和业务保存分开

保留服务端/适配层得到的原始 Markdown 与消息标识；渲染器的临时补全、修剪和排水仅影响显示。传输在收、模型已结束、动画尚在显示、任务已完成可以同时有不同状态；关闭动画不能触发业务成功。

选库时比较不完整粗体、代码围栏、链接、表格与公式的行为。可以暂缓复杂块、显示占位或用受控语法补全；错误时回退为安全原文，保留已接收内容。完成后用规范原文重新确认全文；停止/截断明确标为部分内容。导出和保存说明是已验证原文还是部分草稿，不导出渲染器猜测补出的结束符。

块级缓存是优化策略而非业务承诺。消息/块使用稳定 key，避免逐 token 重排全部历史；新 run、全文替换、引用映射或配置变化时正确失效。后到的引用定义可能改变前文，不能把所有旧块永久冻结。分批提交 UI 更新，复杂数学/高亮可延后；不把全文每次 innerHTML 替换作为流式默认方案。

CJK 行断与字素簇完整是不同问题，插件并非替代浏览器测试。检查中文标点、组合字符、emoji、长代码与宽表；保留回看位置和复制选择，减少动画偏好下仍可使用。性能看目标长度下的增量更新时间、主线程卡顿与内存，不以安装了 memo 或某个插件当性能已达标。

## 渲染不可信内容的边界

模型、用户、RAG、工具结果都按不可信内容处理。核对所用版本默认 HTML 与 sanitizer 的实际行为；不能假设所有 Markdown 组件默认禁用 HTML，也不能认为模型公式比用户输入可信。

- 原始 HTML 默认关闭，或经明确的标签/属性白名单净化。自定义 components、rehype 插件链或内联 HTML 会改变边界；保留/重新落实净化，而不是加一个插件后移除默认防护。
- 链接协议与图片来源分别限制。外部图片即使无脚本也可在自动加载时发送请求；按应用允许的来源关闭、代理或显式加载。净化不等于资源访问控制。自定义链接仍需检查协议和应用路由。
- 数学渲染按可信配置执行，限制扩展与资源消耗，异常时显示安全文本；若插入 HTML，只使用经过限定配置的渲染器输出及必要净化，不拼接模型 HTML。
- Mermaid 只在需要时开启，使用安全配置与大小/超时边界；不允许模型控制任意脚本、链接回调或渲染设置。代码高亮和复制是展示动作，不执行代码。
- 引用标号映射到已验证、当前身份可访问的来源对象；模型生成一个 [1] 不能自动成为已核实引用。异步来源更新要使相关显示正确失效。

## 库接入的核对点

Streamdown 官方当前提供未闭合 Markdown 处理及可选 code/math/cjk/mermaid 插件；按实际需求加载。核对锁定版本的 React/构建要求、组件 props 与插件接口。Tailwind 的扫描配置按 v3/v4 和包实际路径区分，主题/动画 CSS、公式样式另行核对；教程中的 `styles.css` 不能当所有样式已配好的证明。以生产构建结果验证，不能只看开发页。

安全默认值尤其要查：官方文档说明存在净化与 URL/资源限制层，但默认允许的外部来源较宽，且支持经处理的 HTML。选择适合本应用的策略并验证；自定义插件链后不能沿用“库默认安全”的结论。

Astryx 的增量解析、尾部修剪、引用与字素处理在用户文档中有源码索引；当前提供的源码切片没有完整 Markdown 模块，未把这些内部实现全部独立验证。实现时读取所安装源码/文档确认组件参数、数学/高亮依赖、流式完成与全文替换的行为；缺证据时降级实现或标明待验证。Astryx 布局与 Streamdown 正文可以组合，但需要实际依赖、主题与行为兼容验证。
