# LLM 流与应用事件

## 先选择是否流式

短小字段建议或确定性查询可用普通 JSON；需要提前阅读长文本时再用流式。已有任务事件、轮询或 SDK 时优先适配。不要为了渲染器增加一套通用消息总线。

明确链路：供应商流 → 服务端协议适配 → 应用事件/任务状态 → 前端状态归并 → 文本或结构化组件。SSE 只是传输格式；不要直接把供应商的 delta 当应用完成状态。流式与非流式应复用业务规则、权限和结果口径。

## 传输与身份

| 情况 | 可选做法 | 需要说明 |
| --- | --- | --- |
| 一次提交并读取结果，需 POST/自定义头 | fetch + ReadableStream + 成熟 SSE 解析器 | 请求体、认证、HTTP 错误、取消与资源释放 |
| 已创建任务，订阅只读事件 | 原生 EventSource 或现有 SDK | GET、Cookie/跨域策略、重连；原生 API 不提供任意头/POST |
| 简单短任务 | JSON 或已有轮询 | 不因 UI 风格强加 SSE |

Key 留在服务端；浏览器使用应用身份，不把访问令牌放进订阅 URL。先校验响应状态、body 与 Content-Type，再进入解析；不要把 401/500 JSON 正文当流。跨域只按既有认证配置，凭据请求不配通配来源。

## 事件边界与解码

使用增量 UTF-8 解码，保留跨网络块残片；结束时处理解码器尾部。网络 read 的块、模型 token、SSE 事件互不等同。解析器应处理 LF/CRLF/CR、空行派发、多行 data 拼接、可省略的冒号后空格、注释心跳及约定使用的 event/id/retry。优先成熟实现，不复制只 split('\n\n')、只取首个 data 行的演示。

读取 event 类型后再分派和校验数据；按协议处理未知扩展事件。不要以 payload 是否等于 `{}` 判断 done；不是每个 data 都是 JSON，也不是每个供应商都用同一个结束标记。JSON 解析后中文转义与字面中文等价；显示出 `\uXXXX` 时检查是否重复序列化或漏解析。

未以空行结束的 SSE 帧在 EOF 不派发。已收到部分正文但没有约定终态时显示 interrupted/待核对，不把 EOF 计为 succeeded。非 JSON、类型错误、意外事件和残缺帧应有可观察错误及恢复边界，不悄悄吞掉。

## 先约定最小应用事件

按现有契约保留所需标识：task/run、message/item、事件 ID 或序号；重连时才引入所需重放位置。正文增量、正文快照替换、工具状态、来源、产物版本与任务终态分别表达；示例事件名只是应用选择，不是 OpenAI 等供应商标准。

- 文本 delta 追加到指定消息；snapshot 替换并让渲染器重置增量状态。以稳定 ID 定位，避免数组索引造成消息错位。
- 工具参数片段先累积，完成并通过 Schema、权限和范围检查后才能执行。工具状态/证据/卡片不从 Markdown 正则反推，也不公开内部推理或完整敏感日志。
- 工具结束、模型响应结束、任务成功、等待输入、产物可采纳和已经保存是不同状态。结束条件由任务协调层定义，不能靠显示动画推断。
- 发送新请求前终止旧读取；每个回调和 finally 还要检查本地请求代次/run_id。旧流迟到不能追加到新消息，也不能把新请求的 loading 清掉。
- 组件卸载释放 reader/连接/定时器，错误后保留输入与已确认内容。停止读取不等于服务端任务已停止，更不等于副作用撤销；按 runtime 的取消契约处理。

## 断线、重放与运行方式

只在服务端保存事件或快照、检查当前用户范围并支持游标时承诺续传；事件 ID 本身不会创造可恢复历史。重放的 ID 去重、有序归并；出现缺口时按契约重取快照或显示中断。不要自动重发可能写入的任务创建 POST。原生 EventSource 的 error 可能是连接问题，业务失败用独立状态表达；终态后按需关闭订阅。

FastAPI 的异步流中避免阻塞 I/O；检测断开并在 finally 清理上游请求。Flask 可用同步生成器，显式传入身份/参数；确需请求上下文时用其流式上下文机制，不能把每个 Flask 流写成长寿命 asyncio 任务。长任务沿用已有 worker 与任务存储。断开后取消还是继续后台执行应由业务决定。

响应使用 text/event-stream，按部署控制缓存、代理缓冲、压缩和超时；心跳只表示连接存活。X-Accel-Buffering 等仅对相应代理生效，不是通用修复。用真实部署链路观察首事件和增量抵达；异常发生在响应头发送后时，通过约定事件/连接中断表达，不能再假装更改 HTTP 状态码。对事件大小、累计消息、队列和处理时间设置合理边界。
