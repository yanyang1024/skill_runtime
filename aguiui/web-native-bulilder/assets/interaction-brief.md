# 应用交互决策

填写当前任务需要的内容，删除不适用部分。将它用作用户应用的简短设计记录，不把填完模板作为额外审批门槛。

- 用户与目标：
- 当前任务更接近 A（已知条件）、B（探索）还是两者组合；何时切换：
- A 的候选值、来源、个性化范围、人工修改与业务反馈（如适用）：
- B 中可以复用的路径证据、沉淀为 A 的条件与多场景路由（如适用）：
- 输入、上下文与完成标准：
- 主要对象/产物：
- 已有能力与真实可达状态：
- 推理端点协议与可用能力（不含 Key）：
- Flask/FastAPI 选择及原因：
- 初始页面、工作中页面和结果页面：
- 上下文对象、输入/提交边界、执行摘要、产物视图（按需）；各组件拥有的状态和业务责任：
- 流式回看、中文输入、焦点和窄嵌入容器的代表行为（按需）：
- 人、模型、确定性代码各自负责什么：
- 需要澄清或业务确认的条件：
- 失败、缺配置、空结果、取消、刷新后的行为：
- 共享编辑/版本/副作用边界（如适用）：
- 一个主任务和一个重要反例：
- 已验证的行为与需要实测的价值判断：
