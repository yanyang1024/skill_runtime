# 选择交互模式与保护异步编辑

## A 与 B 的关系

**A：条件明确的任务。** 从业务规则、当前记录、授权范围和用户历史中构建候选表单；把人的注意力放在验证、改写和例外处理。可以建议初始值，也可以解释原值为何如此、提示过期或异常、给出多个候选及其后果。若数据不足，显示缺口和来源，不用似是而非的“个性化”覆盖人工判断。高影响动作仍由当前用户确认实际提交内容。

**B：探索中的任务。** 从目标出发，允许试探、澄清、比较和回退，让探索过程留下证据、限制条件、有效步骤与失败例外。价值既在本次结论，也在逐渐找到可复用路径。路径在不同任务中反复成立、输入输出和边界说得清、异常可恢复时，才考虑把一段 B 设计成 A；一例成功只算候选。已经沉淀的 A 遇到新例外时，可由 B 继续探索并修订路径。

当 A 增加到难以选择，B 还可以作为统一入口：识别意图和对象，提出少量可辨认的任务卡，必要时澄清，路由到对应的 A 并传入带来源的预填条件。不要让统一聊天入口遮蔽当前流程，也不要让低把握分类自动触发有影响的动作。这是互相转换的两种交互形态，不是应用成熟度的固定阶梯。

数据库与身份上下文只在用户已授权的对象范围内查询；区分个人偏好、组织规则和本次记录，并显示建议依据与更新日期。用户修正可成为下一轮推荐的反馈，但要核对是否代表稳定偏好；记录并比较误推荐与纠错成本，而不是只数采纳率。

## 从用户任务选择模式

| 任务特征 | 首选入口/主体 | 模型职责 | 必要控制 |
| --- | --- | --- | --- |
| 字段明确、重复查询 | 候选表单 + 可选语言入口 | 生成/解释/监测字段，比较候选 | 来源、差异、字段校验、提交边界 |
| 固定少量步骤 | 结构化输入 + 结果面板 | 提取、分类或补充说明 | 输入与结果绑定、错误重试 |
| 目标模糊、多工具调查 | 目标 + 探索路径 + 证据 | 选择工具、澄清、组织证据 | 预算、实际状态、可继续的失败 |
| 持续编辑文档/分析 | 产物为主、对话为辅 | 局部修订或候选产物 | 草稿与当前版本、人工编辑保护 |
| 业务写入/发布 | 对象与变更提案 | 准备参数与解释影响 | 服务端权限、版本/幂等、按影响确认 |

按场景组合，不把右侧聊天框当成通用答案。先说明用户原本要完成什么，再判断语言入口省了哪一步、增加了多少核对成本。不要将每项增强都升级为长期 Agent 任务。

## 页面结构与状态

- 让用户看清“当前对象/范围”“已经完成什么”“现在需要我做什么”。
- 一次性结果绑定提交时的输入；用户修改输入后标记结果过期，而不是悄悄改标题伪装成新结果。
- 澄清卡只询问影响正确性或执行的条件，显示默认值的来源。已确认的条件成为后端约束，模型改动受限值时返回结构化错误或再次澄清。
- 长任务显示实际阶段和可观察事件，不展示猜测进度百分比或内部思维链；将来源、统计、候选与模型解读区分。
- 使用有限的类型化控件渲染模型请求，例如选项、日期、记录选择与候选差异；不执行模型给出的任意 HTML/JS。
- 设计加载、空数据、部分结果、缺配置、超时、等待输入、取消与完成态；明确错误后可重试什么。
- 为输入提供标签，保留键盘焦点与未提交内容；宽表在自己的容器滚动。窄屏任务选择器须 `min-width:0; max-width:100%`，避免长任务名撑破页面。

## 三种不同的版本

1. **表单修订号**：请求建议时捕获 `form_revision`；返回/应用时不一致则标记过期，不覆盖新字段。字段是否变化由客户端明确记录，不能靠模型猜。
2. **产物持久版本**：运行开始时捕获 `base_version`；采纳或保存用服务端原子条件写入。条件不成立返回冲突，禁止先读后无条件写入。新基准要么明确重做，要么使用经验证的局部合并。
3. **编辑器本地修订**：保存发出时捕获文本/修订号。返回时只清除已经提交的改动；若用户继续输入，保留新内容为待保存，并把基准更新到刚成功保存的版本。

示意（按工程调整，不直接粘成整套状态系统）：

```text
submitted = editor.text
saved = await save(submitted, expected_version)
if editor.text == submitted:
    dirty = false
else:
    dirty = true                  # 保留请求期间的新输入
editor.base_version = saved.version
```

轮询也不能覆盖 dirty editor；旧任务/旧请求的响应须按 task_id、run_id 或请求序号丢弃。不能把“有一个 v1 标签”误当成实现了冲突保护。

## 保持判断开放

字段建议、确定性计算、异步冲突保护能解决具体问题；A 是否减轻填写与核对负担、B 是否发现可复用路径、统一路由是否让用户更快找到正确场景，都需要真实任务比较。记录完整完成时间、修改/纠错时间、错路由及失败恢复成本，不凭点击更少或页面更像聊天得出收益结论。
