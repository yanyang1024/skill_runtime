# 连续动画编排参考

## 分镜模型

把动画写成“状态 → 动作 → 状态”，而不是一串随机效果。常用五拍结构：

1. **建立**：背景、网格或主容器先出现，给观众空间参照。
2. **引入**：标题或核心图形进入，明确视觉主角。
3. **展开**：辅助信息按阅读顺序出现，解释主体。
4. **强调**：只让关键数字、词语或路径获得一次明显运动。
5. **收束**：停留足够时间供阅读，再淡出或停在完整终态。

每拍只设一个主要注意点。元素数量少时，用位置、尺度和留白形成层次，不靠增加粒子填满画面。

## 时间与节奏

- 微反馈：120–220ms。
- 小型入场：240–450ms。
- 主要场景转换：500–900ms。
- 同一组元素的交错间隔：40–90ms。
- 标题与正文之间留出短暂停顿；最终阅读停留通常不少于 1.5 秒。

优先使用少数经过设计的 easing。入场可用减速曲线，离场可用加速曲线；位置连续跟随时使用平滑曲线。避免所有元素共用同一个机械匀速。

## 构图与运动语义

- 向上进入适合“出现、提升、发布”，横向移动适合流程与前后关系。
- 放大适合聚焦，不适合每次普通入场。
- SVG 路径绘制适合解释连接、路线和生长；不要让无关装饰线都绘制一遍。
- 数据动画应先显示坐标或单位，再变化图形，终值停留期间不得仍在跳动。
- 循环背景应比主要内容更慢、更低对比；用户未要求时不添加无限循环。

## 单时钟实现

连续动画优先采用一个 WAAPI 时间轴或一个 `requestAnimationFrame` 时钟。所有视觉状态由同一个时间值计算。定位顺序固定为：暂停时钟、取消待处理帧、设置目标时间、同步渲染一次。

若使用 WAAPI，集中保存每个 Animation 对象，并在 seek 时同步更新 `currentTime`。不要分别调用一组 Animation 的 `play()` 来从中间位置续播；浏览器可能让部分效果重新起播。更稳妥的方式是让一个 `requestAnimationFrame` 主时钟逐帧写入所有对象的 `currentTime`。若同一元素有多个效果，按属性分工：一个动画负责位移，另一个负责透明度；不要让两个动画同时写 `transform`。

推荐保留统一接口：

```js
window.motion = {
  play() {},
  pause() {},
  seek(seconds) {}
};
```

`?t=1.8` 应在初始化完成后冻结于 1.8 秒。不要用 `animations: disabled` 之类会快进动画的方式代替冻结。

## 性能与可访问性

- 高频动画只写 `transform`、`opacity`；SVG 可动画化路径偏移，但控制路径数量。
- 集中读取布局，再集中写入样式，避免读写交错。
- 仅对少量确实运动的元素短期使用 `will-change`，结束后移除。
- Canvas 按 `devicePixelRatio` 设置清晰度，同时限制高分屏的最大像素比；页面隐藏时暂停。
- `prefers-reduced-motion: reduce` 下直接呈现完整终态，保留播放按钮供用户主动选择。
- 不使用每秒超过 3 次的闪烁，不让快速缩放占据整个视野。

## 最小验证

检查开始、中间、结束三个时间点；再检查 seek 后是否稳定。逐个确认标题无裁切、终值准确、无布局跳动。断网打开并查看网络请求应为空；切换到减少动态效果后，全部内容仍应可见。
