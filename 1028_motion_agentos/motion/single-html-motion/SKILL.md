# Single HTML Motion

生成一个可直接双击打开的 `.html` 文件。把内容与动效一起设计，而不是先完成静态页面再随意补动画。

## 严守轻量边界

- 将所有 CSS、JavaScript、SVG 和必要数据内联；使用系统字体。
- 默认不发起网络请求，不引用 CDN、在线字体、第三方库或外部图片。
- 不引入 npm、构建步骤、React、GSAP、Three.js、Playwright、Puppeteer、FFmpeg 或视频导出。
- 不自动添加录屏、截图、部署、PDF 导出或云服务能力。
- 若用户明确要求 `.pptx`，说明本 Skill 的产物是 HTML 幻灯片，并改用适合 PPTX 的流程。

## 选择模板

- 连续动画、动态海报、产品开场、数据叙事：复制 `assets/motion-starter.html` 后修改。
- 键盘翻页的演讲、课程、产品汇报：复制 `assets/deck-starter.html` 后修改。
- 简单任务可直接编写，但保留模板的可访问性、时间控制和离线约束。
- 需要编排连续动画时阅读 `references/motion-patterns.md`；需要设计幻灯片时阅读 `references/deck-patterns.md`。只读取当前任务需要的参考文件。

## 工作流程

1. **确定单一表达目标**：用一句话说明观众看完应理解或感受到什么。删除不能服务该目标的装饰。
2. **先写分镜**：连续动画列出 3–7 个节拍；幻灯片按“一页一个观点”组织。先保证静态关键帧可读。
3. **建立视觉系统**：定义少量 CSS 变量，包括背景、前景、强调色、字号层级和间距。保持文字对比度与移动端可读性。
4. **实现静态结构**：用语义化 HTML；图形优先使用 CSS 或内联 SVG。只有大量粒子、自由绘制或像素操作才使用 Canvas。
5. **添加最小动效**：优先动画化 `transform` 和 `opacity`；避免逐帧修改布局属性。让运动方向与信息关系一致。
6. **加入控制与适配**：连续动画提供播放/暂停和定位；幻灯片提供键盘、按钮、页码和 hash 定位。适配 `prefers-reduced-motion`。
7. **验证后交付**：直接以 `file://` 打开检查；确认无外部请求、无控制台错误、无横向溢出，并测试窄屏、键盘和减少动态效果模式。

## 连续动画要求

- 使用一个明确的时钟或时间轴，不用互相独立的 `setTimeout` 链拼接关键流程。
- 将时间轴设计为可暂停、可定位；保留 `window.motion.play()`、`pause()`、`seek(seconds)` 控制接口。
- 支持 `?t=秒数` 冻结在指定时间点，便于检查关键帧。定位前先暂停，避免实时帧覆盖目标状态。
- 多个效果作用于同一元素时，统一编排属性，避免相互覆盖的 `fill` 或重复动画。
- 默认时长控制在 4–12 秒；除非用户要求，不自动无限循环。

## 动画幻灯片要求

- 同一时刻只展示一张主幻灯片；切页是离散状态变化，不把整套 deck 绑成不可干预的自动视频。
- 支持方向键、空格、Home、End 和可见按钮；点击控件不得依赖网络。
- 使用 `#n` 或模板现有 hash 机制保存页码，使刷新后仍停留在当前页。
- 页内元素采用少量交错入场；不要让每页所有文字都飞入、旋转或弹跳。
- 保留静态打印样式，但不要把“可打印”宣称为完整 PPTX 或 PDF 导出工作流。

## 验收清单

- 单个 HTML 包含全部必要资源，断网可运行。
- 首屏无动画时也能理解；减少动态效果时内容不消失。
- 连续动画可播放、暂停、 seek；指定 `?t=` 后画面稳定。
- 幻灯片翻页、页码、hash、首尾边界和按钮状态正确。
- 连续动画无每秒超过 3 次的闪烁；幻灯片无强制自动播放。
- 360px 窄屏无横向滚动，正文和控件保持可读、可点。
