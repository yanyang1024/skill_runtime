# Skill 组合与配套创建

需要补充、修改配套 skill 或引入其他 skill 时读取。

## 两个 creator 的分工

| 能力 | 负责 | 交付 |
| --- | --- | --- |
| agents-creator | agent 边界、单／多形态、能力导航、权限与跨能力交接 | agent 文档、依赖关系与整体检查 |
| skill-creator | 可复用方法、按需参考、必要脚本、skill 触发描述 | skill 目录、使用契约与验证证据 |

加载由当前 agent 通过 skill 工具执行；SKILL.md 不能自己调用工具，也不会自动授予权限。创建助手的 skill 白名单必须允许二者。`task: deny` 不妨碍在同一主体内加载不同 skill。

## 选择加载范围

| 本次请求 | 加载方式 | 不需要做的工作 |
| --- | --- | --- |
| 只创建 agent，已有合适 skill | agents-creator 读取现有接口并装配 | 不重建现有方法 |
| agent 和配套 skill 都缺少 | agents-creator 确定边界，再加载 skill-creator，完成后续接装配 | 不启动额外 creator agent |
| 只调整 skill 内部方法 | skill-creator 处理授权修改 | 接口未变时不重写 agent |
| 修改公开接口或必需权限 | 核对受影响的 agent 导航与配置 | 不改无关调用方 |

完整文件与交接示例见 [联合创建](../examples/agent-with-skill.md)，只在需要成例时读取。

## 何时复用，何时创建

1. 检查已可发现的 skill：名称和 description 匹配后，再看必要输入、输出和工具要求。
2. 现有 skill 可以满足需求时直接复用；小且稳定的指令可以内联。
3. 只有缺少可复用方法时才创建 skill；缺 API、模型或数据不是 skill 文档能补足的。
4. 修改配套方法已在当前任务授权范围内时直接执行；超出范围时明确缺口，不擅自改无关共享 skill。仅审查不转为实施。

## 交接最小信息

加载 skill-creator 前，保留以下内容即可，不要求建立新协议或文件：

- 方法目标与触发场景；建议名称和已核实的同名／同类 skill。
- 输入、输出、允许访问的资源和实际工具条件。
- 目标 skill 目录、允许修改的文件及不得修改的外部资源。
- 成功标准和供验证的原始样例；拟供哪些 agent 使用。

skill-creator 完成后提供实际名称、路径、触发描述、输入输出、必需工具／权限、检查证据和未完成项。agents-creator 再核对导航名称与白名单、路径、能力契约，继续装配。不得仅因为“创建过文件”就把缺工具的能力标为可用。

## 避免相互调用循环

- agents-creator 负责整体设计；skill-creator 处理当前明确的方法缺口，不反向自动加载 agents-creator。
- 已加载的 skill 继续使用，不为每一步重复加载；返回时续接原任务，保留已有决策。
- 同一缺口没有新输入或可执行改动时停止重试并报告阻塞，不靠反复切换 skill 推进。

## 可选能力

本包只将两个 creator 作为必需能力，不默认引入更多依赖。

| 可选 skill | 适用条件 | 本包处理 |
| --- | --- | --- |
| align-requirements | 业务目标、验收或责任边界冲突，简短澄清无法解决 | 仅在目标环境实际可用且权限允许时加载；未随包分发 |
| modernize-api-for-agents | 已有真实 API 文档与代码，且用户要求实施接口改造 | 作为单独获授权的任务使用；不能因创建 agent 顺带改 API，未随包分发 |

没有这些可选 skill 时，继续已可完成的设计并记录必要缺口；不要把它们加入必需依赖或虚构调用成功。需要接入时在实际发现后追加精确白名单，不开放所有 skill。
