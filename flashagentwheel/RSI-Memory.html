PART 1 · RSI 背景与全景

RSI 的起源：一个六十年的设想

从理论设想到工程现实——写代码与跑实验的自动化，让这条推论比过去近了很多
RSI = Recursive Self-Improvement，递归自我改进——改进后的系统，能够继续参与正向改进自己。问题由此变成：对今天复杂的 Agent 系统，这条回路应该怎么搭？

PART 1 · 定义校准

改了自己 ≠ 越改越会改

「RSI」被用得很滥——把声明拆成四级台阶，每升一级都要单独交证据
层次可以声称什么额外需要的证据
L-A 自我修改系统能产生并采用自身改动修改与采用记录
L-B 系统改进新系统能更好完成目标任务可比较预算下的新旧对照 + 独立任务结果
L-C 改进能力提升新系统更有效地产生后续改进新旧改进器在可比较搜索问题上的对照
L-D 持续递归增益改进能力在多轮中持续贡献收益多轮独立重复 + 阻断递归反馈的对照

PART 1 · 各家做法

做法全景：按「迭代什么」分三条路线

迭代产物 · 迭代代码（Harness）· 迭代模型——改什么，决定了进化的持久性与成本
路线一 · 迭代产物

Artifacts——「打草稿」

  • Self-Refine / Reflexion：任务内自我纠错、多改几版
  • Test-time Compute Scaling：用更多推理换更好结果

任务结束经验即丢弃，下次不会更快。已成熟，但不是真进化——Agent 本身没有任何改变。

路线二 · 迭代代码 / Harness ★ 主战场
  • ADAS（2024）：meta-agent 自动设计 agent——但 meta/target 分离，不算自改进
  • SICA（2025）：首个完全自指的编码 Agent，自己编辑自己的代码库，SWE-bench 17%→53%
  • DGM（2025）：自我修改组织成进化树，扩展高分节点
  • HGM（2025.10）：发现「当前高分≠后代高产」的元生产力错配，用谱系聚合表现 CMP 指导搜索，更少算力达人类工程师水平
  • RRSI（2026.9）：Harness 进化的正则化——防过拟合，收益可迁移，token 省 30%
路线三 · 迭代模型

Model——写入权重

  • STaR / Agent RL：用自身产出的正确样本微调
  • 自对弈微调：经验直接写入参数

持久性最强，但成本最高、风险最大，目前仍在研究阶段，距生产落地尚远。

工程侧配套：Anthropic Dreaming（空闲时异步审阅轨迹发现系统性模式）· EvoAgentX 等开源框架 · 腾讯「四齿飞轮」工程闭环（评测→记忆→落地→控制）。三层并不割裂：Harness 积累的经验可变成训练数据反哺 Model，更强的 Model 又能产出更好的 Artifacts。

PART 1 · 时代演进

Agent 时代，RSI 的主战场是 Harness

Agent = 冻结的骨干模型 + Harness——同一个模型表现如何，很大程度由 Harness 决定

为什么 Harness 是主战场：即时、可控

改完 Skill / Prompt 立刻生效，不需要重训模型；改错了一键回滚，不会造成不可逆的损害。实测：通过 Harness 层进化，迭代次数减少 70%、Token 消耗降低 80%+——这些收益全部来自「改配套系统」，一个模型参数都没动。

对我们意味着什么

智多星上的 Skill 与 Agent 正是 Harness 层资产——方法论上已被各家验证是投入产出比最高的进化着力点。我们不需要碰模型权重，就能让平台能力持续增长。

PART 1 · RSI × MEMORY

Memory 是点，RSI 是线

记忆不是一个静态的「大脑」——它是版本迭代的过程，不断产生点状沉淀；RSI 负责把点连成线

点：只记录「发生过什么」

每一次记忆沉淀都是一枚带版本、带时间戳、带来源的点。孤立地看价值有限——只有点没有线，记忆退化为日志。

线：回答「下一步往哪走」

RSI 从点列中读出模式、归因与方向，外推下一轮迭代信号——只有线没有点，推演沦为空想。点成线，线成势。

PART 2 · 星轮实践

星轮：智多星的资产治理与迭代平台

智多星是生产系统，星轮是它的「进化引擎」——Skill 和 Agent 是平台的核心资产
资产治理

捕捉信号——每天的使用数据与更新事件；积累记忆——by 用户、by 资产的点状沉淀。这是「造点」的过程。

资产迭代

基于快照与记忆做 RSI 式优化——生成 baseline、对照比较、产出优化建议。这是「连线」的过程。

PART 2 · 资产快照与 BASELINE

快照即「点」，快照序列天然成「线」

每一次快照是一枚带时间戳的点；点列连成资产的演化轨迹——RSI 的推演素材由此而来

快照内容

全量 Skill / Agent 的定义、配置、版本 + 当周期调用统计与使用分布——资产的完整切面。

by 用户维度

同一资产按「谁调用、谁创建、谁负责」切分视图——适用性与问题可以归因到人、到场景。

可回滚 · 可溯源

任何版本可还原；任何一次优化都能追到它基于哪个快照、由什么信号触发。

PART 2 · 记忆做法（当前重点建设）

从用户会话中挖「高频模式」，形成点状记忆

两大来源：会话模式挖掘（by 用户）× 资产配置沉淀（三条路径）
来源一 · 会话模式挖掘（by 用户）

拉取每个用户的会话记录，挖掘高频模式：

  • 用户偏好——表达习惯、格式要求、详细程度、交互方式
  • 产物形成偏好——用户最终接受的产出长什么样：报告结构、代码风格、图表口味
  • Skill 使用偏好——什么场景调用什么 Skill、调用顺序、组合方式
来源二 · 资产配置沉淀（三条路径）

围绕「用户 × 资产」的关系做配置级记忆：

  • 用户调用的 Skill / Agent → 使用画像：高频组合、成功场景
  • 用户创建的 Skill / Agent → 创作画像：风格、惯用结构、质量基线
  • 用户负责的 Skill / Agent → 治理画像：维护节奏、问题热点、下游依赖
这些记忆都是「点」——版本化、带时间戳、带来源（哪个用户、哪段会话、何时挖掘）。点会持续积累，等待 RSI 把它们连成线。

PART 2 · 从点到线

星轮如何把记忆产出为迭代信号

四种「连线」方式，对应 RSI 的归因、信用分配、方向与推演
①

点的聚集 → 问题线

多个用户在同一 Skill 上反复卡住（调用失败、重试、放弃）——点的聚集说明这是系统性短板而非偶发个例，优先进入优化队列。

②

点的对照 → 涨跌线

资产更新前后的快照 diff + 调用统计变化——回答这次更新到底带来了什么：哪些能力涨了、哪些跌了、影响哪些用户。

③

点的分布 → 机会线

高频出现但尚未被覆盖的需求模式（用户反复手工做的事）——新 Skill / 新 Agent 的候选方向，从真实使用中长出来。

④

线的延长 → 迭代建议

产出结构化优化建议：改哪个资产、改什么、预期影响谁、依据哪些记忆点——每条建议都能回溯到它的证据点列。

PART 2 · 设计哲学

简洁与可扩展优先，人来推第一圈

创新性 · 简洁性 · 可扩展性——首先追求后两者；AI 的迭代速度必须与人类的理解速度对齐
风格追求

简洁性 × 可扩展性优先

其深意囊括奥卡姆剃刀与复杂系统的核心思想——追求 elegant 的项目会走得更远，创新性在坚实的简洁之上自然生长。

冷启动

初始化一定要人工参与

第一批评测标准、第一条策展规则、安全边界——飞轮的第一圈必须人推。规则级记忆写入、资产更新确认、回归处置等关键节点永远不交给 Agent。

关键 Setup

与人类理解速度对齐

AI 更新速度远超人工逐行验证速度——所有更改必须改写成人可消化的富文本：Diff 一目了然、批量异步审核、自动门控过滤在前，人只做选择题。

把海量的更新、极快的迭代速度，变成人类可理解、可消化的形式，并与人类的意图和理解速度对齐——这一步是整个飞轮最关键的 setup。
