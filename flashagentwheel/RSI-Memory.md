# 上半部分 · RSI 背景与全景

## Slide 1 ｜ 封面

**从 Memory 到 RSI：智多星 × 星轮的智能飞轮**

副标题：Memory 是点，RSI 是线——星轮平台如何把智多星上每一个 Skill、每一个 Agent 的「做过」，连成「变好」的方向

---

## Slide 2 ｜ RSI 的起源：一个六十年的设想

- **1965 · I. J. Good**：设计机器本身也是智力活动——足够聪明的机器可以设计出更聪明的机器，继而引发"智能爆炸"。
- **2003 · Schmidhuber 的 Gödel Machine**：给出理论最优的接受规则——只接受**可证明**能提升长期效用的自我修改。蓝图完美，但依赖形式化证明，难以落地。
- **2023–2024 · 工程化尝试**：STOP（Self-Taught Optimizer，用 LLM 递归改进代码生成器）、Self-Refine 等，把"自我改进"从理论搬进代码。
- **今天 · Coding Agent 时代**：Agent 可以修改训练代码、排查错误、连续运行实验——以前要研究者守着的工作，交给模型就能推进。**AI 正在参与下一代 AI 的研发，RSI 有了具体的形式。**

**RSI = Recursive Self-Improvement，递归自我改进**：改进后的系统，能够继续参与正向改进自己。

---

## Slide 3 ｜ 定义校准：改了自己 ≠ 越改越会改

"RSI"被用得很滥。把声明拆成四级台阶，每升一级都要单独交证据：

| 层次 | 可以声称什么 | 需要的证据 |
|---|---|---|
| **L-A 自我修改** | 系统能产生并采用自身改动 | 修改与采用记录 |
| **L-B 系统改进** | 新系统能更好完成目标任务 | 可比较预算下的新旧对照 + 独立任务验证 |
| **L-C 改进能力提升** | 新系统能更有效地产生后续改进 | 新旧改进器在可比较搜索问题上的对照 |
| **L-D 持续递归增益** | 改进能力在多轮反馈中持续贡献收益 | 多轮独立重复 + 阻断递归反馈的对照 |

现状盘点：SICA / DGM / HGM / RRSI 都已入住 L-A；L-B 需逐案核对（HGM 的跨数据集迁移、RRSI 的分布外收益存活）；**L-C 只有线索，L-D 无人入住**。台阶是声明的阶梯，不是价值排名——停在 L-B 不丢人，声称到了 L-D 才要交证据。

---

## Slide 4 ｜ 各家做法全景：按「迭代什么」分三条路线

**路线一 · 迭代产物（Artifacts）——"打草稿"**
代表：Self-Refine、Reflexion、Test-time Compute。任务内多改几版，越做越好；但任务结束经验即丢弃，下次不会更快。已成熟，不是真进化。

**路线二 · 迭代代码 / Harness——当前主战场**
- **ADAS**（2024）：meta-agent 自动设计 agent 系统——但 meta 与 target 分离，不算自我改进。
- **SICA**（2025，Bristol/iGent）：第一个完全自指的编码 Agent——**自己编辑自己的代码库**，消除 meta/target 之分；SWE-bench Verified 上从 17% 提升到 53%，非梯度、数据高效。
- **DGM**（Darwin-Gödel Machine，2025）：把自我修改组织成**进化树**，经验式地扩展高分节点。
- **HGM**（Huxley-Gödel Machine，KAUST，2025.10）：发现"当前高分 ≠ 后代高产"的**元生产力-性能错配**，用谱系（clade）后代聚合表现 CMP 指导树搜索；更少算力达到人类工程师水平，且跨数据集、跨模型迁移。
- **RRSI**（Google Cloud AI，2026.9）：Harness 进化的**正则化**——约束提案端与筛选端，防过拟合；进化集收益最小，但唯一在分布外显著超过初始 Harness，token 消耗少 30%。
- **工程侧**：Anthropic Dreaming（空闲时异步审阅轨迹）、EvoAgentX、腾讯四齿飞轮方法论（评测→记忆→落地→控制）。

**路线三 · 迭代模型（Model）——写入权重**
代表：STaR、Agent RL、自对弈微调。持久性最强，成本最高、风险最大，仍在研究阶段。

---

## Slide 5 ｜ Agent 时代，RSI 的主战场是 Harness

Agent = 冻结的骨干模型 + Harness（Prompt、控制流、工具接口、记忆与 Skill、上下文管理）。同一模型表现如何，很大程度由 Harness 决定。

为什么 Harness 层是主战场？**即时、可控**：改完 Skill/Prompt 立刻生效，不用重训模型；改错了一键回滚，不会不可逆。实测：Harness 层进化使迭代次数减少 70%、Token 消耗降低 80%+——一个模型参数都没动。

三层并不割裂：Harness 积累的经验可变成训练数据改进 Model；更强的 Model 又能产出更好的 Artifacts。**但当下投入产出比最高的着力点，是 Harness。**

---

## Slide 6 ｜ RSI 与 Memory 的关系：点与线

**Memory 不是飞轮的"大脑"——Memory 是点。**

每一次经验沉淀都是一枚**点状的、带版本的 Memory**：一次会话的高频模式、一条失败反例、一次资产快照、一个被验证的假设。点本身只记录"发生过什么"，孤立地看，价值有限。

**RSI 是把点连成线的方法论。**

- **归因是连线**：这次失败和上次失败是不是同一个模式？点的聚集连成"问题线"。
- **信用分配是连线**：收益该记在哪些点上？改动与结果之间的因果链。
- **方向是线的指向**：历史点列的斜率告诉我们系统在往哪走、有没有偏。
- **推演是线的延长**：从已有的线外推下一轮该改哪里、怎么验证——这就是迭代信号。

**只有点没有线，记忆退化为日志；只有线没有点，推演沦为空想。** 点成线、线成势——这就是 Memory 与 RSI 的咬合方式。

# 下半部分 · 星轮：我们的做法

## Slide 7 ｜ 星轮定位：智多星的资产治理与迭代平台

智多星是我们的内部智能体平台，上面的 **Skill 和 Agent 是平台的核心资产**。为了让这些资产持续自迭代，我们搭建了**星轮**——一套资产治理与迭代平台：

- **资产治理**：捕捉信号（每天的使用数据、更新事件）+ 积累记忆（点状沉淀）。
- **资产迭代**：基于快照与记忆做 RSI 式优化——生成 baseline、对照比较、产出优化建议。

星轮与智多星的关系：智多星是生产系统，星轮是它的"进化引擎"——**by 用户、by 资产**地做 Memory 和迭代。

---

## Slide 8 ｜ 星轮数据流全景：每晚自动转动的飞轮

```
智多星（生产环境）
   │  每晚定时抓取
   ▼
① 会话记录 + ② Skill/Agent 调用次数统计 + ③ 资产更新事件
   │
   ▼
资产快照（Asset Snapshot）—— 全量 Skill/Agent 的版本化快照
   │
   ▼
Baseline Frame —— 当前基线 + 下一步优化的比较对象
   │
   ▼
对照比较 → 归因分析 → 优化建议（改哪个 Skill / Agent，怎么改）
   │
   ▼
回流智多星生效 → 次日晚再抓——飞轮转动
```

每天一圈：抓取 → 快照 → 建基线 → 对照 → 建议 → 回流。**上线不是终点，是下一轮进化的起点。**

---

## Slide 9 ｜ 资产快照与 Baseline：星轮的"点"制造机

- **快照内容**：全量 Skill / Agent 的定义、配置、版本 + 前一日的调用统计与使用分布。
- **by 用户维度**：同一资产按"谁调用、谁创建、谁负责"切分视图——资产的适用性和问题归因到人、到场景。
- **快照即点**：每一次快照是一枚带时间戳的点；**快照序列天然连成线**——资产的演化轨迹清晰可见。
- **Baseline Frame**：以最近稳定快照为基线，新改动与之对照——回答"这次更新让系统变好了吗"，而非"这次更新了吗"。
- **可回滚、可溯源**：任何版本的资产都能还原；任何一次优化都能追到它基于哪个快照、由什么信号触发。

---

## Slide 10 ｜ 记忆做法：从用户会话中挖"高频模式"（当前重点建设）

**记忆来源一 · 会话模式挖掘（by 用户）**

拉取每个用户的会话记录，挖掘其中的高频模式，形成点状记忆：

- **用户偏好**——表达习惯、格式要求、详细程度、交互方式
- **产物形成偏好**——用户最终接受的产出长什么样（报告结构、代码风格、图表口味）
- **Skill 使用偏好**——什么场景下用户调用什么 Skill、调用顺序、组合方式

**记忆来源二 · 资产配置沉淀（三条路径）**

围绕用户与资产的关系做配置级记忆：

- 用户**调用的** Skill / Agent → 使用画像：高频组合、成功场景
- 用户**创建的** Skill / Agent → 创作画像：风格、惯用结构、质量基线
- 用户**负责的** Skill / Agent → 治理画像：维护节奏、问题热点、下游依赖

这些记忆是**点**——版本化、带时间戳、带来源（哪个用户、哪段会话、何时挖掘）。点会持续积累，等待 RSI 把它们连成线。

---

## Slide 11 ｜ 从点到线：星轮如何产出迭代信号

1. **点的聚集 → 问题线**：多个用户在同一 Skill 上反复卡住（调用失败率、重试、放弃）→ 识别系统性短板，而非偶发个例。
2. **点的对照 → 涨跌线**：资产更新前后的快照对照 + 调用统计变化 → 这次更新带来了什么。
3. **点的分布 → 机会线**：高频但未覆盖的需求模式（用户反复手工做的事）→ 新 Skill / 新 Agent 的候选方向。
4. **线的延长 → 迭代建议**：产出结构化优化建议——改哪个资产、改什么、预期影响谁、依据哪些记忆点。

| 飞轮环节 / 原则 | 星轮现状 |
|---|---|
| 信号捕捉（评测的眼睛） | ✅ 每晚抓取会话 + 调用统计 + 更新事件 |
| 记忆积累（点状沉淀） | 🔨 **当前重点建设**：用户偏好 / 产物偏好 / Skill 使用偏好 + 三条配置沉淀路径 |

## Slide 13 ｜ 设计哲学：简洁与可扩展优先，人来推第一圈

- 风格追求：创新性、简洁性、可扩展性——**首先追求后两者**（奥卡姆剃刀 + 复杂系统的核心思想）。追求 elegant 的项目走得更远。
- **初始化一定要人工参与**：第一批评测标准、第一条记忆策展规则、安全边界——飞轮的第一圈人来推。
- **关键选择要人来决策**：规则级记忆写入、资产更新最终确认、回归处置、冷启动种子、安全边界——五个节点永远不交给 Agent。
- **与人类理解速度对齐**：AI 迭代速度远超人工逐行验证速度——所有操作和更改必须做人类友好的改写与摘要，变成人可理解、可消化的富文本，与人类的意图和理解速度对齐。Diff 模式、批量异步审核、四层自动门控在前。

---

## Slide 14 ｜ 收束

- **Memory 是点**：版本化、带来源、可持续积累的点状沉淀——星轮每晚在制造这样的点。
- **RSI 是线**：归因、信用分配、方向与推演——把点连成线，让每一次执行都不白费，每一个教训都不白吃，每一次改进都经过验证。
- **星轮是连线者**：智多星负责生产，星轮负责进化——点成线，线成势，飞轮每晚自己转一圈。
