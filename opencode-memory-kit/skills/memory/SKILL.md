# Memory：文件打底 + grep 检索的记忆纪律

记忆根目录：`.opencode/memory/`

```
memory/
├── MEMORY.md      # 索引：只放一行式指针（带来源），<200 行，每次会话都可能被读
├── topics/        # 主题细节文件：一个主题一个文件，dream 时由 dreamer 维护
└── log/           # 日记：YYYY-MM-DD.md，原始追加，不摘要不压缩
```

## 一、写入纪律（什么时候记、记到哪）

**值得记的**（能改变未来行为的信息）：
- 用户明确表达的偏好（"回复用中文"、"别动这个文件"）
- 项目级决策及**原因**（"用 JWT 不用 session，因为要支持移动端"）
- 环境/工具的坑（"这台机器 docker 要 sudo"）
- 用户纠正过你的错误（这是最高优先级的记忆）

**不值得记的**：
- 代码细节、文件结构——读代码本身更快更准
- 临时任务状态、TODO——那是 git 和会话上下文的事
- 能从仓库里推导出的任何东西

**写入方式**：默认只追加到 `log/$(date +%F).md`，一行一条：

```
- [HH:MM] 事实内容 (上下文: 正在做 xxx 时)
```

**不要**在会话中途直接改 `MEMORY.md` 或 `topics/`——那是 dreamer 的职责。例外：用户明确说"记住这个"且属于持久偏好时，可同时往 `MEMORY.md` 对应分区加一行带来源的指针。

## 二、检索纪律（先索引，后 grep）

需要回忆时，严格按顺序：

1. **先读 `MEMORY.md`**——80% 的问题索引层就能回答。
2. **索引命中指针** → 读指针指向的 topic/log 文件的具体段落，不要盲目全文读入。
3. **索引没命中** → grep 全文：

```bash
grep -rni --include='*.md' '关键词' .opencode/memory/
# 多个候选词用：
grep -rniE '词1|词2' .opencode/memory/
# 看上下文：
grep -rni -C2 '关键词' .opencode/memory/log/
```

4. grep 无结果就诚实说"没有相关记忆"，**不要编造**。

检索到的记忆如果与当前代码/现实冲突，以现实为准，并在 log 里记一笔"记忆已过时"。

## 三、维护纪律

- `MEMORY.md` 接近 200 行、或 log/ 目录超过约 500 行 → 建议用户跑 `/dream`。
- 每条索引必须带 `(来源: 文件路径)`。没有来源的记忆是不可信的断言，dream 时会被清除。
- 记忆文件是项目资产，提交进 git；私密内容不要写入（记忆可能被分享给协作者）。
