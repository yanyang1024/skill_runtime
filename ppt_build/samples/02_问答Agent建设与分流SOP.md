# 问答 Agent 建设与咨询分流 SOP

> 对应痛点 02「需求排期长、一人 loading 大」。
> 目标：把算法工程师从事务性咨询中释放出来，投入核心开发。

---

## 1. 咨询分层分流模型

| 层级 | 咨询类型 | 承接方式 | 目标分流比例 |
|---|---|---|---|
| L1 | 口径查询、状态查询、使用指导 | 问答 Agent 自动回答 | ≥ 60% |
| L2 | 简单取数、报表微调 | Agent 生成代码 / 半自动工单 | ~25% |
| L3 | 新需求、模型问题排查 | 人工（排期池） | ≤ 15% |

## 2. 问答 Agent 知识库构成

1. **映射资料**：痛点 01 的《业务-技术映射资料》（口径类问题的答案来源）。
2. **历史 FAQ**：把过去 3 个月 IM/工单中的问答对脱敏后入库。
3. **操作手册**：WebUI 使用说明、常见报错及处理。
4. **排期公示**：当前排期池状态，Agent 可直接回答"我的需求排到什么时候"。

## 3. 建设步骤（2 周可落地的最小闭环）

| 步骤 | 动作 | 产出 |
|---|---|---|
| D1-D3 | 收集历史咨询记录，聚类 TOP20 问题 | FAQ 清单 |
| D4-D6 | 整理映射资料、手册为结构化文档 | 知识库 v1 |
| D7-D10 | 搭建 RAG 问答 Agent，接入 IM 机器人 | Agent 上线（内测） |
| D11-D14 | 灰度 2 个业务群，设置"转人工"兜底 | 分流率日报 |

## 4. 运营指标

- **分流率** = Agent 独立解决数 / 总咨询数（目标 ≥ 60%）
- **转人工率** 与 **不满意率** 周报监控
- 每周把"转人工"case 回流到知识库，形成闭环

## 5. 红线

- Agent 不直接操作生产数据，只读接口 + 引用文档回答。
- 涉及口径变更、模型结论的问题一律转人工，并自动生成工单。
