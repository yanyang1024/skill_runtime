# 会话进度、执行时序轨迹与耗时瀑布图

用于设计"用户能看见 agent 正在做什么、每步花了多久、和对话内容如何对应"。与 `conversation-trajectories.md` 配套：那份管三种历史的语义与恢复，这份管**时序数据模型、进度条、瀑布图和与对话的同步展示**。

## 先确定口径：进度不是百分比

- 对模型驱动的多步任务，总步数事先未知，**禁止用动画或估算制造完成百分比**。
- 可核对的进度只有三类：**当前阶段名**（来自真实事件）、**已完成/已发现步骤计数**（如"已完成 3 步 · 正在执行数据检查"）、**已用时间**（从 run 开始的真实墙钟）。
- 步骤总数只在流程确定（固定编排、计划已生成且经确认）时显示分母；计划变更时更新分母并保留变更记录。
- 等待用户、等待外部、模型生成中、工具执行中是不同状态，进度条要分别表达，不统一叫"加载中"。

## 时序数据模型：Span

一次 run 的执行是一棵 span 树。对齐 OpenTelemetry GenAI 的通用形状（`invoke_agent` 根、`chat` 模型调用、`execute_tool` 工具调用），但字段以本应用契约为准，不直接暴露供应商内部结构：

| 字段 | 说明 |
| --- | --- |
| `span_id` / `run_id` / `parent_span_id` | 稳定标识与父子关系；重试产生新 span，用 `retry_of` 关联 |
| `kind` | `run` / `llm` / `tool` / `subtask` / `wait`（等待用户或外部） |
| `name` / `summary` | 业务可读名称与结果摘要，不暴露提示词、思维链、敏感参数 |
| `started_at` / `ended_at` | 服务端时间；`ended_at` 为空表示进行中 |
| `status` | `running` / `succeeded` / `failed` / `cancelled` / `interrupted` |
| `seq` | run 内单调递增序号，用于排序与去重，不依赖到达顺序 |
| `message_id` / `artifact_refs` | **锚点**：该 span 对应哪条消息、哪些产物；这是与对话同步的关键 |
| `duration_ms` | 由服务端在结束时计算，前端不自行估算 |
| `error_code` / `user_summary` | 失败原因与可恢复动作 |

可选扩展：`queued_at`（区分排队与执行）、`attempt`、`token_usage`。只记录实现确实产出的字段，不伪造精确耗时。

### 事件协议（应用自定义）

```text
event: span.started
data: {"run_id":"r_01","span_id":"s_3","parent_span_id":"s_1","kind":"tool",
       "name":"数据检查","seq":4,"message_id":"m_02","started_at":"..."}

event: span.finished
data: {"run_id":"r_01","span_id":"s_3","seq":7,"status":"succeeded",
       "ended_at":"...","duration_ms":1820,"summary":"3 个缺失值",
       "artifact_refs":["f_02"]}
```

纪律沿用 `streaming-and-events.md`：终态由协调层定义；迟到事件按 `seq` 归并，**不能把已终态的 span 改回 running**；EOF 未收到 run 终态 → run 与未闭合 span 标 interrupted；快照重放时按 `span_id + seq` 去重。

## 三层呈现，共用一个 span store

同一份归并后的 span 状态驱动三层视图，**不要**让消息流和轨迹面板各自解析一份事件：

1. **会话进度条（始终可见，一行）**：当前阶段 + 已完成步骤数 + 已用时间；失败/等待输入时变为对应状态色与动作入口。它是状态摘要，不是装饰动画。
2. **消息内联步骤卡（默认形态）**：在 `message_id` 对应的消息内，按 span 顺序显示步骤卡；单步内联、多步折叠为摘要行（"3 个工具调用 · 2.4s · 1 个失败"），展开看单项。阅读主路径不被打断。
3. **轨迹面板（按需打开）**：侧栏或全屏，含时序列表与瀑布图两种视图；用于核对顺序、并行、耗时与失败。

## 与对话同步的交互逻辑

- **锚点是双向的**：点消息里的步骤卡 → 轨迹面板打开并定位到该 span；点面板里的 span → 滚动到对应消息/产物并短暂高亮。`message_id` 与 `artifact_refs` 是唯一连接件，不用文本匹配。
- **流式期间各管各的滚动**：正文继续遵循"跟随/回看"规则；轨迹面板的展开、滚动、选中不重置对话位置；新 span 出现不推高正在阅读的消息。
- **进行中与已完成的区分**：running span 显示已用时间与"进行中"，不给假终点；run 终态到达后才把整条消息标为完成。动画结束、瀑布图绘制完成都不构成业务完成。
- **历史回放**：刷新/切换会话后从服务端拉取 run+span 快照重建三层视图；interrupted 的 run 显示到实际中断点，提供"重试失败步骤/重新生成"的真实入口，回放不重新执行。
- **失败优先**：任一步失败在进度条、摘要行、瀑布图三处都可见，不被成功步骤数量掩盖。
- **窄容器**：瀑布图降级为时序列表（每行：名称、状态、耗时），面板全屏；不要压成不可读的细条。

## 瀑布图布局规则

```text
run: 检查销售数据                         总计 12.4s   0s───────6s───────12s
├ llm · 规划                              1.1s        ██
├ tool · 读取订单                          0.3s          █
├ tool · 检索政策                          0.2s          █        ← 并行：同列区间重叠，分行显示
├ llm · 解读结果                           0.9s            ██
└ subtask · 退款计算                       4.6s             ██████
   ├ llm · 子任务规划                       1.2s             ███
   └ tool · 计算（失败，可重试）             0.1s               █✕
```

- 行 = span，按父子缩进；x 轴相对 run 起点，刻度自适应总量级；名称列与条形列分离，名称列固定宽度可省略号。
- 并行分支按 `started_at` 分行，不用到达顺序；嵌套默认折叠子树，父行显示自身总耗时。
- 重试关联显示（`retry_of`），重试链可折叠；不把多次尝试合并成一次成功。
- 未结束的 span 条形延伸到"现在"并动态更新，但**不重排其他行的位置**；新行追加在稳定位置。
- 长历史按 run 分组分页/虚拟化；验证查找、复制、锚点跳转与回看位置。
- 耗时口径在 UI 注明：排队/首 token/工具执行分别是什么；模型"思考"时间不展示为内容。

## 验收

- 用 `assets/timeline-cases.json` 复放：并行工具、乱序/迟到事件、重试链、未终态 EOF、快照去重；断言终态不倒退、计数不重复、锚点指向正确消息。
- 浏览器检查：流式时向上回看不被拉回；点步骤卡与瀑布图行能互跳；失败在三处可见；窄屏降级为列表。
- 从任意产物能找到产生它的 span 与 run；刷新后轨迹可重建且不重复执行。
- 记录耗时数据来自真实事件还是估算；没有真实耗时的步骤不显示精确数字。
