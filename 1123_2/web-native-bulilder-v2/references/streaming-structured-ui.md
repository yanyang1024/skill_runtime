# 流式结构化 UI：SSE 上的内联标记与组件渲染

用于回答"除了 Markdown 正文，模型还能怎样流式地产出卡片、表格、表单、图表等可交互内容"。与 `rich-text-rendering.md` 配套：那份负责正文渲染，这份负责**结构化内容**的生成、解析、展示与交互边界。

## 先选通道，不要默认内联 XML

模型产出结构化内容有三条通道，按复杂度选择，能左不右：

| 通道 | 形态 | 适用 | 代价 |
| --- | --- | --- | --- |
| 独立事件（默认） | `event: tool_status` / `card` 等 SSE 事件携带 JSON，前端按类型渲染固定组件 | 工具状态、产物卡、引用、澄清卡等**已知类型** | 需要逐类型定义事件；与正文的先后位置需另行约定 |
| 内联标记语法（XML-ish） | 模型在正文流中写 `<card ...>...</card>`，前端增量解析成组件 | 结构化内容**与正文顺序交织**，需要渐进出现；组件集合小且固定 | 需要增量解析器、转义规则、未闭合处理；多一层模型格式训练/约束成本 |
| 声明式 UI 描述 | 模型产出受约束的 UI 结构描述（如 A2UI 这类扁平 JSON 消息），宿主映射到原生组件 | 跨端复用、界面结构本身由 agent 组合 | 引入协议与渲染层，小应用不必自建 |

独立事件始终保留：任务终态、权限、执行状态**不允许**依赖正文里的标记。内联标记只承担展示与提案，不承担执行。候选协议的定位见 `open-source-patterns.md`。

## 内联标记的语法约定

先写一份一页语法契约，再实现解析器。建议：

- 标签白名单：如 `<card>`、`<table>`、`<field>`、`<action>`；不在白名单的标签按纯文本转义显示，不报错中断正文。
- 属性白名单与类型：逐标签声明允许属性、类型、枚举和长度上限；未知属性丢弃并记录。
- 内容模型：哪些标签允许嵌套、哪些只能包裹纯文本/Markdown；禁止任意嵌套 HTML 与事件属性（`on*`）。
- 与 Markdown 的关系：明确代码围栏/行内代码内的标记**不解析**；明确标记内部是否再跑 Markdown 解析。
- 转义：正文里的字面 `<`、JSON 属性值中的引号与换行如何转义；不要复用 HTML 实体规则而不写清楚。

示例（应用自定义，非任何协议标准）：

```text
我先看数据。<card kind="finding" severity="warn" title="缺失值">
发现 **3** 个缺失值，集中在 age 列。
</card>建议先补齐再训练。
```

## 增量解析是一个状态机

网络块、模型 token、SSE 事件、标签边界互不对齐。解析器输入是**已解码的字符流**，状态至少包含：

```text
text ──'<'──> maybe_tag ──合法标签字符──> tag_open(累积属性) ──'>'──> in_tag(内容缓冲)
  ↑              │                                                        │
  └──────────────┴── 非法序列：把已缓冲的 '<...' 当普通文本吐出             │
                                                                          └──闭合标签──> 校验 → 产出组件节点 → text
```

必须处理：

- 缓冲区尾部保留可能是不完整标签的残片（如末尾 `<ca`），其余文本才提交给 Markdown 渲染；
- 属性值跨多个网络块、含空格/中文/转义引号；
- 未闭合标签的显示策略三选一并写进契约：**占位骨架**（可交互组件常用）、**暂缓整块**（表格常用）、**按文本显示**；不要静默丢弃已到达内容；
- EOF 时仍有未闭合标签 → 该组件标 partial，整条消息标 interrupted；不把它渲染成完整成功卡片；
- 全文替换/新 run 时重置解析状态，稳定 key 定位已产出节点。

## 交互与提交边界

- **流式中的组件默认只读**：按钮、表单、采纳动作在标签闭合且校验通过前禁用；未完成输出不驱动字段采纳或工具执行（与主文件规则一致）。
- `<action>` 类组件只表达"提案"：点击后走应用自己的确认与服务端校验，不把标记里的参数当授权。
- 组件交互产生的新输入（选择、填写）作为**用户消息或结构化提交**回传，不回改模型原文。
- 组件内的 Markdown 正文沿用 `rich-text-rendering.md` 的全部安全规则；两者共享链接/图片协议策略。

## 安全边界

- 白名单之外的标签、属性、协议一律不渲染为可交互元素；解析失败回退为转义文本。
- 不把模型产出拼进 `innerHTML`/`v-html`；组件由应用代码创建，文本节点用文本方式插入。
- 标记里的 URL、图片、iframe 一律按不可信来源处理；不因为"它看起来是组件"就放宽。
- 属性值不进入选择器、样式字符串或脚本上下文；数字属性做范围限制，防止超大尺寸/数量撑爆布局。
- 安全探针见 `assets/structured-ui-cases.json`；不要渲染到未隔离的生产页面。

## 性能与阅读

- 组件节点稳定 key；正文与组件分段提交，避免每 token 重建整棵树。
- 流式期间组件出现/占位**不推高用户正在阅读的位置**；遵循回看暂停跟随。
- 大表格/大图先在占位中给尺寸，闭合后再填充；长内容进独立滚动容器。

## 验收

- 用 `assets/structured-ui-cases.json` 复放：标签跨块、属性截断、未闭合 EOF、代码围栏内的同名标签、白名单外标签、危险 URL、EOF 后重放。
- 验证：原文可导出且不含显示期补全；未完成组件不可提交；切换 run 后旧组件不再更新；窄屏与键盘可操作。
- 记录"独立事件是否已够用"的判断；内联标记带来的解析与约束成本要有真实收益支撑。
