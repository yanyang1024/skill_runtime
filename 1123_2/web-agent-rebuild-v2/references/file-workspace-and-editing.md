# 文件空间与人机共编

## 先判断编辑对象和投入

先询问或从项目识别：用户交付什么、文件是否会跨会话复用、谁能修改、哪些格式必须保真。只读问答不必建设文件管理器；少量产物可用文件列表；多个项目和大量文件再考虑目录、搜索、筛选与批量动作。把找文件、核对改动、恢复错误的总成本作为收益指标。

| 对象 | 用户应看到什么 | 实现边界 |
| --- | --- | --- |
| 上传原件 | 名称、类型、归属、处理状态 | 原件与解析文本分开；解析失败不伪装为空文件 |
| 生成产物 | 当前内容、生成中/部分/完成、来源任务 | 生成完成、已采纳、已保存分别表达 |
| 人工草稿 | 可编辑内容、未保存提示 | 本地草稿与服务端版本分开 |
| AI 修改提案 | 目标、范围、差异、适用版本 | 不以新回复覆盖人工草稿 |
| 历史版本 | 作者/操作者、时间、改动摘要 | 恢复产生新版本；不抹去已发生的历史 |

文件身份用稳定 ID；路径和名称是可变属性。上传、重命名、移动、删除、恢复、下载及引用均沿用服务端资源权限。删除附件引用和删除源文件是两个动作。文件树不得直接暴露服务器任意路径；上传和预览按类型、大小与处理能力设边界。工作区不自动等于模型上下文：显示本轮实际引用的文件、版本和选区，自动检索要给出来源，可移除或更换。

## 选择页面，不固定三栏

- 简单旧表单：保留表单，结果卡打开编辑面板；只在有复用需求时增加相关文件列表。
- 文档任务：以当前文档为主体，文件空间与对话按需侧开。顶部显示文件名、保存状态、版本及预览/编辑/差异模式；当前选区可发起局部改写。
- 多文件调查：项目内文件列表与任务关联，结果可回到来源文件、段落或数据范围。
- 窄容器：文件、编辑、对话切换为独立视图，保留草稿、选区、滚动和返回焦点；不要把三栏压成三个窄条。键盘与触屏均可完成选择、采纳、撤销、保存。

## 让手工和对话作用于同一个对象

语言指令明确作用于选区、当前文件或明确选中的多文件；打开文件变化后，不把旧请求自动重定向到新文件。请求绑定文件 ID、基准内容版本、必要的草稿修订及选区锚点。位置偏移在插入后会失效；按编辑器能力使用稳定块 ID/事务映射，不能可靠映射就重新比较或请用户定位。

默认把生成流放入候选预览，允许用户继续编辑。结束后显示局部差异和影响范围，支持按块采纳、全采纳、丢弃或继续要求修改。短小、可逆且明确授权的修改可直接应用并提供撤销；不要让每个错别字都变成审批。不要把仅可见于当前客户端的高亮装饰当成持久提案。

采纳前检查目标与基准仍适用。当前草稿有新改动时，用基准、当前草稿与候选比较：不冲突才合并，重叠则保留两边让人选择，或基于最新内容重算。部分采纳后重新映射剩余提案，不能继续套用旧偏移。保存用服务端原子版本检查；保存返回只确认发出时的修订，期间的新输入继续标为未保存。自动保存也须显示保存中、失败、离线与冲突。

流式中断保留明确标注的部分候选；不把渲染补全的 Markdown 当源文。多文件修改先展示逐文件范围和差异，说明是否原子提交；部分失败时逐项呈现，不假称全部成功。撤销最近本地编辑与恢复历史版本分开；在多人协作中撤销不得抹除他人随后修改。

## 按格式选编辑器与真实存储

先确定权威内容格式：纯文本/Markdown、编辑器结构化文档、表格单元格或原始二进制。预览不是编辑模型；Markdown 渲染器不自动具备编辑能力。代码/Markdown 可先用 textarea 或文本编辑器加预览；长篇富文档再评估块编辑器。不要在每个 token 后全量重建编辑器 DOM，避免光标、IME 与撤销栈丢失。

PDF、DOCX、表格不统一承诺原位无损编辑。明确支持查看、提取后编辑副本、结构化编辑或导出；测试转换后的表格、公式、图片和样式保真，保留原件。HTML 预览隔离执行环境，模型产物不获得宿主脚本权限。

优先单用户草稿加版本检查。只有真实多人同时编辑、离线合并需求才引入 CRDT；它解决并发同步，不能替代资源授权、AI 提案审查、语义冲突和持久化。技术选型见主文件列出的开源参考。

## 用一个闭环验证价值

打开报告 → 手动改标题 → 选中结论要求缩写 → 生成期间继续改正文 → 比较并采纳部分建议 → 保存 → 刷新恢复 → 回到生成它的任务。记录完成时间、错误覆盖次数、纠错成本与找回旧版本耗时，再决定是否扩展目录、多文件或协作。
