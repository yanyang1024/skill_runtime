# web-agent-rebuild / web-native-bulilder v2 评审与增补说明

日期：2026-11-23。对象：用户提供的两个新版 Skill 包（对比上一版已加入文件空间、对话轨迹、开源参考与测试夹具）。

## 总体评价

新版方向正确，方法论自洽：三种历史（对话/执行/产物）的语义分离、原文与显示分离、能力契约与真实性边界都延续得很好；`open-source-patterns.md` 带核查日期与许可证/付费边界，是高质量做法。主要缺口集中在**"原则有了，但时序数据与呈现没有落地模型"**，以及**富文本只覆盖 Markdown、缺少结构化交互内容的流式路径**——正是本次增补的两块。

## Review 发现

### 已修复（本次增补）

1. **执行轨迹只有文字原则，没有可实现的数据模型**。原 `conversation-trajectories.md` 提到"展开层提供耗时""平行工具按父任务分组"，但没有 span 字段、事件协议、排序去重规则，无法实现。→ 新增 `references/execution-timeline.md`（span 模型 + `span.started/finished` 协议 + seq 归并 + 瀑布图布局规则）。
2. **会话进度条只有禁令没有正面设计**。原文"不凭动画制造进度百分比"是对的，但没说该显示什么。→ 明确三种可核对口径：当前阶段名、已完成步骤计数、真实已用时间；分母只在流程确定时出现。
3. **轨迹与对话的同步机制缺失**。这是"轨迹面板和聊天如何一起用"的核心。→ 以 `message_id`/`artifact_refs` 作为唯一锚点，三层视图（进度条/消息内步骤卡/轨迹面板）共用一个 span store，双向定位，滚动互不干扰。
4. **富文本渲染只覆盖 Markdown**。工具卡片、表单、图表等"模型在正文流里产出可交互组件"的路径（内联 XML 标记、声明式 UI）完全没有。→ 新增 `references/streaming-structured-ui.md`，先给三通道选型（独立事件 / 内联标记 / 声明式 UI，能左不右），再给增量解析状态机、未闭合与 EOF 策略、交互门禁与安全白名单。
5. **验收与夹具没有跟上新功能**。→ `acceptance.md` 增加两节；新增 `assets/timeline-cases.json`（并行、迟到事件、重试链、EOF、快照去重）与 `assets/structured-ui-cases.json`（跨块标签、围栏内不解析、危险 URL、交互门禁）。

### 建议处理（未改动，留你决定）

6. **两包共享文件已出现漂移**。8 份参考、3 份 assets、1 个脚本在两包中重复；当前 `acceptance.md` 段落顺序不同，`composable-agent-ui.md`、`interaction-patterns.md` 内容已分叉。建议指定单一权威源 + 同步脚本，或至少在发布前跑一致性检查：
   ```bash
   for f in conversation-trajectories file-workspace-and-editing open-source-patterns rich-text-rendering streaming-and-events; do
     cmp web-native-bulilder/references/$f.md web-agent-rebuild/references/$f.md || echo "DRIFT: $f"
   done
   ```
7. **SKILL.md 的 description 开头被新功能稀释**。两包 description 都以"涵盖按需的文件空间、手工与对话共编…"开头，核心触发场景（从零构建 / 改造已有）反而在后。触发匹配主要看前部语义，建议把"从零构建 Flask/FastAPI Agent Native Web UI"与"改造已有 Flask/FastAPI Web UI"提到句首，新功能罗列放到末尾。
8. **`streaming-cases.json` 的 `utf8_multiline` 隐式包含 BOM**。wire 以 `﻿: heartbeat` 开头（U+FEFF + 注释行），SSE 规范允许忽略一个前导 BOM，但用例没有说明这是对 BOM 的期望行为。建议显式注释或拆成独立 case，避免不同解析器实现产生分歧而难以定位。
9. **夹具覆盖缺口（可选）**：现有 SSE 用例没有"工具参数片段跨块累积后校验"的专门用例，而这是 streaming-and-events.md 的硬规则；可在下一轮补一条 `tool_args_fragmented` 用例。

## 落地建议

- 小应用不必引入 AG-UI/A2UI 全套：按 `execution-timeline.md` 的 span 形状自定义最小事件即可，协议候选留作需要跨框架复用时的升级路径。
- 实施顺序建议：先做"消息内步骤卡 + 真实耗时"（收益最大、成本最低），再加轨迹面板瀑布图，最后才考虑内联 XML 组件——后者需要模型格式约束与解析器两层投入。
