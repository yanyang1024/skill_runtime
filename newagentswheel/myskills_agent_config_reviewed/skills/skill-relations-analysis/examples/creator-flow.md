# 本包三方法的场景串联

这是本包真实方法接口的设计示例；业务 Skill 为用户待提供材料，不代表业务组合已验证。

用户：“已有这批 Skill 画像，帮我构建面向业务的 Agent；确实缺可复用方法时补齐。”

| 阶段 | 当前主体采用的方法 | 最少输入 | 交付及下一步 |
| --- | --- | --- | --- |
| 核对已有画像 | skill-relations-analysis：增量入口 | 本次目标、来源、已有画像 | 复用有效字段，只补关键缺口 |
| 选择与组合 | skill-relations-analysis：生态入口 | 能力画像、用户限制、实际工具条件 | 路线、阻塞、主体理由和 design-brief |
| 装配 Agent | agents-creator | design-brief、真实名称和目标目录 | 职责、导航、权限草稿；识别方法缺口 |
| 有条件补方法 | skill-creator | 明确方法缺口、成功标准、修改范围 | 真实 Skill 及检查证据；返回装配阶段 |
| 续接装配 | agents-creator | 新增方法接口、已完成 Agent | 只更新受影响导航与白名单，完成静态检查 |

同一主 Agent 保留目标、事实和文件引用。补方法阶段不反向启动 creator，也不重新画像全库。若没有缺口，跳过 skill-creator；用户只要关系报告时在分析处停止；需求明确时可以直接创建。

如果用户改为“将重复 Skill 合并”，分析阶段改交 consolidation-plan，由 skill-creator 实施。只有名称/触发/工具或公共契约受影响时才需要改调用方 Agent。组合方案本身不授予执行被分析业务方法的权限。

独立画像可按已有 Task 白名单委托 skill-profiler；本例其余阶段默认同主体续接。独立验收需要真实的新验证上下文，本包没有配置验收 Agent，因此交付默认只含自检。
