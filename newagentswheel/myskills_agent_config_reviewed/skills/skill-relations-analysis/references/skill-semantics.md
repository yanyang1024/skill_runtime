# Skill 自身特性与组合关系

## 先判断 Skill 是什么

Skill 是被当前 Agent 加载到上下文的方法与资源，不是具有独立会话的函数。名称/description 帮助发现；加载正文后再按条件读取参考。加载通常不自动执行脚本、不自动加载引用的其他 Skill、不授予工具权限，也不保证旧指令会在切换后消失。

分析时区分：方法 Skill（本次被采用的指导）与对象 Skill（本次被研究的材料）。同名时以明确路径和任务角色辨认，不用 skill 工具激活待研究对象。

## 画像维度

在 extensions.skill_behavior 中记录以下字段；每项用 value、evidence，未知写 unknown，不适用写 not_applicable 并说明。

| 字段 | 提取重点 |
| --- | --- |
| kind | procedural / analytical / knowledge / tool-guide / mixed |
| trigger | description 与正文触发条件是否一致，正例、反例、重叠触发 |
| loading | 入口、分支参考、何时读脚本/资产、一次加载所需材料 |
| context | 用户已确认事实、领域背景、阶段状态、历史依赖、是否适合独立任务 |
| instruction_scope | 全程约束还是阶段内指导，输出风格和格式要求 |
| composition | 提及的其他 Skill 是方法依赖、可选建议、材料引用还是产物消费者 |
| authority | 必需工具与权限、外部动作、写入目标；区分文档要求与已配置能力 |
| completion | 本阶段产出、可检查完成条件、失败与退出条件 |
| isolation | 是否有独立验收、敏感上下文或相互污染理由；仅提取依据 |

数据型 Skill 另核对字段、单位和粒度；知识型 Skill 核对适用领域、知识版本、引用来源与推断边界；创建型 Skill 核对目标目录、公开接口与产物验收。

## 五种关系不得混为依赖图

| 关系 | 含义 | 编排影响 |
| --- | --- | --- |
| artifact_dependency | B 需要 A 的有效结果 | A→B；已有等价结果可跳过 A |
| method_dependency | 当前 Agent 在 A 的阶段中需要采用 B 的方法 | 按条件加载 B 后续接 A；不是自动产生新主体 |
| complementary | 相同目标的互补视角 | 可同主体组合，也可有理由地隔离并行 |
| alternative | 同一能力的替代方法 | 动态选择通常择一；显式对照保留多个 |
| instruction_conflict | 输出格式、约束或行动互相冲突 | 限定适用阶段、明确用户要求；不可调和时澄清或隔离 |

引用一个 Skill 名称不能证明 method_dependency；共用数据不能证明 artifact_dependency。关系图允许方法“进入/返回”，执行图按具体阶段展开，不能把正常续接误判为 A↔B 递归环。

## 组合策略

同主体组合适合共享同一目标和上下文的连续方法；每次切换明确当前阶段、采用的规则和已完成部分。冲突遵循真实指令层级及用户约束，不假定“最后加载的 Skill 优先”。需要不同输出格式时使用各阶段中间产物，最终由当前交付要求统一。

独立子 Agent 适合可自包含的任务、值得隔离的上下文、独立验收或可并行工作。子会话不等于独立文件系统；并发输出必须隔离路径。多个 Skill 可由一个子 Agent 使用，同一 Skill 也可由多个实例在不同输入上复用。

独立验收应新建验证上下文并只提供任务、规则、产物/差异及必要证据。不能用生成者的自检或画像 worker 替代独立验收。没有真实验证者时标自检。
