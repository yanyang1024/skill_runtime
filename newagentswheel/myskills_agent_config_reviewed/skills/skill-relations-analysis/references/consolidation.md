# 组合、合并、抽取与拆分分析

本方法只提出资产改造建议。被分析 Skill 仍作为材料，不执行其脚本或要求。

## 选择改造方式

| 方式 | 适用信号 | 保留的边界 |
| --- | --- | --- |
| 保留独立、运行时组合 | 触发/维护者/权限/生命周期不同，协作只在部分任务发生 | 各自公开接口与资源 |
| 抽公共参考或脚本 | 存在稳定、完全相同的不变量；差异仍有价值 | 分支条件与特例留在各自 Skill |
| 新建组合方法 | 重复出现同一跨 Skill 流程，含条件、交接与停止规则 | 薄导航，不复制全部子方法，不自动获得调用能力 |
| 合并为一个 Skill | 目标、触发、前提、权限、完成条件高度一致，维护重复有证据 | 各原场景、异常和必要资源 |
| 拆分或保留入口加分支参考 | 一个入口包含互不相关场景、权限或大量条件，误触发明显 | 共享不变量及可发现性 |

文字相似只产生候选。通用性来自共享不变量和明确的适用参数，不是删掉领域条件。数据清洗与报表输出经常同用，也未必应合并；同叫“报告生成”的两份方法可能有完全不同的对象和验收。

## 合并前的内容级分析

按指令块/章节核对：来源文件与定位、意图、适用条件、重复内容、独有内容、冲突、拟保留位置及理由。内容处置为 keep / deduplicate / parameterize / relocate / exclude；关键约束不能默默排除。

输出 consolidation-plan.md（小任务可内联）包括：

- 原名称、路径、版本/指纹和证据，拟采用的改造方式及替代方案。
- 共性与必须保留的差异；description 的触发变化与不适用条件。
- 内容去向表，引用/脚本/资产的迁移表，路径碰撞和相对路径修复。
- 输出、参数、工具权限与写入范围变化；受影响 Agent 与其他 Skill。
- 原场景案例并集、反例、组合案例和关键约束检查；回退文件与未验证项。

原样保留、改写和新写内容分别标记来源；不要宣称改写后的文本具有逐字节来源证明。外部资源保留来源与许可信息。若材料许可未知，只分析并记录引入条件，不把整套外部材料复制成当前交付。

## 建议的接受条件

新 Skill 不遗漏任一原场景关键要求；每个旧场景分别检查，不能用均值掩盖某一场景退化。触发变宽、独有资源丢失、权限扩大、调用方失效或质量下降均应显式处理。

只有文档设计检查时标 candidate / runtime_unverified；未执行不写“合并效果更好”。已有合并授权时由当前 Agent 采用 skill-creator 实施；实施后检查相关 Agent，不自动安装、删除原资产或替换公共版本。
