# 分析到创建的交接

本 Skill 输出设计输入，agents-creator 消费它；当前 Agent 在同一任务中续接，不把 Skill 切换描述成主体通信。

写 design-brief.md（小任务可用等价紧凑段落），包含：

1. 用户目标、明确指定/排除项、交付与目标目录；哪些只是建议，哪些已授权实施。
2. 能力清单：分析 ID、真实运行名称、来源/版本、用途、触发与不适用条件、必需工具权限。
3. 路线：选择策略、按阶段展开的依赖与输入绑定、条件分支、最终汇总；每条事实附画像证据。
4. 主体建议：默认单 primary；每个拟拆分边界给出隔离/并发/能力理由、任务输入输出、协调成本与失败处理。
5. 待补方法：现有 Skill 哪部分足够，哪个重复可复用缺口值得补 Skill；缺工具/数据另外列出，不冒充方法缺口。
6. 接收材料：画像/生态/报告实际路径、未验证接口、运行时版本/权限假设、静态验收条件。

进入创建前只要求本次配置需要的事实充分；不要求全库所有画像成功。非关键缺口不阻断无关生成，关键缺口的配置保持 draft/blocked。创建器可针对缺口复核材料，不能无理由重启全套画像。

独立验收交接只给用户目标、验收标准、生成文件/差异、运行证据；不把设计者的“应该通过”判断当作验收输入。

涉及选择/合并/增量时，追加相关项：selected/rejected 及能力缺口；组合使用或资产改造的决策；来源/指纹与受影响范围；内容与资源去向；原场景及触发反例；强制运行约束需要哪些 runtime 能力。小任务可内联，不强制所有任务产生全部文件。
