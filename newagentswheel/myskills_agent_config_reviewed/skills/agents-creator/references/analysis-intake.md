# 分析产物接收与装配

接受用户直接需求，或 skill-relations-analysis 的 design-brief.md。分析不是创建的强制前置：已有充分能力信息即可创建。

## 接收校验

核对目标、授权目录、真实 Skill 名称/来源、触发边界、工具权限、关键输入输出、主体选择理由与证据。分析 ID 不等于加载名；画像 PASS 不证明可运行。旧画像缺字段时针对性读原材料或提出具体补提取请求，不能自动回调整个分析流程。

## 转成配置

| 分析结论 | 配置落点 |
| --- | --- |
| 适用场景、选择/不选择理由 | Agent 的 description 与能力导航 |
| Skill 加载与分支材料 | Skill 的 description、SKILL.md 条件导航 |
| 连续且共享上下文的方法 | 同一 Agent 按阶段采用多个 Skill |
| 独立上下文或真正并行的边界 | subagent + Task 白名单 + 自包含交接 |
| 产物先后关系 | 主体的阶段导航，具体步骤留在方法 Skill |
| 指令冲突 | 明确阶段适用范围/统一最终契约；必要时隔离 |
| 新的重复方法缺口 | 按权限采用 skill-creator，补齐后续接装配 |
| 工具/模型/数据缺失 | 明列阻塞或未验证条件，不能用提示词补足 |

默认生成 `<输出根>/generated/agents/` 与必要的 `generated/skills/`。用户明确要求写指定安装目录时按其授权实施；不另行发布或执行业务。生成的 Agent 只依赖实际业务 Skill、工具及随交付的契约，不把创建器 references 或分析产物绝对路径写成永久运行依赖。

需要共享运行规则时交付到目标 Skill 的 references，双方按其公开导航读取。主体名与权限一致，Task 只指向真实 subagent，不指向 Skill 或 primary。

## 创建阶段的有限补充

记录当前阶段、已完成文件、方法缺口及成功条件，然后采用 skill-creator。完成后只复核新增方法接口与受影响 Agent，不重启分析。未改变接口的内部编辑无需重写调用方；改变名称、触发、权限或输出要求才检查传播影响。

最后检查三个图：Skill 方法依赖、业务产物依赖、Agent 委托拓扑。三者分别表达，不能把一张 Skill 关系图直接翻译成同数量 Agent。

## 组合方案的实施边界

接收 selected/rejected、来源版本、资产改造建议与受影响范围。仅内部实现改动时保留 Agent；真实名称、触发、权限或公共契约变化才更新导航与白名单。合并/拆分实际文件采用 skill-creator；方法切换继续同主体，不新增 creator Agent。

对每步区分方法采用、工具执行和子 Agent 委托；Agent 导航只声明选择理由与交付责任，完整流程留在方法 Skill。Markdown 不能强制回收工具、清空上下文、取消进程或保证幂等恢复；需要这些保障时明确由平台实现，并标注 runtime_unverified。
