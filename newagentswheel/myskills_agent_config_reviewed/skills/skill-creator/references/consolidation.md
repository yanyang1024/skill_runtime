# 多 Skill 资产改造实施

用于获授权的合并、拆分、抽公共内容和重命名。已有分析建议可直接接收，不强制再启动分析流程。

1. 核对改造目标、来源版本、内容去向、关键差异、允许修改的目录及回归样例。方案缺少关键条件时针对性读取源材料；不只根据相似度决定删除。
2. 保留原版本快照或项目版本记录。在草稿目录实施，除非用户已指定原地修改；不擅自删除原 Skill 或替换公共版本。
3. 保留唯一且合法的 name、准确 description 和阶段条件。公共方法只留一份；特例使用清晰分支参考，避免大而全的正文。组合型入口由当前主体加载可用方法，引用名称不等于运行时自动调用。
4. 迁移必要 scripts/references/assets，修复相对路径、参数、资源名与路径冲突。多个 Skill 共享参考时，采用实际环境支持且一并交付的稳定位置；单独分发时随包携带必要副本，不依赖另一个未安装 Skill 的私有目录。
5. 给关键段落记录来源、保留/改写/新增及理由，保留外部许可；不把语义改写伪装成逐字保留。独有边界和失败规则有处置记录。
6. 检查原触发正例、原场景并集、反例、组合与错误案例。质量、触发与成本分别报告。只有静态检查时明确运行未验证，不用“内容更短”推断效果更好。
7. 回交实际名称、资源位置、公共契约变化、受影响 Agent/Skill、迁移方式和回退依据。由当前 Agent 决定是否继续 agents-creator 装配，不自动反向加载。

重要的旧场景退化、不可调和指令、权限范围不兼容或资源无法完整迁移时，优先保留独立 Skill 并组合；记录为何不合并也是有效结果。
