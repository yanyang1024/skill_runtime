# 需求拷问（grill-requirements）

将模糊需求变成双方共识的可交付需求文档。三阶段流水线，每阶段有门禁（gate）：上一阶段未通过，不得进入下一阶段。**在用户确认需求 review 通过之前，不输出方案、不写代码。**

## 总原则（贯穿三阶段）

- **事实是你的工作，判断是用户的工作。** 能从环境（文件、代码、文档、工具、网络）查到的，自己去查，绝不问用户；只把真正的决策交给用户。
- **一次一轮问题，而非一次性轰炸。** 成墙的问题只会换来敷衍的回答。
- **每题必附推荐答案。** 用户只需说"同意/是的"即可快速定夺——推荐答案是你的防失控开关，也是逼用户反驳的靶子。
- **把需求当决策树，不是当文档。** 每个决策分叉出依赖它的后续决策；先定父决策，再问子决策——上游答案会改变下游该问什么。
- **礼貌不是目标，共识才是。** 追问要越过"不好意思再问"的界限，直到没有静默假设残留。

## 阶段一：项目需求分析

输入可能是口述想法、聊天记录、会议纪要、已有文档或旧系统。执行：

1. **解析输入**，将需求映射为一棵**需求决策树**：核心目标为根，功能/约束/角色/数据为分支，每个未定点是一个待决策节点。
2. **三分类清单**输出给用户确认：
   - **已明确**：输入中直接陈述的事实与决策（注明来源）；
   - **我的假设**：输入没说但推进所必需的默认假设（每条标注依据）；
   - **缺口**：既没陈述也无法合理假设的空白。
3. **补齐事实**：对已有代码库/文档，先自行探查现状（现有模块、术语、约束），再修正上面的分类清单。环境事实一律自查。
4. 门禁：用户确认三分类清单（尤其是"我的假设"部分）无误 → 进入阶段二。

## 阶段二：需求对齐与背景完善（拷问循环）

以 grilling 方式逐轮消解决策树。概念：**frontier（前沿）** = 所有前置答案已敲定、现在可以问的问题集合。

### 每轮流程

1. 重算 frontier：只问前置已定的题；依赖本轮未决答案的题留到下一轮。
2. 一轮问完当前整个 frontier，按以下格式逐题编号：

```
❓ **Q1** - **<问题标题>**：<问题正文，可多段，可列选项>

➡️ <你的推荐答案 + 一句话理由>

---

❓ **Q2** - ...
```

3. 措辞让每个问题都能用"是/同意"接受推荐答案。
4. 等待用户回答后再进入下一轮。用户的每个回答都会重塑决策树：已定决策推动前沿外扩，解锁此前被阻塞的问题。

### 提问维度

按 [references/interview-dimensions.md](references/interview-dimensions.md) 的维度库系统扫面，避免只盯功能忽略非目标、异常路径与成功度量。深度优先走完整条分支再换分支，不要浅尝辄止地跳。

### 背景沉淀（边问边写）

每敲定一批结论，立即更新工作区内的需求背景文档（默认 `docs/requirements/背景与术语.md`，若项目已有约定则从其约定）：

- **术语表**：用户澄清的每个黑话/缩略语，一词一条，之后全程使用该词汇；
- **关键决策记录**：难逆转或反直觉的决策，记"决策 + 理由 + 被否决的备选"；
- **背景事实**：业务背景、现状约束、干系人与角色。

沉淀是增量的、随拷问实时进行的，不是结束后的追记。

### 结束条件

frontier 为空：决策树每条分支都走过，没有静默假设。进入阶段三。

## 阶段三：需求 Review

1. **复述共识**：完整复述整个需求——已定的决策、已接受的取舍、**明确不做的事（非目标）**——请用户确认"这就是我们要做的东西"。
2. **清单评审**：按 [references/review-checklist.md](references/review-checklist.md) 逐项评审，输出 review 报告：每项标注 ✅ 通过 / ⚠️ 风险（附缓解建议） / ❌ 缺口（附回到阶段二的追问）。
3. 存在 ❌ 缺口 → 带着缺口回到阶段二继续拷问，再重新 review；只有 ⚠️ → 由用户决定是否接受风险。
4. 门禁：全部 ✅ 且用户确认复述无误 → 按 [references/spec-template.md](references/spec-template.md) 产出最终需求规格文档，交付。

## 反模式（禁止）

- ❌ 在阶段一就给出方案或开始实现；
- ❌ 一轮抛出跨越多个未决前置的问题；
- ❌ 问任何自己能查到的事实；
- ❌ 接受"都行""你看着办"作为答案——把推荐答案压上去逼其表态；
- ❌ review 报告全绿但存在未经用户确认的假设。
