# Rethinking the Evaluation of Harness Evolution for Agents —— 解读与落地建议

> **论文**：Rethinking the Evaluation of Harness Evolution for Agents
> **作者**：Yike Wang、Huaisheng Zhu、Teng Xiao 等（Allen Institute for AI / University of Washington）
> **版本**：arXiv:2607.12227 v4（2026-10-05） ｜ [论文](https://arxiv.org/abs/2607.12227) ｜ [代码](https://github.com/rethinking-harness-evolution) ｜ [博客](https://yikee.github.io/harnessevolution/)
> **一句话**：harness 自动进化报告的收益，大部分可能只是「重复采样」的收益，而不是 harness 设计本身变好了——要区分这两者，必须等预算对比 + 留出集测试。

---

## 一、动机：对既有评测协议的两个指控

2026 年 harness 自动进化（Meta-Harness、AHE、AEVO 等）成为热点，甚至被视作通往递归自我改进（RSI）的路径。但论文发现这类工作的评测方式有两个根本缺陷：

1. **缺少等预算的简单基线**。harness 进化本身是一个迭代搜索过程（反复评估→修改→再评估），消耗大量额外推理算力，却从未与「把同样算力直接花在任务上」的朴素方法（并行采样/串行修订）做等预算对比。不对比就无法区分收益来自「更好的 harness 设计」还是「多试了几次」。
2. **搜索集与测试集不分家**。用 benchmark 的单元测试信号搜索 harness 配置，又在同一个 benchmark 上报告最终成绩——违反训练/测试分离的基本规范，收益可能只是对特定任务的过拟合。

**核心问题**：harness 进化到底产生了可泛化的设计改进，还是仅仅是重复采样？

## 二、核心思想：统一预算框架

固定策略模型 π_θ，给定算力预算 K（主实验 K=5），四种方法的区别只在「预算花在什么上」：

| 方法 | 更新什么 | 类比 | 性质 |
|---|---|---|---|
| **并行采样**（Parallel Sampling） | 轨迹（宽度） | 独立考 5 次，挑最好一份交 | 无持久化，每题重付 5× 成本（计件工资） |
| **串行修订**（Sequential Refinement） | 轨迹（深度） | 看着自己上一份答卷改，连改 4 轮 | 无持久化 |
| **装备进化**（Harness Evolution） | 跨任务共享的 harness | 题库练手改 5 代装备，炼出通用装备再上考场 | 持久化，承诺「一次搜索终身受益」（固定资产投资） |
| **装备即时改装**（Harness Scaling，论文自创探针） | 单任务的 harness | 每道题现场改装备，用完即弃 | 持久化但不求复用 |

- Harness Scaling 是关键的「侦探工具」：隔离「dataset 级进化」与「instance 级适应」，用来回答收益到底是可复用设计还是 test-time 发现。
- 所有方法从同一**极简 harness** 出发（仅一个 bash 工具，无 skills/middleware/memory）。
- Harness Evolution 用 AHE 实例化，**关闭其 explore agent**（因为它会从外部检索已为该 benchmark 调好的现成 harness，混淆进化与检索）。

## 三、评测设计：「反馈」与「赢」的定义

### 3.1 正确答案反馈

- 形式化：任务附带单元测试 g，定义 R(y, g) ∈ {0, 1}，轨迹过测试 = 1，否则 = 0。
- **有测试设置**：判词既给方法（迭代反馈 + oracle 挑卷）也给裁判（打分）。
- **无测试设置**：判词只给裁判打分，方法全程不可见——agent 只能靠自己生成的轨迹自我评估（考生兼裁判，循环论证风险高）。

### 3.2 「赢」的指标与判分细则

- **pass@1（主指标，「平时成绩」）**：最终交卷答案 ŷ 的平均通过率。
- **pass@5（辅指标，「考 5 次取最好」）**：5 条轨迹中至少 1 条通过的比例。只在有测试设置报告——那边它对应真实可交付的 oracle 挑卷；无测试设置下它只是无法兑现的假想天花板。
- **测谎仪逻辑**：pass@5 − pass@1 的差 = 「多试几次」的贡献。若 harness 真变好，**pass@1 必须涨**；只有 pass@5 涨 = 收益来自次数而非设计。
- **严苛记分**：沙箱崩溃/API 超时记 0 分，不许剔除；所有结果 2 次独立运行取平均。
- **预算对齐**：各方法总 rollout 数一致（进化被约束为每代每任务 1 条轨迹，m=1）。注意：评测不重新采样，pass@1/pass@5 从同一批 5 条轨迹算出，不存在「5×5=25 次」。
- **泛化测试**：89 题切成 45 训练 / 10 验证 / 34 测试；训练集上进化、验证集选代数、测试集报 pass@1。

### 3.3 并行采样 vs 裸测的评测流程对照

| 流程 | 轨迹数 | 谁挑卷 | 测的是什么 |
|---|---|---|---|
| 裸测 pass@1 | 1 | 没得挑 | 单次真实水平（无 pass@5 可言） |
| 并行 pass@5 | 5 条独立 | 不挑，取 max | 轨迹池的覆盖上限 |
| 并行 pass@1（有测试） | 5 条独立 | oracle（测试判词） | 有验证器时的交付质量（恒等于 pass@5，有「开卷」水分） |
| 并行 pass@1（无测试） | 5 条独立 | 自评委 J | 无验证器时的交付质量；J 的准确率是天花板 |

## 四、评测结果

### 4.1 Terminal-Bench 2.1：三个负面结果

模型：Claude Opus 4.6 / GPT-5.4 / GPT-5.4 mini。任务：89 个终端任务。

**① 无单元测试（pass@1，三模型平均）**：

| 方法 | 得分 | 结论 |
|---|---|---|
| 直接采样（裸测） | 68.2 | 基线 |
| 并行采样 | **72.3** | 最稳赢家，三个模型全涨 |
| 串行修订 | 69.3 | 仅 +1.1，GPT-5.4 上负收益 |
| Harness Evolution | 67.4 | **输给裸考**；GPT-5.4 从 75.3 掉到 69.7 |
| Harness Scaling | 71.8 | 接近并行采样 |

原因：无外部对错信号时，自我反馈噪声大，迭代修改会滚雪球式累积早期错误。

**② 有单元测试（三模型平均）**：

| 方法 | pass@1 | pass@5 |
|---|---|---|
| 直接采样 | 67.6 | – |
| 并行采样 | **82.0** | 82.0 |
| 串行修订 | 76.9 | **87.1** |
| Harness Evolution | 69.7 | 79.0 |
| Harness Scaling | 75.5 | 85.6 |

测谎仪判定：进化的 pass@1 几乎贴着裸测（69.7 ≈ 67.6），只有 pass@5 在涨——收益来自多次尝试，不是装备变好。

**③ 留出集泛化（34 道没见过的题，pass@1）**：裸装备 63.2 → 进化后 63.2（**+0.0**）。Claude +1.2、GPT-5.4 持平、mini -1.4。训练题上进化出的收益在没见过的题上一分不剩。

**④ K=10 消融**：趋势不变，更大预算没有翻盘。

### 4.2 定性解剖（附录 A.2）：编辑合理，但记的是小抄

meta agent 的编辑有自然升级路径：**prompt 层**（行为规则）→ **middleware 层**（turn 预算追踪、输出截断、交卷门控）→ **tool 层**（修工具说明、注入恢复提示）。逐条看都合理，但本质是「把这道题的坑记进小抄」（文件路径、命令顺序、已知 bug）——这些信息一个合格 agent 单次 rollout 自己就能重新探索出来；真正的硬伤（深层推理）装备够不着；积累的持久化文本还带来 context bloat。**「memorize fixes ≠ distill strategies」**。

### 4.3 长程游戏：正面反转（v4 新增）

论文给出 harness 进化有效的三条件：**① 足够难有提升空间 ② 分布外需临场适应 ③ 环境自带细粒度可验证反馈**。从工程化程度高的成熟 harness（而非极简 harness）出发进化：

- **ARC-AGI-3**（25 个交互式视觉游戏，RHAE 指标＝通关且计步数对标人类，预算 2000 步）：

| 配置（允许进化的层） | Claude Opus 4.8 | GPT-5.6 Terra |
|---|---|---|
| VISTA*（全冻结，串行修订对照） | 43.3 | 21.1 |
| VISTA（仅记忆进化） | 59.3 | 25.9 |
| full harness（记忆+skills+tools+hooks） | **77.5（+79%）** | **38.2（+81%）** |

- **EdgeBench**（5 个游戏/模拟器任务，12 小时墙钟取最高分）：Harness Scaling 比串行修订高 13.3%（Claude）/ 8.5%（GPT-5.4）。

**层间消融结论：tools > skills > memory >> hooks**：

- 工具主导：Claude 每局写约 11 个工具/调用 132 次；GPT 约 20 个/197 次；工具操作占全部 harness 操作约 85%。写工具一次付费、后续每步摊销受益（frame_diff、link_states、route_markers 等）；个别游戏（tr87：11.8→100）只有能写工具才解得开——瓶颈是感知不是策略。
- 拿到完整 harness 后记忆操作下降 17–24%：知识从散文笔记卸载为可执行 artifact。
- hooks 几乎从不被自发使用（每局 0.2/0.0 次）：事件触发规则是低价值复杂度。

## 五、批判性评价

### 强项

- 问题切得准：matched-budget 基线 + 留出集泛化，是整个自我改进领域普遍欠的债。
- Harness Scaling 探针与 pass@1/pass@5 分解是低成本高信息量的诊断设计。
- 不一棍子打死：给出翻案三条件并在游戏场景验证，结论更可信。

### 弱点

- Terminal-Bench 上只实例化 AHE 一家（且阉割了 explore agent）。
- 预算窗口短（K=5/10）：对「积累型改进」天然不利——积累的收益曲线是凸的，前期平缓，短窗口测不到复利。
- 「Terminal-Bench 对 harness 不敏感」是事后推测，未直接测量 harness sensitivity。
- 游戏场景样本小（EdgeBench 仅 5 任务 × 2 次运行），逐任务方差不小，+80% 无置信区间。
- 有测试设置下 oracle 选择对并行采样极其有利（pass@1=pass@5 有开卷水分）；真实部署参考无测试设置的排名。
- meta agent 改 harness 的推理成本未计入账单（作者明说：计入只会让结论更强）。

### 关于「这算不算 RSI」的争论（讨论纪要）

- **工程上**：分数就是分数，归因不影响部署价值；若生产任务分布稳定，「对搜索集过拟合」甚至是量身定做（参考 RRSI：分布内 +14.1 / 分布外 +4.7，分布内收益是真实可购买的）。
- **科学上**：归因即机会成本——同样的钱并行采样买得更多，这决定下次预算怎么花。
- **定义上**：若「用了历史信号」就算 RSI，则 best-of-N 也算，术语失去区分度。RSI 的强声明需要三个条件：产物持久（平凡满足）、**迁移到新任务**（Terminal-Bench 上实测失败）、改进过程自我改进（未测）。
- **同向之处**：论文自己的正面结果恰恰靠「持久化历史信号」（记忆文件、自写工具）——它不否认这个机制有效，只否认它在无杠杆考场上有效。

## 六、领域地图（自我改进工作的声明 vs 证据）

按「修改对象」分类（配套的二维定位图以 Rethinking 的尺子排位）：

| 类别 | 工作 | 一句话方法 |
|---|---|---|
| 理论构造 | Gödel Machine / SSA 成功故事算法 / 自修改 PAC 理论 | 能证明更优才改（Gödel）；事后清算撤销无益自改（SSA）；PAC 可学习性边界 + Two-Gate 护栏 |
| 改权重 | SEAL / SWE-RL | 模型自写 finetune 数据 + RL 奖励 / 软件演化数据上的规则奖励 RL |
| 改 agent 代码 | DGM / HGM / SICA / AIDE² | archive 开放式演化（SWE-bench 20→50%，但搜索集=评测集）；Gödel 机实用近似；无护栏自改（易被毒化 benchmark 带崩）；外层 agent 改内层，有 held-out 验证（公司自报未复现） |
| 改 harness | RRSI / 本论文 | 正则化演化（critic 筛 benchmark 特化编辑），主动拆分布内/外两本账 |
| 积累经验产物 | Voyager / AlphaEvolve / Weng 综述 | 技能库 / 种群演化 + 自动评估器（有真实部署战果）/ harness 工程综述 |
| 推理时方法（无持久化） | Self-Refine / Best-of-N / 人工改 Prompt | 就是本论文里赢了的那些朴素基线 |

**注意**：定位图的分区是定性判断不是测量结果——Self-Refine 被放入「声明透支区」偏冤（其原始声明很 modest，是被 RSI 叙事追封的）；DGM 有 archive 消融等内部验证，与「人工改 Prompt」同区也偏严。「腾讯飞轮」未检索到可核对的公开论文。

## 七、落地建议汇总

### 7.1 评测体系纪律（可直接移植到平台评测 harness）

1. **等预算基线铁律**：任何「自适应/自优化」组件报告收益时，必须配 matched-budget 的并行采样基线。回答「同样的钱直接多试几次能买多少分」。
2. **搜索集/评测集物理隔离**：reward 信号来源任务集与最终报告任务集分开；参考 45 训练 / 10 验证 / 34 测试切分 + 验证集选型模板。
3. **pass@1 / pass@k 分解做验收测谎仪**：只抬 pass@k 抬不动 pass@1 的机制，本质是给采样次数定价——应与「直接多采样」比成本，而非与单次运行比效果。
4. **严苛记分**：基础设施异常记 0 不剔除；多轮独立运行取平均；报方差。
5. **成本记全账**：meta agent / 评审 agent 的推理成本必须计入，不享受「免费午餐」假设。

### 7.2 做不做 harness 进化的决策筛选器

投入前先过三问（论文正面结果的三个条件）：

1. 任务是否有足够 headroom（现有成功率 <60% 左右，未饱和）？
2. 是否需要临场适应分布外动态（而非稳定已知流程）？
3. 环境是否自带细粒度可验证反馈（不是只有最终对错）？

三条齐备再投；否则预算花在并行采样上更值。另加一个预检：**harness sensitivity 测试**——同一模型换 2–3 个差异大的 harness 跑一批任务，分数方差小的场景说明装备没有杠杆，直接放弃进化路线。

### 7.3 产物沉淀的取舍标准（skill / memory 体系）

- **值得沉淀**：跨任务策略、可执行工具（tools > skills > memory >> hooks 的实证排序）。
- **谨慎沉淀**：单任务可重新探索的信息（命令序列、文件路径、已知 bug 小抄）——节省的是已有能力的时间，且贡献 context bloat。
- **避免建设**：hooks 类事件触发机制（实验中 agent 给了接口也几乎不用）。
- 判据一句话：**如果内容是一个合格 agent 单次 rollout 能自己探索出来的，沉淀价值低；memorize fixes ≠ distill strategies。**

### 7.4 分布内/分布外分开报账

- 平台任务分布稳定时，分布内收益是真实可购买的——不必因「过拟合」污名自我否定。
- 但报账时拆成两个数：**搜索集内收益（分布内 +X）** 与 **留出集收益（分布外 +Y）**，让采购方/上级自己决定为哪个付钱。RRSI 的 +14.1 / +4.7 是现成的话术模板。
- 摊销故事成立的前提是任务分布不漂移：进化搜索成本 ÷ 复用次数 = 单次成本，写进 ROI 测算。

### 7.5 生产环境结论对照

- 无验证器场景参考无测试设置排名：**并行采样（72.3）> 串行修订（69.3）> harness 进化（67.4）**。
- 有验证器场景 oracle 选择的 82.0 有开卷水分，部署时无裁判告诉你哪份答卷对，别直接引用。
- 「多试几次」与「改装备」不是互斥而是互补——进化以轨迹为搜索信号；生产系统可组合：日常用并行采样保底，后台低频跑进化攒装备，定期用留出集验收装备是否还值钱。

## 附：讨论中澄清的关键概念

1. **预算不是 25 次**：并行采样的 5 条轨迹既是候选池也是评测样本，pass@1/pass@5 从同一批轨迹算出；每任务真实开销 = 5 条 × 2 次独立重复运行 = 10 条，四方法一致。
2. **oracle 选择的水分**：有测试时并行采样 pass@1 ≡ pass@5（82.0 = 82.0）不是稳定，是裁判开卷。
3. **裸测没有 pass@5**：一个任务只产 1 条轨迹，「取最好」的分子是空集，论文标「-」。
4. **覆盖上限的含义**：pass@5 衡量 5 条轨迹组成的池子能覆盖多少任务（单任务 0/1，全 benchmark 平均成百分比）；它是任何选择规则的天花板，与 pass@1 围出诊断区间（池子不行 → 加采样/改 harness；选择不行 → 改验证/排序）。
5. **「无测试设置」藏起测试的对象是 agent 不是裁判**：裁判始终用测试打分，所以无测试设置技术上也能算 pass@5，论文不报是因为那边它不对应任何可交付路径。
