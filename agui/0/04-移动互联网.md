# 阶段四：移动互联网、iOS UI 与 Android UI——触控、情境和注意力

## 1. 新技术不只是新输入设备

移动时代的变化同时包括触控、小屏、随身携带、网络、摄像头、位置和通知。Apple 在 2007 年的 iPhone 发布材料中明确介绍了多点触控与手指操作，可作为这一输入转向的事实锚点。[Apple 发布材料](https://www.apple.com/newsroom/2007/01/09Apple-Reinvents-the-Phone-with-iPhone/)

触控缩短手与对象的距离，却降低了精确指向与大量输入能力。小屏要求组织优先级；随身设备创造了更多短时、被打断、与环境有关的交互机会。

## 2. iOS、Android 与共同问题

iOS 与 Android 都形成了组件、导航、手势、权限和通知等设计约定，各自内部持续变化。本文避免把某个旧版本风格当成平台永恒特征。Apple HIG 与 Material 文档可作为当前设计资料入口。[Apple HIG](https://developer.apple.com/design/human-interface-guidelines)；[Material Foundations](https://m3.material.io/foundations/)

| 技术条件 | 常见交互回应 | 对 Agent 的启发 |
|---|---|---|
| 小屏和软键盘 | 渐进展开、少输入、明确主动作 | 语言启动，结构化选项收敛 |
| 手指触控 | 较大目标、滑动、直接反馈 | 指向目标后再表达变化 |
| 摄像头与位置 | 扫描、拍摄、情境服务 | 现实对象成为上下文入口 |
| 持续联网 | 云同步、跨端接续 | 任务不绑在单个界面实例 |
| 通知 | 系统外提醒、快捷动作 | Agent 主动提出待决策事项 |
| 系统权限 | 访问资源时请求许可 | 授权要表达用途、范围和期限 |

表中为分析性映射，不表示现有系统已提供完整 Agent 能力。

## 3. 语言在移动端有更强动机，也有更强限制

语音减少打字负担，但受噪声、隐私、社交场合、识别错误和设备延迟影响。用户也未必愿意听完整报告。一个合理探索方向是多模态互补：拍摄、圈选、短语音输入、视觉确认、轻量修改。

例如用户拍一张设备异常照片，说“记录这个问题并对照上次维修”。界面应显示识别出的设备身份，让用户一触修正；资料来源和草稿随后出现。若设备无法可靠识别，界面需要让用户选择，不能用流畅文字掩盖身份错误。

## 4. 通知可能变成新的 Agent 主界面

长期任务无需一直占据屏幕。Agent 可以在完成、阻塞或需要决定时提醒人。真正的问题是如何判断值得打断，而非如何发出更多通知。

**假设 A**：未来 Agent 的重要界面可能是“待处理决定”，而非完整对话历史。任务本体在后台，用户在通知或收件箱中确认局部问题。

**反例**：用户必须了解大量前因后果，简短通知导致草率判断；多个 Agent 各自推送制造新的注意力过载。

**假设 B**：通知可以聚合为同一工作对象下的决策摘要，而非每次工具调用都通知。失败条件是聚合太多，掩盖时效与依赖。

## 5. 跨端分工而非跨端同构

桌面适合大规模比较、复杂编辑和审查；手机适合采集、简短确认与现场信息。两端不一定渲染相同界面，但应绑定同一任务与产物版本。

场景：桌面上启动分析；手机补充现场照片；Agent 产出候选解释；桌面并列检查证据；手机接收“需要补一项设备参数”的请求。跨端延续的是工作状态，不是把长聊天缩成小屏。

## 6. 手势与语言如何结合

手势擅长指称：这个、这些、这里。语言擅长关系与目标：按照什么规则、为了什么目的、哪些例外。两者结合可能降低语言歧义。

但交互时间需明确定义：先选后说与边说边选是否相同？语音识别完成时选区已经改变怎么办？UI 可以把提交时绑定的对象以小卡片保留，便于纠错。

## 7. 主动 Agent 的边界是可见性

用户可能接受系统在后台整理材料，却不接受它未经明确委托对外发送。移动权限弹窗告诉我们资源访问需要表达；但“可以使用麦克风”与“可以代表我承诺交付日期”是完全不同的授权。

可探索的委托界面包含：允许做什么、针对哪些对象、多久有效、何时必须回来询问、如何关闭。它不能只展示一个“自动模式”开关。

## 8. 尚未决定的方向

移动 UI 会更像对话助手，还是系统级动作入口？AI 能否让权限和设置更容易理解，还是让用户更少检查？可穿戴设备可能扩大语音和现场交互，但小屏与低打扰约束也更强。代理任务越多，手机可能越像决策终端；也可能因为需要验证而重新增加查看时间。

可以先测量：每任务打断次数、一次通知能否解决问题、跨端状态丢失率、误确认率、用户为了理解通知回到主应用的次数。
