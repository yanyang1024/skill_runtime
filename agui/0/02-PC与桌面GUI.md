# 阶段二：PC、桌面 GUI、Windows 与 macOS——对象、空间和直接操作

## 1. 技术条件的改变

个人计算、位图显示、鼠标、本地存储与打印，使用户可以持续观察和操作屏幕中的对象。Computer History Museum 对 Xerox Alto 的介绍记载了鼠标、视觉界面和所见即所得等要素的组合；这里以此为事实锚点，不将 GUI 的历史归因于单一产品。[CHM：Xerox Alto](https://www.computerhistory.org/revolution/input-output/14/347)

GUI 的关键变化可以理解为：让系统状态在操作前后可见，让用户在结果附近直接改变结果。文件夹、窗口、工具栏和选区，给大量操作提供共同的定位方式。

## 2. Desktop UI 与平台风格

Desktop UI 是一类使用环境；Windows 与 macOS 是平台及其生态；WinUI 是 Windows 应用的 UI 技术之一，不能代表全部 Windows 界面。两大平台内部也存在传统桌面应用、现代应用、自定义画布和跨平台框架。

| 观察对象 | 常见设计倾向，非排他特征 | 对交互的作用 |
|---|---|---|
| Windows 桌面应用 | 多窗口、菜单、上下文操作、丰富企业工具 | 支撑多任务与复杂配置 |
| macOS 桌面应用 | 文档操作、系统菜单和快捷键、平台一致性 | 让熟悉习惯跨应用迁移 |
| 专业桌面工具 | 时间线、画布、图层、参数面板、精确选择 | 把领域对象变为可操作模型 |
| 跨平台桌面应用 | 统一产品布局与平台适配并存 | 降低开发成本，也可能损失平台习惯 |

这些是分析性概括，不是平台能力排名。Apple HIG 和 Windows 设计文档都覆盖布局、输入和可访问性等主题。[Apple HIG](https://developer.apple.com/design/human-interface-guidelines)；[Windows 设计指南](https://learn.microsoft.com/en-us/windows/apps/design/)

## 3. GUI 为什么没有被语言完全替代

看见选项可以降低回忆负担；连续反馈可帮助用户探索；空间关系能表达语言难以简洁表达的差异。把一个图形向左拖动三毫米，比输入一句模糊指令更直接。批量比较十个方案时，视觉并列也比十段对话更容易。

但 GUI 同样有缺陷：操作路径长、菜单难找、重复劳动多、跨应用流程不易组合。这正是 Agent 可以填补的空间。

**假设**：语言适合描述跨对象的变化意图，直接操作适合指向对象并修正局部；二者结合可能比全语言更稳。

例如在版图或报表中框选区域，再说“让这里采用上面那一组的规则”。表达由语言承担，指称由选区承担，效果由画布承担。模型无需从整屏猜测“这里”是什么。

## 4. 从视觉隐喻到共同对象

在人机共同编辑中，重要问题可能从“按钮摆哪里”转为“人和 Agent 是否指向同一对象”。

- 用户当前选择哪个实体、哪一版本？
- Agent 读到的是已保存状态，还是包含未保存修改的状态？
- Agent 提议修改对象时，人是否还能同时操作？
- 用户改变选区后，刚才的语言指令绑定旧选区还是新选区？

一个可能的约定是：提交指令时冻结对象引用与版本；执行前若版本变化，再协商或重算。这是设计建议，不是各类 GUI 已有的通用标准。

## 5. 直接操作能否扩展为“直接操纵委托”

过去拖动的是文件；未来也许可以拖动任务的边界。比如把某份资料拖进任务卡片，表示纳入本次分析；把一个结果拖出，表示独立成新任务；给产物上的一句话标注“这条前提不成立”，使依赖它的结论失效。

此类交互的价值在于把抽象约束变成可指向对象。但如果依赖关系是模型臆测的，精致界面反而可能制造虚假的精确性。界面需要区分真实数据依赖、人工指定关联与模型推测关联。

## 6. Undo 在 Agent 时代的问题

GUI 的撤销帮助人放心探索。Agent 的“撤销”涉及更广：文件变更可能回滚，已发送通知、已触发制造流程或已经消耗的资源不能简单逆转。

可以思考分开显示：停止新操作、撤回尚未提交的提案、恢复可回滚的对象、对外部效果执行补偿。不要把它们都叫“撤销”。如果任务包含多个系统，界面上的一个按钮必须有实际能力依据。

## 7. 可能的桌面原生模式

1. **对象旁助手**：Agent 在当前文档或画布附近工作，默认范围由选区给出。
2. **差异预览**：先展示可编辑变化，再提交，适合代码、配置和文档。
3. **双人编辑感**：显示 Agent 操作对象的范围，而非每个鼠标轨迹。
4. **命令面板增强**：输入语言，匹配现有动作，必要时组合多个动作。

当前 PowerToys Command Palette 提供应用、命令、文件等统一入口，是键盘工作流的现实例子；它本身不是本文设想的通用 AI 委托系统。[Microsoft 文档](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/overview)

## 8. 反向思考

如果专业用户每天重复同一精确操作，稳定按钮可能比语言快得多。如果界面每次生成不同布局，会破坏肌肉记忆。如果 Agent 太主动，用户可能丢失对编辑状态的掌控。新的设计或许需要稳定骨架，仅允许局部适配。

开放问题：未来最重要的“桌面”是应用窗口集合，还是围绕同一项目的对象集合？Agent 是否能减少窗口切换而不取消专业工具？能否建立人和 Agent 共享的选区、版本与修改协议？
