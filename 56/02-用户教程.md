## 第 0 章：通用生存法则

在打开任何一个工具之前，先养成四个习惯：

1. **git 是后悔药**。让 agent 动手前先 `git commit`（或在干净分支上工作）。agent 改错了，`git diff` / `git checkout` 比任何撤销功能都可靠。
2. **小任务起步**。第一次用任何工具，先给一个只读任务（"读一下目录结构，告诉我有哪些文件，不要修改"），验证密钥、工作区、权限都正常，再给真实任务。
3. **审批弹窗要看内容**。无脑点 allow 等于关闭权限系统。把高频安全命令配进 allowlist，让 ask 只出现在异常场合。
4. **写 AGENTS.md**。五家都认这个文件（行业公约），在里面写清项目约定：技术栈、测试命令、目录规范、禁区。一次编写，所有工具受益。

任务描述的最佳实践：

```
❌ "优化一下代码"
✅ "给 src/api/users.ts 的列表接口加分页，保持现有查询参数兼容，
    改完跑 npm test，有失败先报告别乱改"
```

好的任务描述 = 明确目标文件 + 明确验收标准（跑什么测试）+ 明确边界（别动什么）。

## 第 1 章：Claude Code

### 1.1 适合谁
愿意付订阅费、追求最省心完整体验的用户。绑死 Claude 模型。

### 1.2 安装与登录

```bash
npm install -g @anthropic-ai/claude-code
cd your-project
claude
```

首次启动引导你用 Claude 账号登录（Pro $20/月 起；免费版 Claude.ai 不含 Claude Code）。

### 1.3 日常用法

- 直接对话布置任务；`/init` 生成 AGENTS.md（CLAUDE.md）
- **plan 模式**：先让它出计划再动手，复杂任务必用
- `/permissions` 管理权限规则

### 1.4 权限与安全配置

`~/.claude/settings.json` 或项目级 `.claude/settings.json`：

```json
{
  "permissions": {
    "allow": ["Bash(npm run test *)", "Bash(git status)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Bash(rm -rf *)", "Read(./.env*)"]
  }
}
```

要点：**deny > ask > allow，与规则具体度无关**。配错不会报错，只是不生效——配完用一条命令实测。

需要更强拦截时用 **hooks**（PreToolUse 可在工具执行前阻断，exit 2 直接拦停），这是 CC 独有的第二道防线。

### 1.5 省钱技巧

- 简单任务切小模型（`/model`），不要全程旗舰
- 长会话主动 `/compact`，或在自然节点开新会话
- 大文件别让它全读，任务里指定行范围/关键词

### 1.6 坑点速查

| 症状 | 原因 | 解法 |
|---|---|---|
| 行为突然变了（比如不爱用专用工具） | 服务端 feature flag 灰度 | 先怀疑 flag，更新/回退版本验证 |
| deny 了 `.env` 还是被读到 | deny 被替代路径绕过 | 密钥文件别依赖 denylist，用 hooks 或移出工作区 |
| 权限规则不生效 | 优先级是 deny>ask>allow 与具体度无关 | 检查是否被另一条 deny 覆盖 |
| 想在 opencode 里用 Claude 订阅 | 2026.1 起被官方封锁 | 只能用按 token 计费的 API Key |

## 第 2 章：Codex CLI

### 2.1 适合谁
ChatGPT 订阅用户（一键开箱）、需要无人值守/自动化跑任务的人（沙箱最硬）。

### 2.2 安装与登录

```bash
npm install -g @openai/codex
cd your-project
codex        # 用 ChatGPT 账号登录，或 export OPENAI_API_KEY=...
```

### 2.3 核心概念：沙箱 × 审批 双轴

这是用 Codex 最该理解的东西：

- **沙箱模式**：`read-only`（只读）/ `workspace-write`（只能写工作区）/ `danger-full-access`（裸奔，别开）
- **审批策略**：`untrusted` / `on-request` / `never`

推荐日常组合：`workspace-write` + `on-request`。无人值守任务：**保持沙箱开着**，审批可以放宽——沙箱是构造性隔离，agent 跑 `rm` 也出不了边界。

### 2.4 日常用法

- `/review`：不动工作区做代码评审
- `/import`：一键导入 Cursor / Claude Code 的配置和 MCP
- `codex exec "任务"`：非交互模式，适合 CI 脚本

### 2.5 接第三方模型（进阶）

`~/.codex/config.toml` 加 `[model_providers.<id>]` 块。**注意：只支持 Responses API**（`wire_api = "chat"` 已移除，写错直接启动报错）。你的网关必须支持 Responses，否则没戏。

### 2.6 坑点速查

| 症状 | 原因 | 解法 |
|---|---|---|
| 接第三方网关启动报错 | `wire_api="chat"` 已废弃 | 改 `responses`，网关不支持就换 |
| 换非 OpenAI 模型后编辑全失败 | apply_patch 是 OpenAI 私有格式 | 第三方模型需确认支持该格式 |
| 长日志看完还是答错 | 10KB/256 行硬截断，无回读 | 让它把日志写文件，分段读 |
| Windows 上沙箱不生效 | OS 沙箱主要是 macOS/Linux | 用 WSL |

## 第 3 章：opencode

### 3.1 适合谁
想要模型自由（比价、国产模型、本地模型）、喜欢开源生态的用户。软件免费，模型费自理。

### 3.2 安装

```bash
# 任选其一
npm install -g opencode-ai          # Node
curl -fsSL https://opencode.ai/install | bash
brew install anomalyco/tap/opencode # macOS/Linux
scoop install opencode              # Windows
```

界面三种：终端 TUI（主力）、桌面 App、VS Code 等 IDE 插件。

### 3.3 首次配置

```bash
cd your-project
opencode
# TUI 里 /connect 添加 provider（粘贴 API Key）
# /model 选择模型；/init 生成 AGENTS.md
```

模型选择建议：
- 复杂重构/架构推理 → 旗舰模型（Claude / GPT 旗舰 / Gemini Pro）
- 简单重构/批量改名 → 便宜的轻量模型
- 代码不能出本机 → Ollama 本地模型（`ollama pull qwen2.5-coder:32b`）

### 3.4 两个内置 Agent

- **build**（默认）：完整读写权限
- **plan**：只读，改文件前需确认——按 **Tab** 切换

### 3.5 权限配置（装完必做！）

opencode **默认宽松**，不配权限约等于全自动放行。`opencode.json`：

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "npm run test *": "allow",
      "rm -rf *": "deny",
      "git push *": "ask"
    },
    "edit": {
      "*": "allow",
      ".env*": "deny",
      "../*": "deny"
    }
  }
}
```

规则要点：三态 `allow`/`ask`/`deny` + glob，**last-match-wins**（后面的覆盖前面的，和 CC 相反！）；`edit` 一个键同时管 write/edit/patch。另有两个内置防呆：同一调用重复 3 次自动拦截（doom_loop）、项目外路径默认 ask。

### 3.6 省钱技巧

- 软件本身免费，花钱的是模型：简单任务切便宜模型，可省一个数量级
- OpenCode Go（$10/月）适合不想管 Key 的人；Zen 按量付费适合多模型切换
- 本地 Ollama = 零 API 成本

### 3.7 坑点速查

| 症状 | 原因 | 解法 |
|---|---|---|
| agent 陷入死循环重复同一操作 | doom_loop 会拦，但禁用了工具时截断提示会指向不存在的工具 | 禁用 Grep/Read 时注意连带影响 |
| allow 的命令干了坏事 | 无 OS 沙箱，只查命令字符串 | 高风险项目跑容器/VM |
| Claude 订阅登录失败 | Anthropic 已封锁第三方用订阅 | 用 API Key（按 token） |
| 小模型 tool-calling 翻车 | 非主流 provider 路径打磨不一 | 关键任务用主流模型 |

## 第 4 章：pi

### 4.1 适合谁
想"拥有自己的 harness"的高级用户：极简内核（只有 read/write/edit/bash），一切功能靠扩展。不适合想要开箱即用全家桶的人。

### 4.2 安装与登录

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
# 或
curl -fsSL https://pi.dev/install.sh | sh

cd your-project
pi
```

认证：`/login`（订阅 OAuth：Claude Pro/Max、ChatGPT、Copilot 都支持）或环境变量 API Key。支持 15+ provider，`/model` 或 `Ctrl+L` 切换。

### 4.3 日常用法

- 树状会话：`/tree` 回退/分叉，`/export`、`/share` 分享
- 工作中插话：`Enter` 发 steering（当前工具执行完立即插入），`Alt+Enter` 发 follow-up（等干完再说）
- 脚本模式：`pi -p "任务"`（print 模式），`--mode json` 拿事件流

### 4.4 扩展（pi 的灵魂）

没有的功能力自己装或自己造：

```bash
pi install npm:@foo/pi-tools          # 从 npm 装包
pi install git:github.com/badlogic/pi-doom
```

子代理、plan mode、权限门、MCP 全是第三方扩展。也可以直接**让 pi 给自己写扩展**，改完 `/reload` 生效——"让 harness 适应你，而不是你适应 harness"。

### 4.5 安全（重点！）

**pi 的 bash 没有任何权限层，以你的完整权限裸奔。** 官方答案就是自己隔离：

| 方案 | 隔离级别 | 说明 |
|---|---|---|
| Gondolin 扩展 | 工具进本地微 VM | 改动经 /workspace 写回宿主机 |
| Docker | 整个进程进容器 | 最简单，注意 API Key 会进容器 |
| OpenShell | 策略沙箱 | 文件/进程/网络/凭据全维度策略 |

不理解的任务，绝不在宿主机直接跑。

### 4.6 坑点速查

| 症状 | 原因 | 解法 |
|---|---|---|
| grep/find 首次使用卡住 | 自动下载 ripgrep/fd 二进制 | 离线环境提前装好这两个工具 |
| "为什么没有 plan mode" | 设计如此 | 装扩展或让它用文件管理计划 |
| 长会话后"失忆" | compaction 把工具结果截到 2000 字符 | 关键状态让它写进文件 |

## 第 5 章：dsh（DeepSeek Harness）

### 5.1 适合谁
DeepSeek 模型用户、做 agent 评测/行为研究的人、喜欢 Web UI 的人。**注意：v0.1 开发者预览，会有 breaking change。**

### 5.2 安装与启动

```bash
# 零安装体验
npx @deepseek-ai/dsh web
# 或全局安装
npm install -g @deepseek-ai/dsh && dsh web
```

要求 Node.js **22.19+ 或 24+**。浏览器自动打开 `http://127.0.0.1:3080`。不想装 Node 的 Windows/mac 用户可下载 **DSH Desktop** 桌面版。

### 5.3 首次运行三步

1. **Settings → Models** 填 DeepSeek API Key（存在本地 `~/.dsh/.credentials.yaml`）
2. **添加 workspace**——必须显式选择项目目录，选之前会话不可用（这是安全设计：先声明"允许动哪些文件"）。第一次建议新建空的练习目录，别选主目录/下载目录
3. 发一个小任务验证链路

### 5.4 四个预设怎么选

| 预设 | 适用 |
|---|---|
| **Standard** | 默认，日常开发就用它 |
| **PTC** | 重复性多步任务：模型写程序编排工具调用，缓存命中率约 99%，极省 token |
| **Minimal** | 跑基准评测：固定 prompt、只留 bash + 编辑器，冻结 harness 变量 |
| **Creation** | 开发插件/预设时用，可运行时挂载卸载插件（等同 shell 级权限，慎开） |

权限三档：`read-only`（默认）/ `workspace-write` / `danger-full-access`（**别开**，沙箱审批一起关，没有第二道防线）。

### 5.5 特色功能

- **Trajectory 视图**：append-only 完整事件流，可 fork 重跑——调试 agent 行为的利器，尽早学会
- **headless 模式**：`dsh --profile headless "fix the failing test"` 一次性任务，适合脚本
- 可把 Claude Code 和 Codex 当子代理调用

### 5.6 坑点速查

| 症状 | 原因 | 解法 |
|---|---|---|
| npm 装不上/起不来 | Node 版本不对 | 换 22.19+ 或 24+ |
| WSL 下文件策略不生效 | 已知问题，bash 可跑出 Windows ACL 沙箱 | 避免 WSL，用原生 Linux |
| 想远程访问 Web UI | 只绑 localhost | 自己加反向代理+认证 |
| PTC 任务结果诡异 | 依赖模型代码规划能力 | 换 Standard 逐步执行对比 |

## 第 6 章：故障自查清单

遇到问题按这个顺序查：

1. **模型层**：Key 有效吗？余额够吗？这个模型支持工具调用吗？
2. **权限层**：是不是被自己的 deny 规则/审批策略拦了？（CC 看 settings.json，opencode 看 permission 块，Codex/dsh 看沙箱模式）
3. **上下文层**：会话是不是太长/读了太多大文件？开新会话试试。
4. **工具层**：
   - CC：最近行为变了？怀疑 feature flag 灰度
   - Codex：编辑失败？是不是第三方模型不认 apply_patch
   - opencode：死循环？是不是禁用了被截断提示引用的工具
   - pi：grep/find 没反应？ripgrep/fd 装了吗
   - dsh：先看 Trajectory 视图回放到底哪步出了问题
5. **环境层**：Node 版本、WSL、网络代理。

最后记住：**所有 agent 都会犯错，git diff 是你永远的朋友。**
