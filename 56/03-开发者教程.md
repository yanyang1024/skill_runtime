## 一、五家架构速览

| | opencode | pi | Codex | Claude Code | dsh |
|---|---|---|---|---|---|
| 语言 | TypeScript/Bun | TypeScript | Rust | 闭源（JS bundle + 原生二进制） | TypeScript（Cordis 内核） |
| 架构 | client-server（server 持有 agent loop + 工具执行，TUI/IDE 只是客户端） | 单进程极简 | 单进程 + OS 沙箱边界 | 闭源二进制 + 服务端 feature flag | 插件内核，一切皆插件 |
| 仓库 | `anomalyco/opencode` | `earendil-works/pi` | `openai/codex` | — | `deepseek-ai/deepseek-harness` |

关键认知：**四家的工具面都收敛到同一最小集**——读文件、写文件、改文件、跑命令四个原子能力，靠组合覆盖一切。差异全在实现细节、安全边界和扩展点上。

## 二、工具层实现对比

### 2.1 edit：四家流派，全部放弃行号定位

行号在文件变动后不可靠是行业共识，四家各选了一种锚定方案：

| 流派 | 使用者 | 机制 | 取舍 |
|---|---|---|---|
| 字符串替换 | opencode、Claude Code、dsh（`str_replace_editor`） | search-and-replace，文件被改后仍能工作 | 可靠；需处理多匹配歧义 |
| diff 匹配 | pi | 基于 npm `diff` 包 | 实现简单，复用成熟组件 |
| V4A patch | Codex | 自定义 diff 格式，`Add/Update/Delete File` 三操作顺序应用 | **原子、可审计、可逐 patch 审批**；但格式私有、有解析 bug、对前导缩进敏感 |

附加契约：
- **read-before-write 账本**：CC、opencode、dsh 要求先 Read 才能 Edit，防止基于过期快照盲改；pi 和 Codex 无此约束
- **文件状态校验**：CC 在 read 后文件被外部改动时 edit 失败——多会话并发改同一文件场景有价值
- Codex 的 apply_patch **不在 function schema 里**，是系统提示词定义的"虚拟 shell 命令"，CLI 拦截后绕过真实 shell 走内部处理——省 schema 和 token，但换模型可能不认这套私有协议

### 2.2 bash：安全投入的主战场

文件工具的路径校验相对好做，bash 任意命令才是真正的攻击面，各家差异化投入全砸在这里：

| | 机制 | 边界强度 |
|---|---|---|
| Codex | OS 级沙箱：macOS Seatbelt / Linux Landlock+seccomp，iptables 限出口 | ★★★★★ 构造性隔离 |
| dsh | bwrap 优先、Landlock fallback（预编译二进制随 npm 包分发），默认 read-only | ★★★★★ 内核级拒绝 |
| Claude Code | 权限规则（三列表）→ PreToolUse hooks（exit 2 阻断）→ 可选 OS 沙箱，三层纵深 | ★★★★ 纵深最深 |
| opencode | tree-sitter 解析命令做权限匹配（比字符串匹配更能识别伪装），**无 OS 沙箱** | ★★ 进程内策略 |
| pi | **无防护**，以用户完整权限直跑 | ☆ 安全外包给运行环境 |

**分层共识：进程内权限规则（快、可读）+ OS 级沙箱（硬边界）缺一不可。** 只检查命令字符串的检查器，对"名不副实的命令"（脚本里藏 `rm`）无能为力。

### 2.3 read/write

- opencode：统一截断保护（2000 行/50KB，单行 2000 字符），超限全文落盘 tool-output store，返回 preview + `outputPath` 供按需回读
- CC：双闸门——读前 stat 预检 256KB，读后 25,000 token 二次预算检查（阈值走 GrowthBook 远程可调）
- Codex：无专用 read 工具，靠 shell 里 `cat`/`sed`/`rg`；截断 10KB/256 行硬截断**无回读**——收敛工具面的代价
- pi：绝不返回半截行（防模型把不完整 JSON 当完整结构引用）

## 三、工具设计 Trick 箱

这些是从五家实现里提炼的、可直接复用的设计模式，按投入产出排序：

### 3.1 上下文预算治理：lossy on model, lossless on disk

1. **截断 + 全文落盘回读**：超限内容写本地文件，返回 preview + 路径 + 回读方法。可以收敛工具面，但**截断必须可逆**（Codex 的硬截断是反面教材）。
2. **截断提示即导航**：`[Showing lines X-Y of Z. Use offset=N to continue]`。⚠️ 提示内容必须校验目标工具实际可用——opencode 曾有 bug：截断提示建议模型用被禁用的 Grep，导致无解死循环。
3. **截断方向语义化**：bash 保 tail（错误信息在末尾），read 保 head（结构在开头）。
4. **绝不返回半截行** + **空文件返回显式 reminder 而非空串**：两个一行代码级 trick，消除一大类模型幻觉诱因（空串会让模型怀疑文件不存在或工具坏了）。
5. **重复读取去重 stub**（CC）：模型重读同一未变文件时返回 stub，针对"失忆重读"的定向优化。

### 3.2 工具描述即提示词工程

工具 description 是 system prompt 的一部分：
- opencode 在 read 描述里写"鼓励推测性批量并行读多个文件"
- **错误消息也要 prompt-engineer**：模型是错误消息的消费者，校验失败的报错要给出具体可操作的改进建议，而非 opaque error code；traceback 是给人看的
- offset 越过 EOF 返回提示而非报错——把无害边界情况从 error 降级为 note，避免模型无谓重试

### 3.3 防错与验证

- **doom_loop 哨兵**（opencode）：同一工具以相同输入连续调用 3 次即拦截。零 LLM 成本的防死循环设计
- **编辑内嵌验证信号**（dsh `dsh-tool-edit` 插件）：edit 落盘后接 LSP，把 `N error(s), M warning(s)` 直接附在 edit 返回值里——"编辑→编译检查"两步合一，失败时静默降级不阻塞编辑
- **external_directory**（opencode）：项目外路径默认 ask

### 3.4 调用层

- **PTC 代码编排**（dsh）：多步工具调用压成一次 `run_code`，中间数据留在 Worker Thread 不进上下文，缓存命中率常达 99%。注意 Worker Thread 官方定义为 "containment, not a security boundary"
- **子代理扇出**（CC/opencode）：opencode 的截断提示会引导模型把大文件交给 explore 子代理——截断提示同时是编排引导
- **compaction 时工具结果单独降级**（pi）：序列化总结时每个 tool result 截到 2000 字符——所以持久状态必须写 checkpoint 文件，不能信 summary

### 3.5 Trick 覆盖速查

| trick | opencode | pi | Codex | CC | dsh |
|---|---|---|---|---|---|
| 截断+落盘回读 | ✅ 混合式 | ✅ 无半截行 | ❌ 硬截断 | ✅ 双闸门 | 插件化 |
| read-before-write | ✅ | ❌ | ❌ | ✅+状态校验 | ✅ |
| 编辑内嵌验证 | ❌ | ❌ | diff 审批 | ❌ | ✅ LSP |
| 防死循环 | ✅ doom_loop | ❌ | ❌ | hooks 可配 | 插件可配 |
| 远程调参 | ❌ | ❌ | ❌ | ✅ GrowthBook | ❌ |
| 代码编排 | ❌ | ❌ | ❌ | 子代理 | ✅ PTC |

## 四、扩展机制对比与二开入门

### 4.1 扩展点对比

| | 扩展机制 | 粒度 | 适合 |
|---|---|---|---|
| Claude Code | hooks（PreToolUse/PostToolUse）+ MCP + 插件 | 工具调用前后拦截 | 运行时自定义拦截、企业策略 |
| Codex | 配置 + MCP | 有限 | 不适合深度二开，适合用 |
| opencode | 开源，直接改源码；MCP/Skills | 全量 | 有 TypeScript 能力的团队 |
| pi | TypeScript 扩展（工具/命令/快捷键/事件/整个 TUI）+ 包分发（npm/git） | 全量，但靠组合 | 个人打造专属 harness |
| dsh | Cordis 插件：模型适配器、工具、沙箱、审批、loop、UI 全平级 | **最彻底**：agent loop 本身也是插件，关键节点是 waterfall 事件 | 重构整个 harness 行为 |

### 4.2 pi 扩展入门

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

扩展是 TypeScript 模块，可访问工具、slash 命令、快捷键、事件和完整 TUI。仓库自带 50+ 示例。工作流：

1. 在 `~/.pi/agent/extensions/` 写扩展（或直接让 pi 给自己写）
2. `/reload` 热加载
3. 打包成 Pi Package 发布：`pi install npm:@foo/pi-tools` / `pi install git:...`

底层包可独立复用：`pi-ai`（统一 40+ provider 的 LLM API）、`pi-agent-core`（agent 循环 + 工具调用）、`pi-tui`（差分渲染终端 UI）——自研 harness 可以直接站在这些组件上。四种运行模式：交互 TUI、`pi -p` print/JSON、stdin/stdout JSONL 的 RPC、SDK 嵌入。

### 4.3 dsh 插件入门

```bash
git clone https://github.com/deepseek-ai/deepseek-harness
cd deepseek-harness && pnpm install && pnpm run build && pnpm dsh web
```

monorepo 分 `apps/`（cli、web）和 `packages/`（core、llm、mcp、sandbox、context、plan、goal 等）。二开姿势：

- **换工具/沙箱/loop**：配置层卸载/替换插件，不用 fork
- **写拦截逻辑**：agent loop 的关键节点（模型请求前、工具执行前、轮次结束）都是 waterfall 事件，写个插件监听即可拦截改写，不碰 loop 代码
- **参考实现**：`dsh-tool-edit`（edit 前后接 LSP）、`dsh-sandbox-policy`（spawn 前包裹命令行）
- **评测场景**：Minimal 预设的 `agent.cordis.yml`（固定 system prompt、关上下文压缩、`includeRuntimeContext: false`）是"受控 harness"模板——冻结全部 harness 变量，让评测只度量模型差异

⚠️ v0.1 预览版，API 会有 breaking change；WSL 下沙箱有已知问题。

### 4.4 opencode 二开

工具代码集中在 `packages/opencode/src/tool/`：`tool.ts`（基类）、`registry.ts`（注册表）、`truncation.ts`（统一截断）。client-server 架构意味着工具在 server 端执行、权限请求经 HTTP+SSE 流回 UI——写新工具要同时考虑权限事件流。权限系统是 capability 抽象：`edit` 一个 key 覆盖 write/edit/patch 三工具，设计自家权限时值得借鉴（策略不易漏配）。

### 4.5 Claude Code hooks 示例

`.claude/settings.json`：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "/path/to/guard.sh" }]
      }
    ]
  }
}
```

`guard.sh` 从 stdin 读工具调用 JSON，exit 2 阻断（优先于 allow 规则），exit 0 放行。这是企业侧注入自定义策略（如"禁止访问生产凭据路径"）的通用扩展点。

## 五、自研 Harness 设计清单

如果你要造自己的 agent 运行时，从五家身上直接搬这些：

**工具面**
- [ ] 收敛到读/写/改/跑四个原子能力，edit 用字符串锚点或 patch，绝不用行号
- [ ] read-before-write 账本 + 文件状态校验
- [ ] 截断三件套：全文落盘可回读 + 可行动提示（校验目标工具可用）+ 方向语义化（bash 保 tail / read 保 head）
- [ ] 绝不返回半截行；空文件返回显式 reminder
- [ ] 错误消息写给模型看：具体、可操作、指向下一步

**安全边界**
- [ ] 双层：进程内权限规则（deny 优先三列表）+ OS 级沙箱（bwrap/Landlock/Seatbelt）
- [ ] 默认从严（read-only），放权要显式
- [ ] doom_loop 式防死循环哨兵（零 LLM 成本）
- [ ] 项目外路径默认 ask
- [ ] 沙箱 fallback 做成预编译二进制随包分发（dsh 的 Landlock 打包手法，消除用户侧编译依赖）

**可观测性**
- [ ] append-only 事件流：记录模型看到的每一帧（system prompt、推理、工具调用），支持 fork/replay——比事后从 session 日志挖信号高一个维度
- [ ] 编辑后内嵌验证信号（LSP 诊断或等价物），把验证融进工具返回，天然产出结构化成败轨迹
- [ ] 结构化工具调用优于裸 bash：Read/Edit 是结构化事件，cat/sed 不是——做行为分析时你会感谢这个区分

**编排**
- [ ] 多步任务提供代码编排路径（PTC 式），中间数据不进上下文
- [ ] compaction 时工具结果单独降级；提示用户/模型持久状态走 checkpoint 文件

**行业趋势判断**：opencode/pi 在收敛工具面，Codex 在收敛编辑语义（patch），Claude Code 在加深纵深防御（且灰度测试"Bash 优先"向收敛靠拢），dsh 在把整个 harness 变成插件市场。专用工具相对裸 bash 的价值不在能力，而在**可观测性和权限粒度**——这是你做工具面取舍时的核心判据。
