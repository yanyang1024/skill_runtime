# Web Agent Rebuild

把已有业务能力接入恰当的语言与 Agent 交互，完成可运行的改造。以原任务的完成成本、可核对程度和现有用户习惯决定改造范围。

## 1. 建立功能基线

- 读取项目约束、启动入口、依赖、路由、模板、前端事件、业务服务和相关测试。先识别实际框架与版本，沿用项目的运行方式；不要为增加 AI 更换框架。
- 先用 `rg` 定位入口。需要梳理较多 Python 路由和 HTML 表单时，运行 `scripts/inspect_web_project.py PROJECT_ROOT`。将输出视为静态候选，继续追踪实际注册、模板继承、JS 请求和业务调用。
- 按 [discovery-and-migration.md](references/discovery-and-migration.md) 追踪至少一条主路径和一个错误路径，形成“用户动作 → 页面 → 接口 → 业务函数 → 数据/权限/副作用”的地图。未知项标明未知，不凭界面猜测业务。
- 优先从项目和提供材料补齐问题；只询问会改变业务语义、授权范围或实现路径的缺口。源码缺失时可先完成界面建议与待接接口，不能声称已经理解或兼容未见实现。
- 运行可用的原功能基线。依赖、内网或数据不可达时采用隔离样例，明确真实路径未验证；不要因此停下能独立完成的改造。

## 2. 选择改造切入点

阅读 [interaction-patterns.md](references/interaction-patterns.md)，先判断旧页面承载的是明确任务 A、探索任务 B，还是两者的连接；再选最小有效模式：候选表单、结果解释、动作提案，或围绕产物的任务工作台。

A/B 是帮助观察任务与选择交互的视角，不是必须实现的两套固定页面或 Agent 架构。比较填报、核对、纠错与探索的总成本，根据真实使用反馈调整入口。

- 先复用现有领域对象、字段校验、业务服务和身份上下文。让人和 Agent 调用同一业务规则，避免两个入口产生不同计算口径。
- 对 A，让人主要验证、选择和改写 AI 提议的条件；可从当前记录、已授权数据库、历史操作和个人偏好生成候选，解释原值与建议依据、提示异常变化、比较多种候选。把来源、有效时间和未确定项与字段一起呈现，不能用推荐绕过原有校验与权限。
- 对 B，保留目标、探索动作、证据及例外。识别重复出现且可验证的路径，把成熟片段沉淀成 A；新的例外可以回到 B。若沉淀的场景太多，设计能澄清并路由到各个明确任务的统一入口，同时保留可见的任务选择与当前范围。
- 为语言入口定义明确的作用对象：当前表单、选中记录、当前报告或当前任务。空泛聊天框不构成完成的业务改造。
- 展示模型建议与将发生的变化；按实际影响决定是否需要业务确认。常规查询和用户已授权动作可直接执行，不把所有步骤做成审批。
- 对开放任务，允许以目标启动，再在必要阶段出现结构化条件、证据、结果和下一步动作。不要强制每个表单都增加计划面板、版本管理或完整 Agent 循环。
- 需要组织上下文输入、执行反馈或报告阅读时，按 [composable-agent-ui.md](references/composable-agent-ui.md) 选择可组合的交互：可操作上下文、渐进展开的执行摘要、尊重回看的流式反馈及独立产物视图。明确每个组件的状态与业务责任，复用既有视觉系统。
- 在一页设计记录中写清改动范围、控制权、主要状态和验收例子，然后继续实现；除非用户只要求方案或仍缺关键决定，不等待额外的设计批准。

## 3. 实现业务适配与页面

- 先提取或复用可测试的业务函数，再增加 API/工具适配层；不要复制业务逻辑，也不要从工具直接调用依赖请求上下文的路由函数。
- 采用既有登录、租户、行级范围和 CSRF 机制。由服务端绑定执行主体与对象范围，不能接受模型提供的 owner/tenant 作为授权依据。
- 在新入口先校验请求体与嵌套字段的类型、空值和范围，再复用业务函数；原表单只接收字符串并不意味着 JSON 输入也安全。
- 为 Agent 公开有限的语义工具及输入/输出 Schema；在服务端重新校验参数、当前对象版本、权限和已确认约束。模型选择不等于业务授权。
- 阅读 [runtime-and-endpoints.md](references/runtime-and-endpoints.md)，按用户已有推理端点与 runtime 接入。需要新增模型端点时预留服务端环境配置；有可用配置且任务授权时做小规模连通测试，不向聊天或浏览器索要、显示 Key。
- 实现当前任务需要的页面状态、错误反馈和恢复动作。将模型文本安全渲染；结构化控件由应用渲染，不执行模型输出的 HTML/JS。
- 默认保留原有手工路径；用户明确要求替换时，提供功能对照与迁移路径。缺 Key 的演示模式要有标识，真实调用失败不能静默伪装成演示成功。
- 对异步建议绑定表单修订号；对人机共编产物绑定基准版本。保护轮询、晚到建议和保存返回期间发生的新编辑，具体规则见交互参考。

## 4. 验证与交付

按 [acceptance.md](references/acceptance.md) 选择与本次改造相关的检查。至少证明旧主路径仍成立、新入口调用真实业务代码、模型失败可理解且可继续处理。共享写入、取消、异步编辑等功能一旦实现，必须覆盖对应冲突路径。

在可用浏览器中操作页面并查看桌面/窄屏实际结果。无法使用浏览器时交付后端和静态验证结果，并明确尚未验证浏览器；不以语法通过代替交互验收。复杂改造可让独立上下文只接收任务、代码、差异与验收规则进行验证，不传递预期结论。

交付修改后的代码、启动/配置说明、功能对照、主要交互说明及已完成的验证证据。可合并文档，避免重复。说明真实模型、内网数据与生产权限的验证范围。仅在用户要求时部署或打包；默认不引入 Docker。
