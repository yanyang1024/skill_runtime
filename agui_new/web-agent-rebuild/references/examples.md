# 典型请求与实现边界

## Flask 查询表单

请求：“已有库存查询页面，支持仓库、物料、日期。加一个自然语言入口，帮用户填条件并解释异常库存。”

执行：读取 form、Blueprint、查询服务与仓库权限；添加局部字段候选和差异视图；应用后沿用原提交；解释绑定已提交结果。检查缺字段、旧建议、未登录和仓库越权。不要为单次查询增加多 Agent、持久任务队列或审批工作流。

若已有可查询的历史与身份上下文，尝试预填一组带依据的完整条件（如最近负责仓库和有效日期），让用户只改不合适的值。向用户说明“沿用上次”“来自当前记录”“组织规定”各是哪一类依据；有多个合理时间范围时并列候选，避免强行给出唯一答案。用实际编辑与错误率判断是否比原表单省事。

## FastAPI 报告工具

请求：“已有数据分析和 Markdown 报告页面，希望 Agent 能调查数据、追问条件、生成报告，人可以继续改。”

执行：复用统计/报告服务，增加任务和有限工具；分开草稿与当前报告；版本绑定到运行开始；人工编辑、取消、刷新和重新提案走真实状态。展示工具计算的证据，模型解释不代替数值计算。

若多次调查收敛到相同的输入条件、查询和验收口径，可把它作为候选“常规报告”任务，先校验例外，再提供可编辑的报告条件。例外与新问题仍可从调查入口继续；常规任务越来越多时，目标入口可先帮助识别与路由，呈现将进入哪个任务及预填依据。

## 有写入的已有应用

请求：“订单页面加一个 Agent，可以帮我处理延期申请。”

执行：追踪既有申请、权限与批准逻辑；将“收集条件/准备申请”与“提交/批准”分别映射。由当前登录身份和既有业务规则决定可执行动作，不能因为模型生成了批准参数就授予审批权。

## 只有截图或局部源码

请求：“按这张图把我的系统 Agent 化，后端在内网。”

执行：用截图理解布局和可见任务，产出可运行的前端/接口替身以及待接契约。列明尚未见到的业务规则与权限。不要把静态截图分析写成原系统回归已完成，也不要因无法访问内网而停止独立可做的设计与代码。

## 候选采购申请与异常调查共存

已有采购表单时，复用当前订单与授权历史起草候选，把供应商、数量、交付日等按业务含义展示，并标明来源。用户在表单里修正；异常交付问题可在同一对象范围内进入探索，显示实际查询摘要与证据缺口。探索得到的调整仍回到申请草稿与原审批流程。无需先把整个页面改成聊天。
