# 典型场景

## 已有 Skill + Python 脚本

请求：“已有检查 CSV 的 Skill 和统计脚本，用 FastAPI 做质量检查应用，用户上传数据后得到问题清单和报告。”

先确认 CSV 格式、脚本输入输出及文件处理边界。复用脚本，设计输入数据对象、校验结果、需要时的口径澄清、报告与导出。接口不可达时使用明确替身；不要把统计改成 LLM 估算，也不要求先搭通用多 Agent 平台。

如果检查条件已经稳定，可用数据集类型与上次确认的规则生成可编辑的检查设置，标注默认值来源、给不同修复策略候选。若用户问“为什么这一列一直异常”，转为基于证据的探索，并把反复有效的处理步骤沉淀为可复用建议。

## 已有 Agent 服务

请求：“我们已经有 Agent 会话和任务接口，做一个 Flask 工作台给业务人员使用。”

把现有任务创建/事件/产物接到页面；业务工作状态与其契约对应。采用服务已有继续、取消和权限机制。缺少取消接口时如实显示限制，不能通过停止前端轮询来声称任务已停止。

## 只有场景和模型端点

请求：“给运维人员做一个日志摘要与排查建议应用，有兼容 v1 的端点。”

读取端点说明确认具体协议，明确日志结构与输出用途；短单轮输入可直接用输入区、结构化结果与导出。工具/运行任务能力若未被需要，不自动增加。模型拒绝和超时提供可理解的重试；输入敏感字段处理沿用用户要求。

## 文档型 Skill 没有可执行工具

请求：“已有一份评审流程 Skill，希望做文档评审 Web UI。”

将流程转为应用中的阶段指导，按需加载评审规则；接入可用文件读取与模型端点。规则文档参与生成，不等于已经执行了验证脚本。展示引用、候选修改与待人工判断处；不虚构确定性验收通过。

## 流式调查与独立报告

故障调查工作台可由目标、所选日志/部署记录、阶段摘要和报告卡组成。用户回看证据时暂停滚动跟随；日志检索失败保留已获得结果与输入，让失败在摘要可见。报告在宽容器并排阅读，在窄嵌入容器切换独立视图；草稿、版本与保存是真实业务对象，不只是模板上的标签。若某类调查反复得到稳定步骤，可另提供预填条件的常规任务入口。
