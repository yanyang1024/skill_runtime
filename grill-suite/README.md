# grill-suite —— 决策可追溯的需求拷问套件（OpenCode）

把「先想清楚再动手」从口头倡议变成可执行、可追溯的工作流。设计依据：mattpocock/skills 仓库 grill-me 生态的 81 个相关 issue 中互动量最高的三类诉求——**决策持久化与下游追溯**、**低疲劳交互**、**高风险决策验证门**——官方均尚未解决，本套件将其补齐。

## 目录结构

```
.opencode/
├── skills/
│   ├── grill/         # 核心拷问引擎：决策树追问 + 决策台账持久化 + 低疲劳协议
│   ├── grill-gate/    # 高风险决策验证门（schema 冻结 / API 定型 / 大重构 / 派任务前）
│   ├── grill-idea/    # 泛化拷问：观点、选型、创意、非编码决策的压力测试
│   └── grill-form/    # 全栈表单契约拷问（空态/字段×角色/保存生命周期/状态锁定）
└── agents/
    ├── interrogator.md        # 主代理：默认"先拷问后实现"，实现期对照台账
    └── decision-auditor.md    # 只读子代理：审计台账 → PRD/issue/实现/测试 的覆盖率
```

## 安装

把 `.opencode/` 目录整体拷入项目根目录即可（技能与代理均项目级生效）。

## 典型工作流

```bash
opencode                    # 进入后 Tab 切换到 interrogator 代理
> 我要给后台加一个订单审核页
# → grill 拷问启动，表单分支自动叠加 grill-form
# → 每轮：进度头 + 竖排选项 + ✅推荐，你只回分歧项（如 "3. (c)"）
# → 每条结论实时追加 .opencode/decisions/decision-ledger.md（D-001…）
# → 收敛后停下等你确认，绝不无缝开写

> 生成 PRD 和任务拆解        # 要求逐条引用 D-xx
> 开始做吧                  # 实现期台账为硬约束

> @decision-auditor 审计台账 # 实现后/提 PR 前
# → 输出 覆盖率 X/Y，逐条 ✅traced / ⚠️weakened / ❌dropped / 🕓stale
```

冻结 schema、定 API、大重构或派发任务前，说一句「过一遍 gate」触发 `grill-gate`；想挑一个想法的毛病，说「拷问下我这个观点」触发 `grill-idea`。

## 关键设计决策（对应 issue 教训）

| 设计 | 对应教训 |
|---|---|
| 决策台账追加式、ID 永不复用、推翻标 superseded | #341/#689：已确认答案在 PRD→issue→实现链路中被软化或丢失 |
| 只答分歧 + 全推荐可一键通过 + 进度头 + 竖排选项 | #819/#834/#597：默认全对是常态，访谈疲劳是弃用主因 |
| 依赖问题拆轮、未探索完禁止出方案、转阶段须一句话论证 | #729/#895/#570：弱模型塌缩成一题出大纲、拷问后无缝切实现 |
| 明确列出"不该拷问"的场景 | #274：把拷问硬塞进探索类技能导致其不可用 |
| grill-form 四分支强制走完 | #914：表单 UI 组合契约是通用拷问的系统性盲区 |

## 反模式提醒

本套件刻意**不**把拷问嵌入所有工作流。纯执行任务、头脑风暴、方向全模糊的 vibe coding 场景下请绕开 interrogator——拷问的价值与"未决分支 × 返工成本"成正比。
