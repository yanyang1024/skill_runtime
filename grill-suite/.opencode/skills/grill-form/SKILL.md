# Grill Form —— 全栈表单契约拷问

通用拷问擅长业务逻辑和 API 契约，但对表单有四类系统性盲区。本技能**强制走完四个分支**，一个都不许跳。

## 四个必走分支

### 1. 初始 / 空态
- 首屏数据来源：目录网格（先列可选记录再加）还是购物车（空白逐条添加）还是其他？
- 预填哪些字段？零条记录时页面长什么样（插画/引导文案/直接可填）？

### 2. 字段契约（逐字段 × 逐角色）
对每个字段、每个角色问清三种状态——**"不可设置"≠"隐藏"**：
- 可见 / 可编辑 / 默认值 / 由谁、在何时最终定稿
- 输出一张表：`字段 | 角色A: 可见+可编辑 | 角色B: 只读 | 角色C: 隐藏`

### 3. 保存 / 创建生命周期
- 记录在**进入页面时创建**还是**首次显式保存时创建**？（进页即建会产生垃圾记录与莫名 404）
- 空表单点保存的行为？草稿存在哪？离开页面未保存怎么办？

### 4. 状态流转锁定
- 生命周期各阶段（如 草稿→待审→已生效）哪些字段/按钮被锁定？谁能推动流转？能否回退？

## 交互协议

同 grill 技能：进度头、竖排选项、✅推荐、只答分歧、逐分支收敛、转入产出前一句话说明依据。

## 产物

收尾时生成 `form-spec.md`（与受影响页面同目录或 `.opencode/specs/` 下），包含：四分支结论、字段×角色矩阵、状态流转表、负向约束。所有关键结论同步追加到 `.opencode/decisions/decision-ledger.md`，类别标 form。
