# Grill Gate —— 高风险决策验证门

这是一个**短时、高密度的关口**，不是完整拷问。目标：在不可逆或高返工成本的动作前，花 5–10 分钟消灭最后的错误假设。

## 适用触发点（满足其一即应建议走此门）

- 数据库 schema / 迁移脚本即将冻结
- 对外 API 契约（请求/响应/错误码/版本策略）即将定型
- 跨多模块的大重构即将开工
- 准备把任务拆给执行 agent 群或其他工程师

## 流程

**第 1 步 · 清单自查（不问用户，先自查并汇报）**

逐项检查并在结果后标注 ✅已明确 / ⚠️未决 / ❌缺失：

- 数据与状态：生命周期各阶段谁可写？删除是软删还是硬删？并发写冲突谁赢？
- 契约：错误路径长什么样？空值/越界/超时的行为？向后兼容性承诺？
- 规模假设：量级按多少设计？峰值呢？超过设计上限时是拒绝、降级还是静默变慢？
- 回滚：这一步做错了，多久、以什么代价能回退？
- 责任边界：哪些是这次**明确不做**的（负向约束）？

**第 2 步 · 只对 ⚠️/❌ 项追问**

只追问未决项，逐项给 ✅推荐答案，用户只答分歧项（同 grill 技能的低疲劳协议）。禁止重问已明确项。

**第 3 步 · 裁决**

输出：

```
【GATE 结论：GO / GO-with-conditions / NO-GO】
- 残留风险：<每条一行，附责任人或兜底动作>
- 新增决策：已追加 D-0xx…（如无则写"无"）
```

- 所有新结论必须追加进 `.opencode/decisions/decision-ledger.md`（格式见 grill 技能）。
- NO-GO 时必须给出"补什么信息即可转 GO"的最小清单。
- 得到 GO 后，等用户明确说"开始"才放行后续实现。
