# Skill 创建与维护

这是随包提供的 OpenCode 适配版，面向用户授权的项目文件；不依赖 ChatGPT 安装机制、云端同步或固定个人目录。同名 skill 已存在时先评估复用，不覆盖环境中的其他版本。

## 工作流程

1. **明确方法与范围。** 确认触发场景、输入输出、成功条件、可用工具和目标目录。接受调用方已明确的信息，不重复询问。新建、修改和仅审查分别处理；修改前读取现有内容及调用方依赖。
2. **优先复用。** 已有 skill 能覆盖就使用它；方法仅是简短稳定指令时不强行建立新目录。缺少真实工具、数据或运行环境时明确依赖，不用空脚本、模拟结果或虚构接口填补。
3. **组织最少文件。** SKILL.md 保留精确的 description、共用流程、核心约束和条件导航；复杂分支放 references，完整成例放 examples，确定性重复工作才写 scripts。只建立有实际内容和用途的目录。
4. **编写或最小修改。** 按 [writing-and-validation.md](references/writing-and-validation.md) 完成名称、路径、加载、失败处理和兼容性检查。需要骨架时读取 [skill-template.md](assets/skill-template.md)，删除无用分支并替换全部占位内容。
5. **验证并回交。** 核对文件、引用、实际工具依赖和产物。新增或修改脚本时实际运行有意义的样例；环境不具备时明确标为未运行。对涉及多分支或交接的改动，用代表场景检查行为；自查不能声称独立验收。

## 按需示例

需要看与 agent 创建流程的衔接时，读取 [agent-integration.md](examples/agent-integration.md)。示例不作为每次创建的必读内容。

## 对外回交

向用户或当前调用流程提供：实际名称与目录、description、输入输出与必需工具、发生变化的公共契约、已完成检查及未验证／阻塞项。无改动的复用也应说明采用了哪个实际 skill。

由 agents-creator 发起时，完成后在当前上下文继续原装配任务，不自动加载或重新触发 agents-creator。不要派生更多 creator，也不要擅自安装、注册、修改全局配置或扩展文件授权范围。
